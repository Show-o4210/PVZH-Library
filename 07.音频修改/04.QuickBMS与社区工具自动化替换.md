# 04. QuickBMS 与社区工具自动化替换

本篇讨论内嵌音频的**修改回写**。仅提取 BGM 时，导出银行后使用 wwiser/vgmstream 即可，不需要执行重新注入。

## 一、QuickBMS 提取与重导入

[QuickBMS 官方页面](https://aluigi.altervista.org/quickbms.htm)提供程序、脚本与重导入说明。Wwise 提取脚本的名称/版本可能不同，使用前阅读脚本及对应 reimport 文档。

### 1. 得到真正的银行载荷

用 UABEA 或 UnityPy 从目标 TextAsset 取出 `m_Script` 字节，检查其是否以 `BKHD` 开头。`Export Raw` 可能包含 Unity 序列化封装，不能仅改后缀便认定它是银行。

备份原 Bundle、TextAsset 载荷和提取索引；所有替换先在副本上进行。

### 2. 提取媒体

选择适用于当前银行的 Wwise BMS 脚本，将 `.bnk` 中的内嵌媒体提取到输出目录。保留媒体 ID、偏移、长度及类型，不把所有结果都假定为 WEM。

### 3. 同名替换与重导入

QuickBMS 的传统 reimport 命令示意如下，**不是任意 Wwise 脚本的通用银行重建保证**：

```cmd
quickbms.exe -w -r wwise_bnk_extractor.bms soundbank_copy.bnk output_folder
```

其中脚本必须真实存在且适用于目标格式。传统模式受文件大小、压缩方式和脚本记录的偏移/长度等限制；其他重导入模式也有各自前提。较大的替换文件尤其不能默认可用。

> [!WARNING]
> 不能承诺该命令会自动修正全部 BKHD/HIRC 指针、重建任意变长银行或修改音乐编排。若脚本只支持提取，则换用有明确重建能力的工具，不反复强行注入。

### 4. 核对并写回 Unity

重新解析生成的银行：检查 Chunk 长度、DIDX 的每项边界、媒体 ID 和媒体可解码性。再通过工具支持的方式写回 TextAsset 的 `m_Script`，保存 Unity 对象与外层 Bundle。

`Import Raw` 是否接受裸银行取决于工具/插件；若它要求完整 Unity 对象，直接导入 `.bnk` 不正确。写回后再次导出 `m_Script`，确认与目标银行哈希一致，再做游戏验证。

## 二、社区图形化工具

原教程推荐休切尔制作的 PVZH 专属工具，入口见[社区专属工具集](../01.工具链介绍/01.社区专属工具集.md)。图形界面可以减少中转步骤，但应确认所用版本确实支持目标银行、媒体编码、变长替换和 Bundle 保存方式。

本次工作验证的是**提取与离线编排**，没有重新验证每个社区工具的重打包功能，因此不作“所有银行一键兼容”的承诺。

无论用哪种工具，都按“备份 → 单项替换 → 重新解析 → 回写核对 → 实机触发”验收。若只需要把原音乐交给人工队，转入[第 05 篇](05.背景音乐结构与完整提取.md)，不要修改游戏资源。
