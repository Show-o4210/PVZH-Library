# 06. wwiser 与 vgmstream 音乐编排导出

目标是生成便于人工筛选的**有限时长试听与原始片段素材**，不是伪造固定原版结尾或自动宣布完整 OST。原始银行和媒体只读，输出放在新目录，已有成果不覆盖。

## 一、工具分工与目录

| 工具 | 本次使用版本 | 用途 |
| --- | --- | --- |
| UnityPy | 1.25.0 | 从 Unity Bundle 读取 TextAsset 字节 |
| wwiser | v20250928 | 解析银行、音乐图，生成 TXTP 播放规则 |
| vgmstream CLI | r2117 | 解码 WEM，并按支持的 TXTP 规则渲染 |
| FFmpeg / ffprobe | 8.0.1 | 制作兼容性试听 MP3、检查音频信息与整段解码 |

工具文档：[wwiser 项目](https://github.com/bnnm/wwiser)、[功能与限制](https://github.com/bnnm/wwiser/blob/master/doc/WWISER.md)、[vgmstream 项目](https://github.com/vgmstream/vgmstream)。下面参数针对本次版本，更新后先检查 CLI 帮助。

建议建立便携目录，不把本机绝对路径固化进交接规则：

```text
audio-work/
  banks/         # 五个全局银行；需要时加入英雄银行
  media/         # 校验过同 ID 冲突的 <sourceID>.wem
  txtp/          # 原工具生成规则
  wav/           # 无额外有损编码的解码/编排输出
  mp3/           # 便于试听的衍生文件
  inventory/     # 来源、参数、状态、别名、错误清单
```

生成规则可能同时引用 WEM 与 `.bnk` 内嵌媒体。核对路径是否指向真实文件；只修正路径，不丢掉原银行。含 `?` 或不支持来源的规则须标记为部分还原，不能悄悄忽略后称为完整曲目。

## 二、先用一个有证据的序列验证

本次“实例 A”来自 `MusicRanSeqContainer 356316667`，三段顺次播放，第三段循环。它已获用户及同人作者试听反馈认可，但不是官方曲名。

| 顺序 | Segment ID | Track ID | WEM ID | 银行规定的段长 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 512940634 | 923781142 | 17936251 | 13.44 秒 |
| 2 | 318165538 | 509851820 | 894316 | 13.44 秒 |
| 3，循环 | 609184230 | 167858427 | 921890154 | 11.52 秒 |

将三份原 WEM 放在 `media/`，把下面规则保存为 `audio-work/example_a.txtp`：

```text
media/17936251.wem #i #b 13.44
media/894316.wem #i #b 13.44
media/921890154.wem #i #b 11.52 #@loop
group = -S3 ##loop
```

这是由本例银行结构得到的规则，**不能当作其他曲子通用模板**。如果源文件/银行版本不符，重新解析，不仅替换数字 ID。

在 `audio-work` 中执行（工具名称需替换为本机可用命令或路径；输出目录事先创建，文件名未使用）：

```powershell
vgmstream-cli -l 2 -f 10 -o wav/example_a.wav example_a.txtp
ffmpeg -hide_banner -v warning -n -i wav/example_a.wav -ar 44100 -c:a libmp3lame -b:a 160k mp3/example_a.mp3
```

原循环起点为 26.88 秒，终点为 38.40 秒。两次循环加 10 秒预览淡出，本例得到 **59.92 秒**；淡出是人为限制试听长度的设置，不是原版固定结尾。WAV 为 16000 Hz、双声道 PCM16；MP3 重采样到 44100 Hz 是为了播放兼容，不是提高源音质。

## 三、用 wwiser 生成规则

从 `audio-work` 中运行，示意以本例序列 ID 为过滤目标：

```powershell
python path/to/wwiser.py -d none -g -gu -gf 356316667 -gv 0 -go txtp -gw "*" banks/Init.bnk banks/Global_Data.bnk banks/Global_Persistent.bnk banks/Global_Menu.bnk banks/Global_Gameplay.bnk
```

- `-d none` 不写完整结构 dump；本次完整 XML 很大，非必要不生成。
- `-g` 生成 TXTP；`-gu` 允许生成未作为顶层事件直接使用的节点，`-gf` 指定过滤 ID。
- `-go` 指定 TXTP 输出；`-gw "*"` 自动查找工作目录下的媒体和银行，并生成相对于 TXTP 的路径。手动指定媒体位置时，路径相对于 TXTP 所在目录，例如本布局需 `../media`，不是 `media`。
- 本次版本实测 `-gv 0` 跳过额外主音量调整，避免默认自动增益，保留银行音量规则；**这里不表示把音乐静音**。这是该版本的参数行为，升级后重新核对；不另做归一化/压限。
- 想展开原有随机候选可增加 `-gra`，数量会明显增加。不要为了提取使用移动媒体的选项。

过滤内部节点缺少顶层事件上下文时，结果可能与完整事件渲染不同。优先保留能够生成的事件上下文规则，再用单节点输出补充素材。

完整 `PLAY_MUSIC` 自动生成曾在产出 87 个 TXTP 后遇到 `ValueError: wrong TXTP clip values` 而中断。**已有输出不表示全部成功。** 应记录出错 ID，再逐节点隔离生成；不能靠重跑一个总命令保证完整导出。

## 四、原始片段与编排分别导出

原始 WEM 播放一次，忽略其循环、不给人为淡出：

```powershell
vgmstream-cli -i -o wav/source_17936251.wav media/17936251.wem
```

其他编排可设置两次循环与 8 秒试听淡出：

```powershell
vgmstream-cli -l 2 -f 8 -o wav/arrangement.wav txtp/selected.txtp
```

不要按时长阈值丢弃短片段；引子、收尾或变奏可能只有几秒。也不要把独立轨道、单段、完整序列放在同一目录且全部命名为“完整版”。vgmstream 没有本流程中的统一防覆盖包装，批量调用前需自行检查输出名冲突；FFmpeg 用 `-n` 拒绝覆盖。

## 五、广覆盖批量策略

本次按“多导出、人工筛选”的目标处理当前音乐图：

1. 保留全部 260 个 Vorbis 来源，并记录 4471 个 MIDI 来源，不改造后者。
2. 尝试 188 个随机/序列容器、721 个片段、32 个切换容器和 709 个含 Vorbis 的轨道，展开可支持的随机候选。
3. 单节点生成失败只记日志，不让它中止所有其他节点；相同规则保留来源别名。
4. 每个 TXTP 分别分类：成功、缺声部、纯 MIDI/无支持来源、完全无声、解码失败。
5. 保留 WAV、MP3、TXTP、银行、来源清单及失败记录，允许音频内容相同但用途/规则不同的版本并存。

本次得到 1916 个新规则，纳入先前 87 个上下文规则，去除 10 个字面完全相同项并保存别名，余下 1993 项分别处理。生成阶段 40 个节点出现 `wrong TXTP clip values`；这些节点的源 WEM 仍保留。

随机选择规则也须检查。例如一项生成规则把只有两个候选的组写成 `-R2>4`，无法解码。本次保留原规则，依据实际已有候选分别输出两个合法版本，并记录修复。不能不看层级就批量替换数字，也不能捏造新的音乐候选。

最终数量与质量核对见[第 07 篇](07.动态音频追踪与导出质量核对.md)。这是原有可支持结构的简单还原；Wwise MIDI、实时切换及部分引擎行为仍未完整模拟。
