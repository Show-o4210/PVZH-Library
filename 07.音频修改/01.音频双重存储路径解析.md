# 01. 音频双重存储路径解析

“双重”指 **独立媒体流文件 + Unity Bundle 内嵌音频** 两种存储形式，不是只有两个目录。当前确认与音频有关的目录有三个。

## 一、三个目录与两种存储形式

以下路径均相对于 Android 外部应用目录：

```text
/storage/emulated/0/Android/data/com.ea.gp.pvzheroes/files/
```

| 相对路径 | 本次确认的内容 | 处理方式 |
| --- | --- | --- |
| `streaming_audio/` | 独立的数字 ID `.wem` 流文件，包含音乐及其他声音 | 直接解码；替换时保留目标文件名并实机验证 |
| `cache/bundles/files/audio/` | 全局 SoundBank、初始化银行、装有 WEM TextAsset 的流资源 Bundle | 先解 Unity Bundle，再读取银行/媒体 |
| `cache/bundles/files/autotagged/` | 单位、英雄等资源 Bundle；部分 TextAsset 包含 SoundBank | 根据音频引用定位，不能只寻找贴图 |

> [!NOTE]
> 旧教程中的 `files/audio/`、`files/autotagged/` 是不完整的简写。独立 WEM 的实测位置是 `streaming_audio/`，不要把 WEM 直接塞进装 Bundle 的 `cache/bundles/files/audio/`。

`streaming_audio` 本次缓存有 1009 个文件，但不全是 BGM；流资源 Bundle 也可能带有同一来源的副本。目录文件数不能相加后当成曲目数。

## 二、独立 WEM 并不等于完整歌曲

`.wem` 是 Wwise 媒体文件扩展名，不是一种单独的编码。本次音乐来源使用 Custom Vorbis；其他资源/版本需按实际文件检查，不能假定全部声音均为 Vorbis。

“明文 WEM”在这里仅表示没有包在 Unity Bundle 中，不表示它是可用文本编辑器修改的文本。

独立 WEM 可以是几秒的引子、循环段、收尾、单个声部，也可以是较长片段。原版播放顺序、裁剪、循环和叠轨通常由银行控制，而不是由文件名顺序决定。

## 三、Bundle 内的 SoundBank 与媒体

例如[康加僵尸资源包](../资源/1f826228d36c6f0478c72b56f17541d2_1)的历史案例中，约 64.6 KB 的 TextAsset 以 `BKHD` 开头，可识别为 Wwise SoundBank。它不是文本台词，也不是单独的 WEM。

定位某个单位的音效时，可先检查对应 `autotagged` 包内的 SoundBank；但不要推断所有声音都在该单位包中。全局事件、流文件和英雄银行也可能参与播放。BGM 尤其需要先读 `Global_Data` 的音乐引用，详见[第 05 篇](05.背景音乐结构与完整提取.md)。

导出时取 TextAsset 的 **`m_Script` 原始字节**。工具的 `Export Raw` 可能导出整个 Unity 对象的序列化数据，未必直接得到以 `BKHD` 或 `RIFF` 开头的载荷，需核对后再交给音频工具。
