# 04. 自动化 Patch 构建与真机部署实战

本篇讲解如何使用开源项目 [pvzh-local-inventory-mod](https://github.com/Show-o4210/pvzh-local-inventory-mod)（工作区副本见 [资源/pvzh-local-inventory-mod](../资源/pvzh-local-inventory-mod)）中提供的自动化 Python 脚本一键构建 v3c 静态补丁 SO、重打包 APK 并进行真机部署与异常调试。

---

## 一、 准备工作与依赖安装

补丁构建自动化工作流基于 Python 3.9+ 环境。

### 1. 安装环境依赖
在终端中进入工具脚本目录：

```bash
pip install -r requirements.txt
```

数据处理依赖库：`keystone-engine` (用于汇编代码洞编译) 与 `lief` (用于 ELF 段安全操作与修补)。

### 2. 准备官方原版 SO 文件
从官方正版 APK（`arm64-v8a` 架构）中提取 `lib/arm64-v8a/libil2cpp.so` 原版文件。

---

## 二、 自动化一键生成 Patch SO (`build_and_patch.py`)

运行构建脚本进行汇编注入与 SHT 自动对齐：

```bash
python scripts/build_and_patch.py
```

### 自动化构建处理步骤：
1. **源码编译**：自动将 `native/merge_inventory_extra.c` 编译为适用于 ARM64 架构的代码段 payload。
2. **符号定位与校验**：搜索目标 `SetLocalPlayerInventory` 函数偏移（`0x1FEB4E0`）。
3. **汇编注入与跳转**：将 Epilogue 指令替换为开辟跳转指令 `B` 指向 Code Cave。
4. **v3c SHT 偏移纠正**：修补 ELF `sh_offset` 与 `PT_DYNAMIC` 段并对齐 4KB 页边界。
5. **产出输出**：在 `dist/arm64-v8a/` 目录下导出打好补丁的成品 `libil2cpp.so`。

---

## 三、 真机与模拟器部署安装

### 方案 A：在已安装的游戏上直接替换 SO（需 Root 或模拟器）
1. 将 `dist/arm64-v8a/libil2cpp.so` 复制到设备中。
2. 使用 **MT管理器** 将其覆盖替换至应用安装目录 `/data/app/.../lib/arm64/libil2cpp.so`。
3. 将配对好的卡库声明文件放置到：
   `/storage/emulated/0/Android/data/com.ea.gp.pvzheroes/files/cache/mod/inventory_extra.json`
4. 启动游戏即可使用新卡牌！

### 方案 B：重打包为成品 APK（免 Root 玩家分发）
1. 使用 APK Editor 或 MT管理器 解包目标 APK。
2. 将 `lib/arm64-v8a/libil2cpp.so` 替换为打过 v3c 补丁的新文件。
3. 重新打包并使用 **V2/V3 签名** 重新签名 APK。
4. 安装重签后的 APK，玩家仅需将 `inventory_extra.json` 放入 `files/cache/mod/` 文件夹即可试玩！

---

## 四、 常见故障排查档案 (Troubleshooting)

在部署静态 Patch 过程中若遇到异常，请参阅以下诊断措施：

| 故障现象 | 产生原因 | 解决排查措施 |
| :--- | :--- | :--- |
| **启动即白屏/黑屏闪退** | SO 使用了旧版 v3a/v3b 策略，ELF 节区段未对齐，触发了 Bionic `linker64` 校验错误。 | 确认运行了最新的 `build_and_patch.py` 并选用了 **v3c 策略** 重新构建 SO。 |
| **卡牌能看到但仍为灰色无法编组** | `inventory_extra.json` 路径错误或 JSON 中的 GUID 与 `card_data` 中的 GUID 不一致。 | 使用 ADB 抓取 logcat 观察 log：<br/>`adb logcat \| grep -i inventory`，确认读取文件成功。 |
| **进入关卡时报错闪退** | 在 `card_data` 中定义的新卡牌 `prefabName` 或 `components` 数组语法损坏。 | 查阅 [02. 卡牌数据说明/05. 手动修改最佳实践](../02.卡牌数据说明/05.手动修改最佳实践与新建卡牌指南.md)，确保复制的原版代码节点结构完整。 |
