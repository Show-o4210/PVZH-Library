# 01. Unity 2D 动画机制与核心组件

在 PVZH 中，英雄与单位的丰富动态表现（如摇头、出拳、挨打、眨眼）是由 Unity 的动画系统驱动的。理解动画系统的四大底层组件及其调用逻辑，是进行动画修改的前提。

---

## 一、 动画系统四大核心组件

| 组件类型 | 核心职责 | Mod 修改中的作用 |
| :--- | :--- | :--- |
| **Animator** | 动画状态机挂载器 | 挂载在角色根节点上，控制动作之间的状态切换逻辑（如 Idle 转换至 Attack）。 |
| **AnimatorOverrideController** | **动画重定向控制器** | **Mod 替换的核心切入点**。用于在不破坏底层状态机的情况下，将原版动作替换为自定义动作。 |
| **AnimationClip** | **关键帧动作片段** | 记录具体的动作轨迹（如 `Sunflower_attack.anim`），包含帧率、时间轴与属性变化曲线。 |
| **Node Path Hash** | 节点路径 Hash 寻址 | 动画系统在运行期用于定位具体骨骼节点的内部 Hash 哈希校验码。 |

---

## 二、 `AnimatorOverrideController` 重定向工作流

在 PVZH 中，为了避免为每一个英雄/随从都重新编写一套复杂的状态机，官方采用了 `AnimatorOverrideController` 机制：

```yaml
m_Controller: {fileID: 0, pathID: 1001}  # 指向通用的基础 AnimatorController
m_Overrides:
  - m_OriginalClip: {fileID: 0, pathID: 2001}  # 原版基础 Idle 动作
    m_OverrideClip: {fileID: 0, pathID: 9001}  # 重写为耀斑花的专属 Sunflower_idle
  - m_OriginalClip: {fileID: 0, pathID: 2002}  # 原版基础 Attack 动作
    m_OverrideClip: {fileID: 0, pathID: 9002}  # 重写为耀斑花的专属 Sunflower_attack
```

通过修改 `AnimatorOverrideController` 中 `m_Overrides` 数组里的 `m_OverrideClip` 指针，即可实现用我们自己制作的动作片段完全替换原版角色的动作表现！

## 三、 节点 Hash 路径原理（为什么 m_Name 绝不能拼错）

> [!IMPORTANT]
> **关键原理**：
> Unity 的 `AnimationClip` 在播放时，**绝不是通过 C# 组件的 `PathID` 来寻找要动的手或脚的**！
> 它是通过节点在层级树中的相对路径字符串（例如 `"root/body/arm_l"`）计算出的 **Hash 哈希值** 来匹配 `GameObject` 的。

### 动画匹配流程：
1. 动画文件读取指令：在第 0.5 秒，将相对路径为 `"body/head"` 的节点旋转 15 度。
2. 动画系统在 `GameObject` 层级树中搜索 `m_Name == "body"` 的子节点下的 `m_Name == "head"` 节点。
3. **如果拼写错位**：如果你的 `GameObject` 名称被误改为了 `"Head"`（大写 H）或 `"head_01"`，动画系统无法命中该 Hash 路径，该节点就会**完全脱离动画控制**，静态留在初始坐标，造成画面错乱漂移！
