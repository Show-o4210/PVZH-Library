# 02. 动画提取脚本使用指南

## 一、准备环境

安装 Python 依赖，并确保 `ffmpeg` 可从命令行直接调用：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install UnityPy Pillow numpy opencv-python
ffmpeg -version
```

将本章 `examples/` 下的三个脚本复制到同一工作目录，并准备：

```text
工作目录/
├── extract_animation_mov.py
├── batch_extract_animations.py
├── batch_rebuild_sprites.py
├── index_new.json
├── cab_index.json
└── autotagged/
    └── 各 AssetBundle 文件
```

## 二、先测试单张卡

建议先从索引中查出目标资源包文件名和 UUID，再运行：

```powershell
python .\extract_animation_mov.py `
  .\autotagged\目标Bundle文件名 `
  --uuid 目标UUID `
  --name-cn 中文卡名 `
  --bundles .\autotagged `
  --cab-index .\cab_index.json `
  --output .\动画测试\目标卡
```

仅提取名称包含指定文本的动作：

```powershell
python .\extract_animation_mov.py .\autotagged\目标Bundle文件名 `
  --uuid 目标UUID --bundles .\autotagged `
  --clip idle --output .\动画测试\idle
```

常用参数：

| 参数 | 说明 |
| :--- | :--- |
| `bundle` | 目标 AssetBundle；省略时仅使用脚本内的研究样本默认值，不适合通用使用。 |
| `--uuid` | 按索引 UUID 选择 prefab 根节点。 |
| `--name-cn` | 中文卡名，用于动作输出名。 |
| `--bundles` | 用于解析 CAB 依赖的 Bundle 目录。 |
| `--cab-index` | CAB 内部名到实际文件名的映射。 |
| `--clip` | 只处理英文名包含该文本的动作。 |
| `--output` | 当前卡牌的输出目录。 |
| `--keep-frames` | 保留中间透明 PNG 序列。 |
| `--include-mov` | 额外生成 PNG video codec、RGBA 的无损透明 MOV。 |

默认只输出 H.264 MP4。脚本会为整张卡从六种高饱和颜色中选择与其像素差异较大的抠图底色，并让所有动作共用该颜色。

## 三、批量提取

先做小批量验证，并显式指定输出路径：

```powershell
python .\batch_extract_animations.py `
  --index .\index_new.json `
  --bundles .\autotagged `
  --cab-index .\cab_index.json `
  --output .\动画输出 `
  --limit 10 `
  --workers 2
```

确认结果后移除 `--limit` 运行全量任务。动画处理的内存峰值明显高于静态拼图，默认 2 个 worker 是较稳妥的起点；内存紧张时降为 1。

> [!WARNING]
> 批处理脚本源文件带有研究环境使用过的默认输出路径。实际使用时务必显式传入 `--output`，不要依赖该默认值。

| 参数 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `--index` | `index_new.json` | 卡牌资源索引。 |
| `--bundles` | `autotagged` | AssetBundle 目录。 |
| `--cab-index` | `cab_index.json` | CAB 映射文件。 |
| `--output` | 研究环境路径 | 应显式改为自己的输出目录。 |
| `--limit` | 不限 | 仅处理前 N 个有效条目。 |
| `--workers` | `2` | 同时处理的卡牌数。 |
| `--min-free-gb` | `5` | 剩余空间低于该值时停止提交新任务。 |
| `--retry-errors` | 关闭 | 重新执行上次报告中标为 error 的条目。 |

## 四、输出与报告

```text
动画输出/
├── 植物/单位/0020_中文名_英文名/
│   ├── 中文名_待机/
│   │   ├── 中文名_待机.mp4
│   │   └── clip.json
│   └── report.json
└── 批量处理报告.json
```

`clip.json` 记录 FPS、时长、帧数、尺寸、输出 PPU、抠图色、空帧与未匹配路径 Hash；单卡 `report.json` 汇总动作和依赖包；`批量处理报告.json` 记录每张卡的状态、耗时与错误输出。

批处理发现有效 `report.json` 且其中全部 MP4 仍存在时会标记 `skipped_complete`，实现断点续跑。上次为 `error` 的条目默认保留错误，确认环境已修复后使用 `--retry-errors` 重试。
