# 01. 从 idle 首帧到完整动画

## 一、与第 13 章共享的基础

动画提取仍然需要读取 `GameObject`、`Transform`、`SpriteRenderer`、`Sprite` 与 `Texture2D`。节点层级、pivot、PPU、渲染顺序以及 active/enabled/alpha/null Sprite 的判定都与静态拼接相同；区别是第 13 章只求值 idle 起点，本章需要在每个采样时刻重新求值动作。

动画绑定使用相对 Animator 根节点路径的 CRC32，而不是 GameObject 的 PathID。脚本先为 prefab 层级建立路径 Hash 映射，再将每条绑定应用到对应节点。

## 二、Unity 动画标量的四个来源

PVZH 的 `AnimationClip` 可能从以下位置提供标量：

| 数据区 | 含义 |
| :--- | :--- |
| `m_StreamedClip` | 以三次多项式系数保存的连续曲线。 |
| `discreteCurveCount` | Sprite、布尔状态等离散曲线，应保持前一个关键帧的值。 |
| `m_DenseClip` | 按固定采样率连续存储的密集数据。 |
| `m_ConstantClip` | 整段动作中不变化的常量。 |

标量游标必须满足：

```text
streamed.curveCount
+ streamed.discreteCurveCount
+ dense.m_CurveCount
+ len(constant.data)
= len(m_ValueArrayDelta)
```

漏掉 `discreteCurveCount` 会让后续 ConstantClip 整体错位，典型表现是多套脸同时出现、Sprite 切错部位，以及 active、颜色或 Transform 串到其他节点。

## 三、从标量恢复姿态

当前脚本处理的主要属性包括：

- Transform attribute 1：Local Position；
- Transform attribute 2：Local Rotation Quaternion；
- Transform attribute 3：Local Scale；
- Transform attribute 4：Local Euler Angles，取 Z 轴角度转换为四元数；
- SpriteRenderer 的 Sprite PPtr、Enabled、Alpha 与 RGB；
- GameObject 的 `m_IsActive`。

动画未绑定的属性必须保留 prefab 默认值。默认关闭或 Sprite 为 null 的 Renderer 也不能在求值前删除，因为动作可能在后续帧启用节点或赋予 Sprite。

## 四、跨 CAB 依赖与对象身份

PVZH 常把结构和动画放在 B 包，把 Sprite 与 Texture 放在 A 包。跨包 PPtr 的 `fileID` 指向当前 serialized file 的 externals 表，脚本据此从 `cab_index.json["cabs"]` 加载实际使用的依赖包。

不要递归加载整个共享依赖图，它可能扩散到大量无关 Bundle。也不要只用整数 PathID 判断节点归属：PathID 只在单个 serialized file 内唯一，正确身份是：

```text
(assets_file identity, pathID)
```

外部包只用于解析主 prefab 引用的资源，不应加入主 prefab 的层级遍历。

## 五、为什么必须使用固定画布

若每一帧各自紧裁，角色位置或轮廓稍有变化，视频边缘就会不断移动，形成明显抖动。脚本先求值整段动画，收集所有可见 Sprite 的世界坐标四角，计算联合包围盒，再用同一原点和画布渲染全部帧。

动作结束后的全透明帧不一定是错误。死亡、退场和技能动画可能按设计关闭全部节点；只要整段至少有可见内容，这些空帧应被保留。

为控制异常尺寸和计算量，当前实现将最终栅格密度限制为最高 100 PPU，并将最长边限制为 2048 像素。限制只会等比降低最终输出密度，不改变轨迹、帧率和相对布局。
