# 03. 渲染质量与异常排查

## 一、轮廓白边与锯齿

直接对 straight-alpha RGBA 做仿射插值，会把透明像素中的 RGB 混入轮廓。脚本先将 RGB 乘以 Alpha，在预乘 Alpha 空间使用 Lanczos 变换和合成，再恢复 straight alpha，从而减少白边。

当前正式输出以吞吐为优先，按最终分辨率渲染；代码仍支持超采样渲染路径。若修改脚本做单卡质量审查，可提高 supersample，但应先估算内存和耗时。

## 二、画布异常巨大

典型信号包括内存暴涨、渲染极慢，或包围盒达到数万乃至数十万像素。优先检查：

1. 是否把依赖包中 PathID 相同的对象误判成 prefab 后代；
2. active、enabled、alpha 或 null Sprite 是否没有正确应用；
3. 是否选错 Animator、根节点或动作；
4. 远距离辅助节点是否本来应隐藏；
5. 该动作是否确有超长位移。

不要简单删除尺寸保护。当前 100 PPU 和最长边 2048 像素限制既控制异常，也让真实长轨迹动作可以等比输出。

## 三、多个头部、表情或状态层同时出现

这通常不是图层排序问题，而是动画标量游标错位或显隐覆盖错误。确认 `streamed.curveCount` 后已加上 `discreteCurveCount`，且离散曲线取前一个关键帧而非连续插值；同时确认未绑定属性继承 prefab 默认值。

## 四、缺脸、缺部件或 Sprite 错位

检查单卡 `report.json` 中的依赖包列表，并确认：

- `cab_index.json` 的真实映射读取自顶层 `cabs`；
- external fileID 正确转换为 CAB 名；
- 只加载实际使用的外部包；
- 跨文件对象使用 `(assets_file identity, pathID)` 判断身份；
- Sprite PPtr 为 null 时被视为该帧隐藏，而不是解析失败。

## 五、空帧与无可见帧

`clip.json` 中的 `empty_frames` 只是提示。死亡、退场和技能动作末尾可能故意全透明，这类帧应留在固定时长内。只有整段动作都没有可见图层时，提取器才会报 `has no visible frame`。

`unmatched_path_hashes` 也不必一律视为失败。官方复用动画可能包含当前 prefab 没有的粒子挂点或可选节点；应结合视频缺失内容判断。

## 六、FFmpeg 与输出格式问题

出现 `ffmpeg` 找不到时，确认它已经安装并加入 PATH。默认 MP4 使用 H.264、`yuv420p`、CRF 12，不保留 Alpha；抠图底色的 RGB 和十六进制值会写入报告。

需要真正透明的视频时使用 `--include-mov`。当前 MOV 使用 PNG video codec 和 RGBA，逐像素无损，但文件体积、临时 PNG 和编码时间都显著增加，不适合默认全库运行。播放器若不正确显示 Alpha，应在支持透明通道的剪辑或合成软件中验证。

## 七、批处理状态速查

| 状态 | 含义与处理 |
| :--- | :--- |
| `ok` | 子进程成功且单卡报告包含动作。 |
| `skipped_complete` | 报告完整且全部 MP4 存在，正常断点跳过。 |
| `missing_bundle` | 索引中的 `TEXTURE_NAME` 对应文件不存在。 |
| `error` | 查看批量报告保存的 stdout/stderr；修复后加 `--retry-errors`。 |
| `stopped_low_space` | 剩余空间低于 `--min-free-gb`，更换输出盘或清理空间后续跑。 |

维护资源版本时，应先更新 `autotagged/`、`index_new.json` 与 `cab_index.json`，再用 `--limit` 做小样本验证。不要只按视频数量判断成功，应检查所有非 `ok`/`skipped_complete` 状态及各动作报告中的警告。
