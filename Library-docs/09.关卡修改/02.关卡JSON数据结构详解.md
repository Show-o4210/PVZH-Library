# 02. 关卡 JSON 数据结构详解

关卡在底包中以标准的 JSON 文本存在。理解关卡 JSON 的核心字段，是手工修改与使用关卡编辑器的核心。

> 2026-10-25更正：本篇以下示例改用R30所附11064原版底稿的实际字段；它们仍是摘录，不是完整可导入关卡。旧版的MaxHealth、StartingSun、StartingHandCount、ShuffleDeck、Blocks及“权重必须100”均不能作为当前构建依据。范围、指纹与未测项先读[索引](INDEX.md)，历史案例见[Agent关卡指南](../../agents/03-levels-and-localization.md)。

---

## 一、 基础属性与规则开关

```json
{
  "Id": "PVE_Soft_Node_Plant_001",
  "OpponentElo": 500,
  "MustPlayAllPlayableCards": false,
  "DisableSurprisePhase": false,
  "EnableReadySetPlant": false,
  "SkipHeroSelect": false
}
```

| 字段名 | 类型 | 含义说明 | 常用场景 |
| :--- | :---: | :--- | :--- |
| **`Id`** | `string` | 关卡唯一标识符 | 必须与 `TextAsset` 的资源节点名完全匹配。 |
| **`OpponentElo`** | `int` | 对手ELO配置值 | 不能仅凭名称保证提高决策智能；对结算／动态难度的影响需按实现和实机分别核对。 |
| **`MustPlayAllPlayableCards`** | `bool` | 是否强制出完所有手牌 | 常用于解密挑战（Puzzle Party）。 |
| **`DisableSurprisePhase`** | `bool` | 是否禁用僵尸锦囊阶段 | 对应ZombieSurprisePhase，不是墓碑现身开关。 |
| **`SkipHeroSelect`** | `bool` | 是否跳过英雄选择直接开局 | 剧情关卡固定英雄时开启。 |

## 二、 角色配置 (`OpponentConfig` 与 `PlayerConfig`)

人机（`OpponentConfig`）与玩家（`PlayerConfig`）拥有完全对称的属性配置结构：

### 1. `Parameters` 基础角色参数
```json
"Parameters": {
  "Faction": 0,
  "InitialCardsToDrawFromDeck": 4,
  "NumCardsToDrawPerTurn": 1,
  "InitialHealth": 20,
  "InitialSunCount": 1,
  "ShuffleDeckAtStartOfGame": true
}
```
- `Faction`: 归属阵营（`0` 代表植物，`1` 代表僵尸）。
- `InitialHealth`：英雄初始生命参数；不要与卡牌Health组件的MaxHealth混淆。
- `InitialSunCount`：初始化资源参数。它与回合增长、场景资源效果和开局显示值之间的顺序需要另验，不能仅凭字段名作总资源承诺。
- `InitialCardsToDrawFromDeck`和`NumCardsToDrawPerTurn`分别控制初始抽牌参数与每回合基础抽牌；场景额外抽牌另计。

### 2. 护盾概率权重表 (`SuperBlockTable`)

> [!IMPORTANT]
> **权重需按原配置用途判断，不能固定要求合计100。**
> R30附带的11064底稿共有2130侧配置：权重合计100的2026侧、合计0的103侧、合计1的1侧。原包反例足以否定“非100必崩溃”的旧断言；不代表任意新权重都安全。桌面编辑器目前仍有合计100的导出拦截，应识别为工具限制。数值分布和反例见[事实摘要](关卡事实核对-20261025.json)。
>
> 以下是植物任务001玩家侧摘录：`ChargeAmount`是原生充能数值，配套`BlockMeterMax=80`，不要把它改名为Blocks或直接写1/2/3来代替。

```json
"SuperBlockTable": {
  "TableEntries": [
    { "RngWeight": 33, "ChargeAmount": 10 },
    { "RngWeight": 34, "ChargeAmount": 20 },
    { "RngWeight": 33, "ChargeAmount": 30 }
  ]
}
```

## 三、 战场与 5 路地形配置 (`BoardConfig`)

定义对局战斗场景、5 条路线的地形类别以及开局预置在场上的单位：

```json
"BoardConfig": {
  "PlantsBoardName": "Impfinity",
  "ZombiesBoardName": "Impfinity",
  "LaneEntries": [
    { "LaneType": 0, "Cards": [] },
    { "LaneType": 1, "Cards": [] },
    { "LaneType": 1, "Cards": [] },
    { "LaneType": 1, "Cards": [] },
    { "LaneType": 2, "Cards": [] }
  ]
}
```

### 1. 地形分类 (`LaneType`)
- **`0`**：高地 / 屋顶地形 (Highground)
- **`1`**：平地 / 地面地形 (Ground)
- **`2`**：水路地形 (Water)

### 2. 预置场上单位 (`Cards`)
`Cards`保存该路的预置GUID。新增布阵前核对当前卡表、阵营、格子占用、组队／环境及地形限制；只存在字段不能证明任意组合可放置。修改时保留该路其他字段与未涉及道路，实际初始化结果需进游戏确认。

两侧背景独立保留：本底稿有405/1065关的`PlantsBoardName`与`ZombiesBoardName`不同。只有需求明确要同一背景时才同时修改，不能照搬编辑器每次同步统一两侧的行为。
