# 05. 背景音乐结构与完整提取

本篇的“完整提取”指保留**当前已收集音乐图引用的媒体和编排资料**，不是宣称已还原全游戏 OST。以下是 2026-10-01 对 PVZH 1.67.8 Android arm64 的调查记录。

## 一、为什么只导出 WEM 会感觉音乐不全

音乐系统中常见的引用链是：

```text
Event → Action → MusicSwitch / MusicRanSeqContainer
      → MusicSegment → MusicTrack → WEM 或 Wwise MIDI 来源
```

这是阅读线索，不是每个节点都必须出现的固定格式。银行还记录状态条件、随机候选、循环次数、起止 cue、裁剪、音量自动化及转场。

因此可能同时出现：

- 顺序：引子 → 正文 → 循环；
- 并行：多条轨道在同一片段中同时演奏，不能顺次串接；
- 随机：从几个原有候选中选一项，并非每局都一样；
- 切换：随出牌/战斗等状态改变，按拍、按小节或片段出口转场；
- MIDI：媒体保存演奏/控制信息，不是已经录好的波形。

本次 721 个 MusicSegment 中有 430 个包含多条轨道；有的同时引用 WEM 与 MIDI。也有本身数十秒的 WEM。不能把所有音乐都描述成“短片段依次拼起来”。

同人作者没有提供具体缺失曲目的例子，故**没有证实另一个藏着完整歌曲的第四目录**。已定位来源支持“遗漏内嵌媒体、MIDI 或音乐结构”这一解释，但不能据此断定对方具体遗漏了什么。

## 三、怎样保留二进制载荷

1. 收集上述 Bundle 和 `streaming_audio` 的副本，记录版本、原路径、大小及 SHA-256。
2. 用 UABEA 或 UnityPy 找 TextAsset，取出 `m_Script` 的原始字节；不要通过普通文本 Dump 中转。
3. 以 `BKHD` 开头的载荷保存为 `.bnk`，以 `RIFF` 开头的载荷交给媒体解析器检查。
4. 根据 DIDX/DATA 索引导出银行内嵌媒体，保留媒体 ID、所在银行、偏移、长度和哈希。无 DATA 的逻辑银行也要保留。

UnityPy 1.25.0 的 TextAsset 读取可能把二进制载荷表示为含 surrogate 的字符串。恢复字节时采用可逆编码，而不是 `errors="replace"` 或 `ignore`：

```python
# obj 为已经确认类型是 TextAsset 的 UnityPy 对象。
asset = obj.read()
payload = asset.m_Script
raw = payload.encode("utf-8", "surrogateescape") if isinstance(payload, str) else bytes(payload)
# 再检查 raw[:4]，将 raw 以二进制写入新输出文件；不保存/修改原 Bundle。
```

不同工具版本可能返回不同类型，以实际 API 为准；首次导出应通过长度和再次读取确认没有改字节。DIDX 的边界及类型分类见[第 03 篇](03.AB包内BKHD SoundBank解构与手改警告.md)。

> [!IMPORTANT]
> 同一个 ID 可能在多个位置出现。平铺成 `media/<ID>.wem` 前先比较哈希；若同 ID 内容冲突，分开保留并记录版本/银行，不静默覆盖。

## 四、先读音乐引用，再决定哪些文件是 BGM

用 wwiser 解析全局银行的 HIRC，沿 MusicTrack 的来源引用收集 ID，并保留来源插件类型。不能靠数字文件名、时长或文件打开记录单独判定 BGM。

本次 `Global_Data` 的结构计数：

| 类型 | 节点数 |
| --- | ---: |
| MusicTrack | 4183 |
| MusicSegment | 721 |
| MusicRanSeqContainer（随机/序列） | 188 |
| MusicSwitchContainer | 32 |

其音乐轨道引用的 **4731 个去重 source ID** 全部在本次缓存中定位：

| 来源 | 数量 | 后续处理 |
| --- | ---: | --- |
| Vorbis | 260 | 240 个在独立流目录，20 个在银行内嵌媒体中；均可导出试听 |
| Wwise MIDI | 4471 | 保留银行与索引；当前流程不能完整合成演奏 |

来源与节点数不是歌曲数。一个来源可被多条轨道/多个状态复用；一个片段也可需要多个来源。

## 五、MIDI 的边界与最小交接清单

不要把 Wwise MIDI 改名为 `.wem` 或 `.mid` 后宣称转换成功。它可能参与实际演奏或同步控制；仅靠目前工具不能断定所有 MIDI 都是可忽略的静音。

只提取 Vorbis 的版本即便可以试听，也可能缺少声部。完整银行及 MIDI 来源索引要随技术素材保留，供进一步还原；当前缺失不能用随便找的乐器或自编音符冒充原版。

每项交接至少包含：**研究编号、节点类型/ID、状态条件、源媒体 ID、来源路径/银行、SHA-256、导出参数、是否缺少 MIDI、失败原因**。没有证据的曲名留空，让人工队识别。下一步见[第 06 篇](06.wwiser与vgmstream音乐编排导出.md)。
