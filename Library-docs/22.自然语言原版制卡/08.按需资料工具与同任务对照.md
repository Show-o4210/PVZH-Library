# 按需资料工具与同任务对照

2026-10-22，Android R16 开发记录。本页归档按需资料设计、16 份真实 API 主对照、两份 legacy 锚点与三组原引擎抽测，**把静态语义符合、具体游戏场景通过及真实失败分开记录**。前序项目登记与标签联动见[07](07.项目登记簿与标签联动.md)，原版组合及最小验证见[06](06.实验原版组合与最小验证.md)。本轮不升级本库公开 Python v1 的 plan 合同，也不增加新的游戏 Hook。

## 为什么拆资料，还要提供阅读工具

大文件不是模型必定不会阅读的原因；关键是服务是否把它送进本次请求，以及模型能否主动取得尚未送入的部分。此前 Android 预选资料把少量相关原卡与节点直接放进上下文。模型不会因为 Library 磁盘上有其他文件就自动访问它们。

R16 将通用资料组织成有稳定 ID 的小条目，给模型一份简短目录和两种只读工具。模型先寻找相关来源，再读取具体条目，需要时继续检索；可以只读相关卡牌及节点，避免每次把完整库塞进请求。**拆文件本身不构成检索能力**，需要服务实际支持标准 tool calls，并把每个 tool 结果回传同一轮对话。

工具不开放任意磁盘路径、网络访问、原生执行或写文件；修改仍由模型输出计划、现有编译器检查，再由用户同意整份提案。查询次数多不能证明技能正确，也不能代替结构检查或游戏实测。

## 适合按什么粒度拆

| 层次 | 条目应回答什么 | 不应混入什么 |
| --- | --- | --- |
| 短目录 | 有哪些主题、工具怎样取资料、当前版本/预算 | 全部原卡实体 |
| 语义概念 | 抽牌与生成、来源与事件目标、设值与增减、期限 | 某个 Mod 作者的私有约定 |
| 原版模式 | 多个原版组件如何配合，依赖及适用范围 | “所有组合已经实测”的结论 |
| 原卡实例 | 某张原卡的完整有关实体、属性/标签/文本 | 被裁掉但没有说明的后半段实体 |
| 节点参考 | 精确字段、已观察枚举、引用规则和开放字段 | 猜测出来的新原生类型 |
| 反例与案例 | 初始要求、失败现象、修正与证据边界 | 抹掉失败只保留最终方案 |
| 当前项目 | 当前卡牌与 CN、待审稿、登记簿/自定义 tag | 其他 Mod 的记忆或 API 凭据 |
| 实验能力 | 用户当前许可、运行依赖、可表达的扩展配方 | 未启用的能力默认可用 |

主题划分应允许交叉引用。例如“随机获得锦囊并降费”同时涉及卡池、数量、生成结果身份与费用，不宜只放进一个巨大“抽牌”文件。先读概念，再按引用取具体来源；不要把同一事实复制到很多条目后各自维护。

原卡的技能实体需要保持完整依赖。`HeraldEntities.ids` 指向该卡完整 `EffectEntities` 数组的零基索引，不能截掉数组开头后仍原样解释编号，也不能把“第五个实体”误当成 ID 5。查阅返回体若受预算限制，必须明确显示省略，要求缩小读取范围；不能给模型一个看似完整的断裂技能包。

## 查询与阅读的区分

接口示意如下，只解释只读工具，不是可导入的卡牌 JSON：

```json
{"name":"search_knowledge","arguments":{"query":"仅本次生成牌 设为0费","limit":8}}
```

搜索返回条目 ID、标题、类别与简短摘要。模型选择结果后调用 `read_knowledge`，以 `ids` 批量读取；可提供受支持的 `sections` 缩小范围。必须使用当前目录真实返回的 ID，不凭示例猜造条目。

稳定前缀区分 `topic:`、`concept:`、`pattern:`、`case:`、`node:`、`project:`、`extensions:` 等。尤其要区分：

- `card:`：当前 Mod 的工作基线，包含已经保存或当前累计待审的内容。
- `original-card:`：原包来源，用来核对原版技能、复制与比较。

若当前 Mod 已改过某张卡，读取 `card:` 不能冒充“原版证明”。项目登记簿中的作者说明也只是项目资料：记录某个 tag 的名称、成员和设计目的，不代表它已被引擎结算验证。

查询应返回明确的未找到、无效参数或预算错误。不能用空结果掩盖错误，也不能读取一个包含无效 ID 的请求后，把所有请求 ID 都统计为“已读”。建议分别记录请求的 ID、成功返回的 ID、整项省略与实体是否完整。

## 维持一条可恢复的旧通道

R16 每个 Mod 独立选择资料读取方式，默认“AI 按需查阅”。三种方式分别登记：

| 值 | 内容 | 判断用途 |
| --- | --- | --- |
| tools | 模型通过工具自主选读 R16 修订资料 | 新流程 |
| fixed | 程序预选同一份 R16 修订资料 | 主要公平对照 |
| legacy | R15 原资料与原预选 | 恢复与历史锚点 |

旧资料包含已知错误时，保留其历史身份，另在修订资料说明纠正；不要悄悄改旧版后仍称其是原恢复通道。若提供方不支持工具，明确报错并允许用户选择 fixed/legacy，不能后台静默切换却继续显示 tools。

方式在请求开始时冻结。用户在运行过程中更改偏好，只影响下一次请求，不更换当前请求的资料或覆盖已经保存的对话、Mod 版本、GUID 预约和 API 配置。独立偏好文件 schema 为 1；损坏时保留现场并提示，不能按默认值重写全部偏好。

UI 同时区分“下次方式”和“本次方式”，显示实际读取进度及可打开的摘要。摘要随对应 AI 回复/提案保存，避免采纳或下一轮请求覆盖最近 request 后找不到记录。记录不包含全部重复资料或凭据；详细语义判断仍看候选卡实际结构。

## 本轮需要纳入资料的反例

R15 的孢子工坊实验发现，`ModifySunCostEffectDescriptor` 写 `BuffDuration=EndOfTurn` 不代表手牌费用一定在回合结束恢复。已观察的原版 EndOfTurn 清理路径处理 Attack/Health，没有自动处理该手牌 SunCost；原版 GUID180 的文字也没有承诺“本回合减费”。最终三卡采用来源隔离的持续减费，不能把它写成原临时减费要求已经完成。

这个反例应放进费用与期限相关条目并链接原案例，不能只埋在一份很大的验收报告末尾。模型有 `EndOfTurn` 枚举不等于已有正向语义证据；同样，当前缺少一种准确恢复写法，也不等于证明引擎所有可能组合绝对不能实现。需要把事实、推断、表达缺口和待测范围分开。

## 如何做同任务比较

主要比较 fixed 与 tools，使用相同原版空 Mod 的独立克隆、全新会话、同一模型及采样配置、同一资料版本和编译器。任务中文原文一致，不给某一侧补原卡答案。新增 GUID 按各自预约分配，审查按逻辑角色对应，不能回滚预约来凑相同编号。

这仍然是“同语料、不同读取流程”的产品对照，不是纯检索算法或模型聪明程度的因果实验。fixed 会自动提供完整计划 schema 等通用概念，tools 需自行取读；tools 可多轮追查，两侧资料预算与工具协议开销也不同。应报告实际提供/读取/省略的条目和开销，不能把 schema 没读到、预选没命中或长条目被预算挤掉的影响，全部解释成模型判断能力差异。

预先登记八类任务：随机植物普通锦囊设 0 费、每回合首次事件目标加血、死亡抽牌、临时费用正确性判断、token 收藏边界、未知原生能力判断、生成来源隔离、刚打出的敌方单位设攻。预算较小时先成对跑四类：随机池设费、死亡抽牌、期限判断、未知能力；可再用 legacy 跑随机池/期限两个历史锚点。完整清单不是完成记录，未跑项写 `NOT_RUN`。

验收应分层：

1. 请求/工具协议成功与格式解析；失败和修复轮也保留。
2. 是否按用户意图生成提案；只评估任务应无修改。
3. 实际编译器的结构结果，不采信模型自报“可编译”。
4. 对实际组件/字段独立核对语义：目标、时点、次数、来源、期限、无关卡差异。
5. 游戏中独立正反例；未测就是 `NOT_TESTED`，能进入游戏也不等于技能全部正确。

每项记录所有 HTTP 请求、工具轮数、实际读取 ID、截断/失败、修复次数、累计输入输出 token 和耗时。输入总量要包括重放对话与工具结果；提供方缺失 usage 时写不可得，不能用 0。若某轮失败而丢失 usage，后续成功一轮的 token 不能冒充整项总量，应标记累计数据不完整。

不使用自报信心、措辞流畅或阅读次数当作技能正确率。不删除首次失败，只挑最终成功；不把 legacy 与 tools 的差距全部解释成主动阅读效果。样本很少时按任务报告差异，不宣称模型能力普遍提高。

## 本轮实际对照

正式 RC2 使用 deepseek-flash、temperature 0、thinking disabled、JSON 外壳、max_tokens 8192；八项任务各执行 fixed/tools 一次，共 16 个用户任务。每项独立克隆原版空 Mod；有修复时累计计数，没有挑成功答案替换失败。语料 SHA-256 为 `8c373859872edd074d4e05ad15d8375782f691d08daf948877e5e868d2cc1e9b`。RC1 早期协议问题另留诊断，不混入主成绩。

独立按预登记 74 条断言审查实际 plan、编译预览、原卡及工具轨迹后，fixed 为 2/8 项静态意图或边界判断符合，tools 为 6/8 项。**这不是游戏成功率**：需要提案的六项里，fixed 有三份结构通过但只有一份符合意图，tools 六份结构通过但只有四份符合意图；另外两项是只讨论的边界判断。

| 任务 | fixed | tools |
| --- | --- | --- |
| 随机植物锦囊、仅本次设 0 费 | 错选僵尸模板 542，文字却称植物 | 正确植物模板 10，配置符合 |
| 每回合首次目标 +2 血 | 配置符合 | 配置符合 |
| 来源自己死亡抽 2 张 | 未知死亡短名被拒，修复后未提案 | 错写成其他植物死亡，结构通过但语义失败 |
| 临时费用是否到期，只评估 | 边界判断符合 | 经一次格式修复后判断符合 |
| 不可收藏 token | 普通克隆，没有实现隐藏边界 | 同样缺少边界，且声称的 Unusable 未写入 |
| 不存在的回滚组件，只评估 | 两次外壳 plan 类型错误，没有有效回答 | 不造组件/不改文件，核心拒绝符合 |
| 指定生成与来源永久减费 | 未登记 Subset 值被编译拒绝 | 配置符合 |
| 刚打出的僵尸设攻 1 | 阵营误读和不必要澄清，未完成 | 配置与中文符合 |

实际累计成本来自逐轮 accounting：fixed 11 次 HTTP、输入 194,911 token、输出 8,497 token、主机观察总耗时 92,507 ms；tools 37 次 HTTP、输入 572,087 token、输出 13,873 token、148,789 ms，另有 48 次工具调用。两侧 usage 都完整。tools 输入约 2.94 倍、耗时约 1.61 倍；不能只报告正确项增加而省略读取成本。fixed 工具返回字符为 0 表示没有工具调用，初始预选资料仍计入输入。

还保留了没有直接反映在汇总分数里的问题：首次/永久范围经编译器自动描述后可能只剩“BuffEffectDescriptor”，玩家看不懂；tools 的未知能力答复把宽泛搜索的有结果说成“均无命中”，虽然精确类名查询确实为 0；临时费用讨论出现把组件字段说成卡面、先断言持续到离手又说离手待测等不严谨文字。主动读取没有消除误读和表述错误。

## 三组原引擎抽测

Root 在已授权设备执行，独立审查者只读核对报告与刺激脚本；没有人工替换原 AI 技能。运行场景使用合法出牌及原引擎结算，无模拟触摸和截图。

- **随机锦囊 tools：18 项通过。** 两张旧手牌、现场上限 10 时，生成 8 张补到 10；均为普通植物锦囊且 0 费，实际出现重复卡；旧牌费用不变、牌库不因生成减少；另一单位不重复触发工坊，另一原版来源后来生成的牌维持 2 费。只覆盖该具体场景，不外推空手、双工坊、跨回合和视觉表现。
- **每回合首次 tools：17 项通过。** 来源保持 1 血；首株其他植物变 3 血、同回合第二株仍 1 血；下一回合首株再次变 3 血，第二株仍 1 血。旧宿主脚本误排非两栖到水路，在 fixture 请求前停止，另留 host-abort，不计为技能失败；正确平地刺激重新独立运行。
- **来源死亡 tools：明确语义失败。** 第 9 项核心检查失败：其他植物死亡时实际手牌 +2、牌库 -2；来源自己死亡时手牌/牌库都不变。进程仍存活、当前 PID crash buffer 为空。它确认了 Not(Self) 的静态目标错误，不能因为没有闪退就称技能实现成功。

运行来源标识为 R16 `evidence/game/k01-pool-zero-tools`、`k02-once-target-tools-land` 与 `k03-death-draw-tools`；计划/逐项审查与逐轮统计分别在 `evidence/comparison/rc2-primary`。这些是工程内证据位置，不是本库读者的必要依赖。完整调试服务、APK、签名材料与私有资料不随本章发布。

## 其他验收与边界

偏好类桌面检查 35 项通过，覆盖默认只读、按 Mod 持久化、非法值/损坏文件不覆盖、并发不丢其他 Mod，以及原会话/API 配置保持原字节。使用窄 Context 与原子存储替身，不能替代 Android UI 或 NativeChat 生命周期检查。八项清单的格式/ID 完整性检查通过，不等于它们的所有游戏边界通过。

legacy 两项另经真实 RC2 兼容路径执行：随机锦囊任务一次完成并产生结构通过提案（模板 10、Plants、10费7/5）；期限判断任务两次 plan 外壳类型错误失败。它证实恢复通道实际可调用，同时保留旧路径的问题；提案没有游戏验收，不计入 2/8 对 6/8，也不与两种修订语料流程合成第三组公平比较。

Android菜单8项通过，包含三方式显示/保存/回读与资料详情；只有菜单验收用到触摸。恢复24项通过，原4个Mod及资源、存档、旧会话核对并复原，26个本轮测试Mod从列表移除，7个新GUID预约保留。APK为R16 RC2，R15原APK与资料恢复通道保留；临时API服务已停止。详见[机器摘要](按需资料验收摘要.json)。完整游戏UI、动画和所有卡牌语义没有因此获得全量PASS，本页不重写R14/R15历史成绩。
