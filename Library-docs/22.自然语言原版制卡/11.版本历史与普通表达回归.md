# 11. 版本历史、真实筛选与普通表达回归

本节记录Android R24对连续创作的补充：真实历史快照、可检查的单次批量撤销、按当前卡表发现筛选值，以及普通玩家一句话测试集。它延续[R23批量与分类型审查](10.批量属性与分类型审查.md)，不改本库公开Python v1，也不把Android测试结果回填成旧工具已经升级。

筛选后的来源和验收见[连续创作验收摘要](连续创作验收摘要.json)；音乐是独立运行时能力，见[第21章09](../21.语义调试与技能扩展实战/09.本地背景音乐与共享生命周期/README.md)。本页归档时，历史与API已验，音乐RC3/RC4失败保留；RC5音乐原引擎18检查、原版隔离冷启动10检查通过，实际听验未做。

## 版本是一份快照，不只是ZIP哈希

同一个原ZIP可以有不同的手动文件映射。只比较归档字节会漏掉“当时用户选了哪一份card_data/CN”的变化。R24同时保留：

- 原ZIP的SHA256；
- 稳定索引指纹：Mod身份和卡牌命名空间、标题、runtime/能力声明、源文件→逻辑资源族/SHA/选择方法、overrides；
- 实际资源winner，而不把勾选状态和导入时间算成内容修改。

回退读取同Mod、同命名空间的真实历史原件，校验索引归属、SHA和原ZIP，再生成新revision的候选。旧ZIP、旧索引和旧账本不覆写。恢复范围是整份Mod快照，包括卡表/CN/关卡、项目资料、音频与其他附带文件；附带文件不会因为被恢复就自动获得执行权。

历史候选把当时实际采用的映射winner写清楚。用户同意保存时重新核对历史索引，并恢复当时的overrides，不能用当前映射偏好盖掉刚批准的旧版本。旧直接恢复接口仅保留兼容，新界面从差异预览进入普通待审提案；同意后才保存，仍需完整重启游戏加载。

## 单次撤销需要真实输入和依赖检查

随Mod传播的账本是资料，不能仅按其中的before值给当前卡表赋值。R24先定位该批次真实`input_zip_sha256`对应的本机原件或真实历史草稿，从实际卡表重放整批程序，核对输入/输出/非属性SHA、逐步操作和目标集，再决定撤销值。

操作使用整条批次记录的`entry_id`加`op_index`定位。只有`operation_id`不足以区分同一程序在不同版本重复出现。

撤销只恢复本次实际改变的字段，并保留后续无关费用、攻血、技能、CN、关卡和资源。放行前检查：

1. 当前值仍等于该操作当时的after值，即CAS保护；
2. 后续有没有再写同字段，或通过`current`、跨批次`base`读取它；
3. 后续数值选择器是否读取待撤销字段。

数值筛选可能使原先未命中的卡重新进入集合，不能只看后续已经命中的GUID。当前采取保守依赖判断，冲突返回有界说明、无部分ZIP，不静默重算后续效果。

原本0攻且缺Attack组件的单位，如果该批改补了最小Attack，撤销会验证该容器仍严格最小并移除；后来扩展过该组件则报告冲突。撤销审计追加到独立记录，原批量账本不改。“收据标记已撤销”不能作为放行证明；重复点击仍从真实输入和当前值核对，不能靠伪造收据跳过依赖。

结构化读写检查也不能推断全部人类语义依赖。例如后来故事写“必须9攻”，不能擅自猜它是否需要同步修改。此类约束仍由玩家审阅。

## 筛选值要发现，不要猜数字

`query_units`的只读目录来自当前冻结单位卡表，包含种族、稀有度、卡集、职业及两栖/组队分布。目录约5.4k字符，可按组分页，不返回全量GUID。它面向全局当前单位，不预先套用普通查询的selector。

新增选择字段如下，所有字段之间为AND：

| 字段 | 行为 |
|---|---|
| `subtypes` | 同时具有所列种族，例如Peashooter与Nut |
| `subtypes_any` | 具有所列任一种族，例如Bean或Peashooter |
| `rarities`、`sets`、`colors` | 各组内为任一值；使用当前目录的准确字符串 |
| `is_aquatic`、`is_teamup` | 布尔条件 |
| `cost_min/max`、`attack_min/max`、`health_min/max` | 操作开始时基础属性的闭区间 |

种族名称与根Subtypes组件编号逐位配对，检查名称↔编号唯一；当前原版34种族配对无冲突。目录中的数字是已观察映射，不授权模型创建新Subtype。

尤其注意根`rarity=0/1/2/3/4/5`分别对应`R1/R2/R3/R4/R0/Event`。**传说为R4，对应根整数3；根整数4是R0。**R0含基础与衍生单位，不能等同于Token，也不能替代`sets:["Silver"]`。稀有度、卡集、Token/power和不可收藏标记分开处理。

新枚举不接受数字、未知名、空数组、重复值或控制字符；错误指出字段/GUID并引导读取目录。两栖、组队、稀有度和种族还核对显示元数据与根ECS标记的一致性。批改仍限单位基础属性，不把锦囊/环境的攻血、批量技能覆盖或任意文件修改混入这条路径。

## 普通玩家话术与独立Oracle

30条定义中有19个可机器检查的批量案例；其他覆盖目标不明、只讨论、历史操作、缺失音乐和能力关闭。定义本身不是30次模型成功。测试者只把日常`prompt`及正常项目资料交给模型，不能把测试用`where/effect`一起投喂。

Oracle从实际before元数据和ECS独立计算目标和值，不按模型计划反推期望。它检查所有目标、非目标、未提及属性、技能/辅助实体、卡表集合和CN；JSON类型严格比较，不让Python的`True == 1`掩盖类型变化。0攻单位只放行有依据的最小Attack补全。

返回层次明确：数据符合为PASS，错误为FAIL，处理中为PENDING，历史/音乐等卡表无法证明的行为保持UNVERIFIED。没有实际回复分类，不能仅凭“没有改文件”把目标缺失处理判成澄清成功；没有API会话也不会声称真实模型通过。

真实原版CSV包含大量空Key填充、重复空Key和一条三列记录。首轮过严解析曾误拒原包，FAIL保留。修正后按有效两列记录取值，同时保留整份CSV字节SHA，因此既兼容原包，也能发现只比较最终字典时漏掉的填充行删除。

## 已核对结果

| 层次 | 结果 |
|---|---|
| 历史核心 | 两种JSON各48检查，完整反例集512MiB；真实双快照生产热路径256MiB各7检查；Store/映射24检查 |
| 设备历史/界面 | Pixel6协议25检查、实际Android界面5检查通过；这些不等于战斗结算 |
| 筛选 | 两种JSON各12453检查，旧核心各1241；128MiB真实回读/重放保持R23六项golden哈希 |
| Oracle | 20项正反例自检；19组人工确定性原生输出交叉验证；不是19次API |
| 真实API | DeepSeek八条最终全部符合预期，无手改计划；n10经过内部修订，不是八条首轮全对 |

八条真实API分别为全体9/9、豌豆加血、小鬼降费、传说植物固定攻击、低费僵尸加血、目标不明澄清、仅讨论、未导入曲目澄清。五个批改候选均由独立实际回读验证，保存Mod仍未改变；用户尚未同意不能说已经生效。具体目标/变化数量与候选SHA见机器摘要。

批量计划正文为201～271字符，省去了逐GUID展开；但独立理解、检索和审查仍包含1～12次HTTP请求，不能由短计划直接宣称端到端低延迟或更低总token。这套八例没有战斗实测。

## 保留失败与范围

R24宽反例夹具同时持多份全资源快照，在256MiB构造额外fixture时OOM；完整集改在512MiB验，双快照生产热路径另在256MiB验。不能将局部热路径通过写成整个夹具256MiB通过，也不能以JVM堆结果替代Pixel内存或实际游戏。

R23首次真实审查OOM及后续RC4修复成绩继续保留在上一节，不被本轮覆盖。当前本地回退仍继承编辑器47MB ZIP、128MB展开限制，不承诺大型美术包全部可编辑。库内只保存方法与筛选证据，完整Android工程、设备原件、运行日志、密钥与游戏资源不随Library提供。

本机工程说明：版本核心（`pvzh-launcher/native-r24/docs/VERSION-HISTORY.md`）、筛选（`pvzh-launcher/native-r24/docs/BATCH-FILTERS.md`）、回归（`pvzh-launcher/native-r24/docs/NOVICE-REGRESSION.md`）。这些文件名对应退役工程，保留作历史来源。

最终收尾按独立汇总登记：RC5原证书APK保留，设备134项恢复检查通过，760份原工作台文件、65账户和2887资源指纹恢复；10个本轮测试Mod隐藏、10会话归档，音乐登记禁用。没有清空账户，原始备份留本机；本章不复制设备详细记录。
