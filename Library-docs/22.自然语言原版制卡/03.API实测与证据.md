# DeepSeek实测与验收（2026-10-18）

本页记录初轮API与离线制作证据。用户随后授权的独立设备抽样另见[04](04.API卡牌独立真机抽测.md)，不能把后续样本成绩扩展成这里全部32例或415来源已经战斗通过。

本轮使用用户授权的DeepSeek API，实测返回模型`deepseek-flash`。共10次生成请求、40份计划（含重测）、32个不同中文用例；实际累计29,198输入token、2,553输出token，共31,751。认证信息仅在测试进程内存，通过隐藏输入传入，没有写入代码、提示词、响应记录或文档；测试worker已退出。

调用根据当日[官方API入口](https://api-docs.deepseek.com/)与[JSON Output说明](https://api-docs.deepseek.com/guides/json_mode/)核对，使用JSON对象输出。JSON可解析只解决格式问题，后续仍独立检查中文含义、原版组件及Bundle。

## 最终结果

| 层 | 结果 | 能证明的范围 |
|---|---|---|
| 中文样本 | 32／32符合预先写好的预期 | 23个ready、6个unsupported、3个clarify；包括错误拒绝修正及4个最后新增说法 |
| 候选回包 | 23个ready均对两个Bundle回包／回读 | 中文与卡表能序列化，非目标对象字节保持一致；无变化Bundle原字节保留 |
| 原生复制矩阵 | 415／415静态比较通过 | 当前原包`isFighter=true && usable=true`的能力包复制保真；不是收藏可见性或游戏交互保证 |
| 工具检查 | 27项通过 | 非法字段／代码、扩展标签、目标／动作、跨阵营、重复组件、基线、覆盖输出、有限反馈等 |
| 游戏运行 | 本轮未测 | 没有ADB、安装、对局、动画或AI预测验收；现有Mod和设备未改 |

415项中的“可用”指原包字段，不等于每一张都在收藏界面可直接收集。能力包保留字面GUID，隐含同名、种族、循环与视图联系仍需在目标底卡上验证。

## 实际遇到的失败

首轮24例通过22例：程序把“中文无需变化”的零对象变化Bundle误报为失败；模型把原版已支持的本线战斗开始前额外攻击错误拒绝。前者改为原字节复制，后者通过明确时机与合法组合说明修正，重测相应批次。

随后新增4例时，模型又把“造成伤害后随机弹射一株敌人”错误拒绝。合同已明确该组合；补清“伤害事件接单一bounce”与“bounce后继续别的动作”的区别，重测通过。最后再新增4个未用于改提示词的表达，4／4通过。

因此，**最终32／32是校准后的组合结果，不是首次请求成功率，也不是32个全新样本上对最终提示词的一次性估计。**公开记录混合保留不同提示词阶段的通过输出；相应原始散列、重复次数及失败在[验收摘要](验收摘要.json)里分别记录。

评测助手还出现过相对／绝对路径混用：生成与回包已经通过，写报告引用时错误，导致一轮正例全部被标FAIL。修正路径后重新执行，旧FAIL保留。单元检查遇到Python 3.14临时目录ACL与受限令牌不兼容，以及UnityPy路径读取残留句柄影响Windows删除；改为项目目录继承ACL和字节加载。最后一个新增负例误认为原表有usable=false的单位，改为内存中显式构造不可用来源后验证。没有为让测试通过修改原始输入。

## 复查方法

[32例测试集](../../tools/natural-card-author/benchmarks/cases.json)在调用前写定对应预期；[recorded目录](../../tools/natural-card-author/benchmarks/recorded/)只保存脱敏后的模型计划及模型／用量信息，不含请求认证头和原始游戏对象。原始报告指纹与筛选关系在机器摘要中。

提供匹配原版Bundle后，可在[工具目录](../../tools/natural-card-author/README.md)运行：

```powershell
python benchmark.py --input 'C:/work/original' --output 'C:/work/replay-v1' --replay benchmarks/recorded --pack
```

这是离线回放，不再次调用API。`--live`才会发送请求，32例最多8个四例批次；新结果必须放新目录，不覆盖本轮记录，也不将本轮成绩当作新模型／新版本的结果。

完整API请求、原始响应、回包候选与早期失败保留在原工作区`native-card-author-lab`。库中只有源代码、合同、用例与筛选证据，没有游戏Bundle、完整卡表、APK或密钥；克隆Library仍需自己的原包。

## 尚不能推出的结论

这些样本不是随机抽样，覆盖面有限。尚未证明全部原版条件、所有数值、所有卡牌组合和自然语言说法都能正确生成；未验证所有移植的实际时序、动画和AI。完整原生类型表不等于所有类型自由组合均已开放。下一步应建设累计项目与经过游戏验证的配方库，再接玩家UI及加载端。
