# 独立审查与新手表达验收

2026-10-22，Android R17 架构与实验方法归档。本页接续[按需资料工具与同任务对照](08.按需资料工具与同任务对照.md)，说明如何把主动查阅升级为需求理解、真实候选核对和有限内部返修。它没有升级本库公开 Python v1 的 plan 合同，不随库提供完整 Android 工程、调试服务、APK、凭证或原始 API 对话。

本轮关注普通玩家的一次请求能否得到准确、可审阅的结果。更多调用、更长回答或更多提案均不直接代表质量更好。模型核对、结构检查、原引擎刺激、完整玩家流程与动画表现分别留证。

## 从单作者到有边界的质量流程

原流程已经允许模型搜索资料、读取原卡和组合已知节点，但作者仍可能同时误解需求、写错目标，又用相同误解解释自己的计划。结构检查通常不能发现这类问题：例如要求“自身死亡抽牌”，候选实际监听其他植物死亡，依然可能是合法 ECS。

R17 将职责拆为以下顺序：

```text
玩家原文 + 当前项目
  → 独立理解需求与正反例
  → 作者查阅并生成增量计划
  → 本地编译并回读真实候选
  → 独立核对原文、需求与候选
       ├─ 确定错误：有限内部返修
       ├─ 合法未测：保留具体未测范围
       ├─ 确实缺表达能力：说明缺口
       └─ 只需修中文：CN 子候选 → 再审
  → 最终提案 → 玩家同意或拒绝
```

需求理解阶段尚未看到本轮作者计划。作者与审查各建新的工具上下文；作者可以收到独立需求和审查反馈，审查者不继承作者整段工具对话。它们可以使用同一供应商与模型配置，因此“独立”指职责、输入与取证分离，不代表模型偏差互相独立。

模型仍只拥有搜索和读取知识的工具。实际修改由编译器形成候选，最终保存由玩家明确同意触发；任何模型角色都没有自动采纳 Mod 的权限。

## 意图摘要也是待核对的解释

意图阶段将原文拆成 `requirements`，列出合理默认、关键问题与 `scenarios`。作者和审查可以据此工作，但摘要不能成为比原文更高的权威。审查者先检查“这些要求是否准确代表玩家”，再检查“候选是否实现这些要求”。

常见的过度限定包括：

- 玩家要求某种可观察效果，意图却指定必须使用某组件、算法或固定内部步骤。
- 玩家只在当前游戏规则下使用，意图却凭空要求适配任意手牌上限、规则配置或未来版本。
- 玩家说“其他植物”，意图却把它变成“不同名字的植物”。
- 玩家允许复用合适资源，意图仍增加原文没有要求的全新美术或精确模板条件。

这些额外条件不能仅因为已经获得需求 ID 就阻断正确候选。审查应保留逐项核对，并说明该条件为何超出了原文；不能删掉难做的真实条款，也不能把自己假设的条款悄悄提升为玩家要求。

低风险空白可以合理决定并说明，例如用户让 AI 自由设计的名字、故事或未指定强度。缺少关键修改目标时才澄清：“把那张卡改强一点”在没有选中卡、历史指代或待审目标时不应随便猜一张。理解者不要求玩家提供 GUID、JSON 或组件名。

## Self 是实例，不是同名卡集合

语义核对需要区分来源、事件对象、阵营和区域，不能仅对照中文名字。

| 表述 | 通常需要核对的含义 | 常见错误 |
| --- | --- | --- |
| 这名队友、这株植物、本卡、自己 | 携带技能的当前来源实例 Self | 写成其他队友，或所有同名卡 |
| 其他植物 | 在所需阵营/区域范围内排除来源实例 | 排除所有同名或同 GUID 实例 |
| 刚打出的那只 | 事件关联目标 | 给来源或随机单位加成 |
| 己方、自己的植物 | 阵营归属 | 把“其他”误当作己方筛选 |
| 本次获得的牌 | 这一生成事件实际产生的卡 | 同时改旧手牌或其他来源将来的生成 |

例如场上有两份同 GUID 的工坊 A、B。A 具有“其他植物被打出后……”时，B 仍可能是相对 A 的其他植物；B 与 A 同名不会自动变成 A 的 Self。测试应保留多实例情况，分别观察各自触发和重置，而不是发明“同名必须不触发”的反例。

“自身死亡抽两张”至少需要检查来源死亡会抽，其他植物死亡不替代来源触发；回手也不能当死亡。每回合首次效果则要检查事件目标、同回合第二次、下回合恢复与多个来源的状态是否独立。具体查询与过滤组合从完整原卡及当前编译结果核对，不能把一个组件名当成所有效果通用的正确写法。

## 按当前规则判断行为等价

玩家通常描述结果，不规定内部实现。审查不能因为内部次数、步骤或原生效果名字不同就直接判错，也不能仅凭作者声称“差不多”就通过。

例如“用随机锦囊填满手牌”可以有不同实现思路。只有在已核对当前手牌上限、实际获得效果的超量处理、随机卡池和生成结果范围后，才能判断“尝试获得固定数量，超额被丢弃”是否在该范围内与填满等价。不能凭空把另一套上限加入验收，也不能在没有溢出证据时宣称任意配置均等价。

“设为 0 费”与“减少一个很大的数”同样需要检查当前池费用范围、费用下限、作用对象、期限和后续交互。仅对眼前卡面结果相同，不足以自动覆盖未来增费、旧手牌、其他生成来源等差异。“本回合减费”与持续减费已有已知语义差别，不能用文字把两者合并。

判断依据按顺序包括当前游戏规则、实际候选字段、完整原版来源、已知反例及相关原引擎收据。若存在可观察差异，写清触发条件和证据；资料不足但表达合法时保留未测范围。行为等价必须说明适用范围，不据少量场景推导跨版本万能结论。

## 真实候选事实与版本绑定

审查输入来自实际编译后的 ZIP，不从作者回复反推技能。事实提取器比较三个快照：

| 快照 | 用途 |
| --- | --- |
| 已保存源 saved | 当前真正保存的 Mod |
| 请求起点 working | 当时旧待审稿；没有待审稿时等于 saved |
| 最终候选 after | 当前编译产物，含内部返修及可能的中文子候选 |

`working → after` 是本轮增量；`saved → after` 是累计变化。它们不是相邻两次内部返修的差异。分别保留卡牌数据、CN 和关卡关键字段前后值，既看本轮改了什么，也看玩家最终会采纳什么。

候选产物 SHA-256 取自实际 ZIP 字节，必须匹配已知编译报告。逐卡另外计算机械定义指纹与 CN 指纹，使“技能相同、说明变了”可以区分。审查记录绑定草稿 ID 和产物 SHA；来源发生变化的过期请求不能发布。

逐卡事实包括实际阵营、卡种、身材、文本绑定、资源/模板身份、tag/subtype、收藏相关标志、组件类型及完整技能实体。技能数组保留原顺序和所有辅助实体，`HeraldEntities.ids` 仍按完整数组的零基位置解释。不能截掉几个实体后保留旧索引，或只看触发器名称推断后续正确。

不把全部原卡重复塞给每个角色。差异摘要有条数与字符预算，省略整项时必须明确列出；完整事实和按 ID 读取路径继续保留。登记簿、导入笔记、作者自述和编译报告中的说明均不是可信运行收据，不能使 `NOT_TESTED` 变成游戏 PASS。

## 部分阅读用于导航，完整阅读用于最终门禁

`search_knowledge` 返回定位线索；`read_knowledge` 可读某 ID 的全部或指定部分。部分读取仍有价值，例如先看身份、CN 或一个节点。但在最终审查实际变动卡时，“请求了这个 GUID”“搜索到它”“读过原版同号卡”和“完整读到候选”是不同事实。

R17 的审查知识快照冻结到当前 after：

- `card:<GUID>` 读取最终候选。
- `original-card:<GUID>` 读取原包，仅用于比较与参考。

当前程序对本轮增量中的所有变动卡要求完整候选文档，包含 `identity`、`localization`、`components`、`abilities`、`evidence` 五部分，以及完整有序技能数组和辅助依赖。部分章节不能冒充完整读取；失败、超预算省略、原版卡或前一次格式失败尝试中的读取也不能满足最终门禁。

实际工具结果生成普通 `read_ids` 与 `full_card_read_ids` 等分离收据。阶段格式重试后，仅最终成功尝试的完整候选读取用于门禁。程序不从请求参数或模型“我已阅读”的说法推定成功。缺少完整回读时阻止发布，优先重审同一候选，不立即重新写卡或预约新 GUID。

大卡无法完整返回时，应单独读取或缩小修改批次。不能把技能树裁断后给它一个完整标记。这个门禁能证明资料确实进入过相应上下文，不能证明模型已经正确理解，更不能代替原引擎。

## 中文子候选也要重新审查

卡文正确性属于产物，而不只是回复润色。审查可对本轮已变动卡提出短/长技能说明修订，例如把“组合1：PlayTrigger；BuffEffectDescriptor”替换成玩家能理解的实际技能。

这条接口仅写对应 CN，不允许审查者直接改技能、身材、名称、故事或其他卡。只剩这类可修文本问题时，可以给出“等待中文子候选复审”的静态结论；程序随后编译 localization-only 子候选，重新提取事实、绑定新产物 SHA，并再次完整读卡和核对。之前的 pass 不直接放行改后的 ZIP。

若技能本身没有实现，不能先把中文写成成功效果；若技能正确，说明也不能删掉关键目标、数量、来源或期限。相同文本无需生成新候选，真实改字则必须经过最终复审。

## token 缺口应诚实表达

当前 Android 作者合同仍没有显式 token、可收藏、可组牌生命周期字段。实际 `usable`、`Unusable` 等标志可以作为事实读取，但需要区别标志存在与收藏/构筑真实行为已经验收。

普通模板克隆、名称叫“分身”、故事写“只能召唤”、未自动解锁，都不能证明它是 token。用户要求“只能召唤，不进入收藏和卡组”时，若当前接口无法完整写入这个边界，应明确说明能力缺口，不交付普通新卡后口头宣称完成。

诚实缺口可以算理解和真实性正确，不能计作完整制作成功；乱造 token 则是另一种语义失败。也不能通过删存档、清牌组或回滚 GUID 预约来掩盖生命周期问题。

## 内部草稿不等于玩家采纳

模型可内部返修，但最多 3 次作者迭代、4 个审查循环；格式修复和工具往返另有分层预算，因此这些数字不是总 HTTP 次数。中文子候选也消耗审查循环，不能在耗尽后改完就跳过最终核对。

只有最终 ready 报告才形成新的待审提案。澄清、讨论、明确缺口、未收敛、取消或错误，都不覆盖玩家原有 pending。内部候选保留用于诊断，不更新保存版项目记忆，不自动启用 Mod 或重启游戏。玩家最终同意的是一个绑定来源与产物指纹的完整候选，而不是某段模型解释。

保留完整 R16 作为旧 tools 行为的恢复基线；R17 的 fixed、legacy 继续提供原单作者路径。R17 tools 已经加入质量流程，不能称其与 R16 tools 完全相同。生产恢复应使用当次新鲜备份，不能用旧验收账户覆盖现在的玩家状态。

## 新手表达与同任务实验方法

主组使用普通玩家原文，例如：

> 给我做个小蘑菇，2费1攻3血。它死掉以后，我抽两张牌。

主提示不附组件、GUID、查询树、负例答案或人工评分断言。模型可使用产品正常提供的真实项目与合法知识工具。人工断言、预期刺激和技术表达对照单独保存，不能暗中给审查者标准答案后声称它更会理解玩家。

每个任务使用独立原版空 Mod 和新会话，冻结资料、编译能力、模型与采样配置。专业提示另作一组；修改某个失败提示后得到的成功，不冒充最初新手请求一次完成。GUID 按正常预约分配，不回滚预约凑对照编号。

建议覆盖属性修改、自身死亡抽牌、随机生成及费用、每回合首次与多实例、token 边界、关卡场景规则、故事/CN，以及目标确实不明的澄清。关键事件至少有正例和合理反例；反例也必须来自原意和当前规则，不能发明额外限制。

| 验收层 | 应记录什么 |
| --- | --- |
| 协议与读取 | 格式、工具实际返回、完整性门禁、失败与格式重试 |
| 意图 | 是否忠实理解、是否增加限制、澄清是否必要 |
| 结构与产物 | 实际编译结果、非目标变化、卡/CN/关卡与 ZIP 指纹 |
| 静态语义 | 阵营、Self/事件目标、次数、来源、期限、当前规则下的等价范围 |
| 原引擎 | 具体起点、刺激、正反例、实际结算、失败及未测边界 |
| 玩家流程 | 最终审批、保存、重启加载、收藏/组牌等本次实际覆盖范围 |

不同层级分别统计。明确错误应返修，合法未测保留 unverified，真实表达缺口给 gap；不能把三者都归为“模型没生成提案”。模型审查通过不是实机通过，进入游戏也不是所有技能通过。

成本记录包含 intent、作者、review、中文复审、工具往返、失败重试和重复输入；供应商缺少 usage 时标不可得或不完整，不能填零。质量优先允许初期增加成本，但需同时报告延迟与调用量。R16 历史成绩不能写成 R17 同任务结果，资料或编译能力的变化也不能全部算作独立审查的收益。

## 本轮验收摘要

2026-10-22至23，R16、R17 RC1、RC2分别执行相同八句新手原话；另有RC4三题、RC5一题反馈后定向修复。共28次用户任务、292次真实供应商HTTP，累计输入5701414、输出97425 token，包含所有重放与纠正；28个会话的用户消息均逐字等于预登记短句，额外用户提示0。专业表达组未运行。系统资料与原引擎反馈的变化单列，不能把定向组当盲测。

严格完整静态符合：R16为3题、RC1为3题、RC2为4题。RC2另有一题形式符合却在游戏中失效、两题协议失败、一题正确澄清。提案率、澄清、诚实能力缺口与完整制作成功没有混算。RC2输入约R16的1.41倍、宿主累计耗时约2.02倍；不宣称更省token或普遍准确率提高。

保留的原引擎四场：

| 候选 | 实际范围 |
| --- | --- |
| RC2小蘑菇自身死亡抽2 | 语义FAIL：自身死亡抽0；其他死亡0、回手不抽牌库正确，进程存活 |
| RC2小帮手 | 17项PASS：单控制者自身排除、每回合首个其他植物加2血、第二个不加、下一回合重置 |
| RC4小蘑菇修复版 | 12项PASS：自身死抽2/2、其他死0/0、回手+1/0，未手改AI技能 |
| RC5随机免费锦囊 | 18项机械检查PASS：10费7/5、补到10、新8张普通植物锦囊0费、旧手牌和其他来源费用不变、不消耗牌库 |

最后一题仍用了丰饶玉米角资源而非树木，属于机械符合、完整设计未达成，没有为了凑通过手工替换资源。token定向题准确说明当前作者合同缺少不可收藏/组牌表达，不产普通克隆冒充完成。RC1/RC4“补满”被额外解释为动态算法的误拒也保留；RC5补充普通术语定义后才产生最终提案，不能回填前轮成绩。

本地候选事实两种JSON各28项、质量协议各55项、实际Chat/Workbench闭环各54项、模板诊断各19项通过。部分章节冒充全文的程序漏洞由本地测试发现并修复，实际主组没有据此蒙混过读卡门禁。知识目录为24块，R16的23块原件与全部旧成绩保持。

游戏场景均独立QA克隆、冷进程、render=false，未模拟游戏点击或截图；完整自然对局、动画、收藏/组牌UI、所有模型兼容性及复杂未列联动不在本轮结论中。UI、设备精确恢复和最终构建/源码指纹以最终验收（`pvzh-launcher/native-r17/docs/RELEASE-VALIDATION.md`）及[质量闭环摘要](质量闭环验收摘要.json)为准。详细对照见R17对照报告（`pvzh-launcher/native-r17/docs/COMPARISON-RESULTS.md`），包含真实产物SHA、全部失败与范围限制。
