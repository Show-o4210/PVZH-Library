# 从制作经验到可调用的知识

## 需要达到的程度

一个可供普通用户使用的制作流程，应能完成：中文需求→定位底卡与原版能力→明确的中间计划→原版组件编译→中文同步→回包回读→按范围实机验收。每一步能解释来源和失败原因；不能只以JSON解析成功作为完成标准。

本轮实现了前六步的离线制作原型，并用DeepSeek进行真实请求测试。实机结算与公开产品的操作流程留在后续阶段。一个小模型配上受约束的合同可以覆盖不少制作需求；没有必要先训练一个“记住全部IL2CPP结构”的模型。

## 模型与程序各做什么

模型将“打出时随机伤害一株敌方单位”翻译为play、enemy_fighters、random及damage(amount)。GUID由本次原包索引查到；原始CLR类型和默认字段由程序从原包克隆。模型输出的未知字段、代码、私有规则编号都不会成为原生节点。

程序核对阵营、对象种类、引用和参数后，生成EffectEntityGrouping、触发器、Self／Trigger过滤器、PrimaryTargetFilter和原版EffectDescriptor。SelfQuery代表技能控制者，TargetQuery在已开放的出牌观察事件中代表刚打出的卡；二者不能互换。

需要复杂原版技能时可复制同阵营可用单位的完整能力包。该操作保留目标的身份、美术、种族及默认身材，复制来源的能力组件、技能树和原生词条／对应标志；不拆开重写复杂树，也不跨阵营盲换Plants/Zombies。身材变动需计划另外指定。

## 本轮复用的制作经验

- 递归检查每个实体的组件类型唯一性，不能只检查卡体。两个SetStat描述器不能放进同一能力实体。
- 一次手动选择后的串行动作需要确认同卡身份和原生筛选；原型拒绝bounce后再接别的动作，也不自动拆成两个独立Manual选择。
- 造成伤害后、本线战斗开始／结束、一次攻击结算完成是不同事件。通用攻击后不能拿DamageTrigger冒充。
- 召唤以原版空位查询和放置器决定。召唤组队单位时OpenLaneQuery的IsForTeamupCard必须与目标卡匹配，不能统一用false。
- 只改属性时CN可能无需变化，应该保留整个CN Bundle原字节，不能强迫“恰好一个对象变化”。有内容变化的Bundle才要求唯一目标对象变化。
- 回包从内存字节读取，避免UnityPy保留Windows文件句柄；输入、输出对象按序列化文件名和path_id完整比较。
- 输出长短说明由计划及实际词条生成，未涉及的中文物理行与原顺序保留，描述不能加入未实现的承诺。

## 对失败的分类

clarify用于缺少底卡、无法唯一定位或属性相互矛盾。unsupported表示当前合同／编译器尚未开放所需组合；它不等于原版引擎永久不可能。ready也需要通过程序检查；编译失败最多将真实错误反馈给模型一次，不执行它提供的修复代码。

编译器能拒绝非法计划，却不能仅凭结构判定模型有没有误解中文。为此，测试集先写中文及独立预期，再调用模型；还要检查其是否把确实支持的组合错误拒绝。本轮实际发现了两次这类误拒绝，保留在验收说明中。
