# 04. 全卡牌解锁与本地存档调试

为了方便测试自制的卡牌 Mod、新技能以及复杂卡组，开发者通常需要在本地调试环境中解锁全部卡牌与英雄。

本篇讲解玩家本地卡库的逻辑、`new_player_inventory` 初始配置解构、全卡牌解锁调试流程以及正版/非正版客户端的区别。

---

## 一、 玩家本地卡库与 `new_player_inventory` 初始模版

在 PVZH 客户端中，玩家拥有的卡牌资产与解锁状态分为两部分：

1. **服务器数据 (Server Inventory)**：联机匹配时与 EA 官方服务器校验的在线卡库资产。
2. **本地客户端缓存 (Local Client Cache)**：保存在应用 `files/` 数据目录下的本地配置文件与数据缓存，用于单机离线对局、战役及卡册展示。

在底层 `data_assets` 资源包中，定义了新玩家初始资产模版 `new_player_inventory` (TextAsset)：

```json
{
  "gems": 0,
  "heroes": {
    "Penelopea": 1,
    "CptBrainz": 1
  },
  "cards": {}
}
```
- **初始解锁英雄**：底层数据证明，新玩家注册登录后默认只解锁两个代号英雄：`Penelopea`（绿影侠）与 `CptBrainz`（超尸）。
- **初始钻石与卡库**：`gems` 默认为 0，`cards` 列表为空（后续随着完成新手指引动态注入基础卡牌）。

## 二、 本地全卡牌/全英雄解锁调试方案

> [!IMPORTANT]
> **正版客户端与 MOD 版本特别说明**：
> 文档下文提到的 `pvzh-local-inventory-mod` 补丁与 `inventory_extra.json` 本地卡库合并方案，**专为社区第三方 MOD/修改版客户端设计，绝非 EA/PopCap 官方原版**。
> **如果 Modder 自身使用的是 EA 官方正版（未修改）客户端，请直接忽略/跳过本地卡库合并方法**！因为正版官方客户端的卡库资产由在线 EA 服务器强校验，无法通过改本地文件解锁卡牌。

在开发 Mod（例如新建了新卡牌、修改了卡牌技能，详见 [02. 卡牌数据说明](../02.卡牌数据说明/README.md)）时，针对不同版本的调试方案如下：

### 1. 第三方 MOD 版本调试（`pvzh-local-inventory-mod`）
参考 [11. 静态高级实战](../11.静态高级实战/README.md)，在已 Patch 汇编的 MOD 客户端中，利用 `inventory_extra.json` 在本地客户端强行合并全卡牌与全英雄，免氪金显示并试玩全套卡牌。

### 2. 官方正版客户端调试（关卡预置法）
若使用的是官方正版客户端或不想修改全局存档，最稳妥的方法是参考 [09. 关卡修改](../09.关卡修改/README.md)，在自定义关卡 JSON 的 `PlayerConfig.Cards` 或 `LaneEntries` 中直接预置目标卡牌，进入单机关卡即可直接测试！

## 三、 联机安全与防封号提醒

> [!CAUTION]
> **联机安全与防封号警告**：
> 1. **单机专用**：本地全卡牌解锁或测试 MOD，仅限在**单机战役、人机对战与离线 Mod 测试**中使用。
> 2. **服务器校验**：联机天梯匹配（Multiplayer）时，EA 服务器会在对局开始前严格校验玩家提交的卡组合法性（检查职业匹配、40 张总数限制及单卡 4 张限制）。
> 3. **封号风险**：篡改卡组或强制携带非法卡牌加入联机匹配，会导致服务器校验失败拒绝连接，甚至引发账号永久封禁。
