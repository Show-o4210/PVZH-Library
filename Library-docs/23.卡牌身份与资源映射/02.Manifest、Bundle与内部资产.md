# 02. Manifest、Bundle与内部资产

本页用当前11064清单的离线快照说明查找关系。快照与当时设备文件已做哈希核对；这不是重新连接设备测试。

## 1. 从逻辑资源路径查表

卡牌视图使用prefabName拼接不同用途的路径。当前清单中的完整路径形态为：

```text
Assets/Ship/Prefabs/Cards/<prefabName>
Assets/Ship/Cards/GeneratedSprites/InHand/<prefabName>
Assets/Ship/Cards/GeneratedSprites/InCollection/<prefabName>
```

清单路径键不一定带扩展名。`BundleNamesByAssetPath[path]`给出`Bn`和`Ex`，再以Bn查`BundleNameToDetails[Bn]`取得`Version`、`Size`和`Dependencies`。不要自行给清单键添加`.png`后再宣称查不到。

示意结构，省略其他项目及真实依赖内容：

```json
{
  "BundleNamesByAssetPath": {
    "Assets/Ship/Prefabs/Cards/Weenie_Beanie": {
      "Ex": ".prefab",
      "Bn": "autotagged/9b6d7cdb899396e4db4c003f44f19375"
    }
  },
  "BundleNameToDetails": {
    "autotagged/9b6d7cdb899396e4db4c003f44f19375": {
      "Version": 1,
      "Size": 24885
    }
  }
}
```

## 2. Bn加版本确定磁盘文件

以缓存Bundle根目录为起点，当前关系是`<Bn>_<Version>`，目录前缀必须保留：

```text
files/cache/bundles/files/
  autotagged/9b6d7cdb899396e4db4c003f44f19375_1
  atlastagged/cardfaces_smarty_1
```

索引里的`TEXTURE_NAME`常是某个包文件的最后一段名称，不是Unity `Texture2D`对象名的通用同义词。不要丢掉`autotagged/`或`atlastagged/`后只按basename匹配，也不要据32位十六进制外观猜UUID→包名的哈希算法。本轮验证的是**查表关系**，没有验证包名的生成算法。

## 3. 卡图、战场单位和图鉴可以分包

当前11064样例：

| 卡 | 用途 | Bn | Version |
|---|---|---|---|
| 小豆丁，prefabName=`Weenie_Beanie` | Prefab | `autotagged/9b6d7cdb899396e4db4c003f44f19375` | 1 |
| 小豆丁 | InHand | 同上 | 1 |
| 小豆丁 | InCollection | `atlastagged/cardfaces_smarty` | 1 |
| 鳄梨，prefabName=`2f9fa005-8b50-4d1a-89be-38e4a82036c4` | Prefab | `autotagged/2ceeb890a69397041ba1fd559056c358` | 1 |
| 鳄梨 | InHand | 同上 | 1 |
| 鳄梨 | InCollection | `atlastagged/cardfaces_guardian` | 1 |

这两张卡的Prefab与手牌图共用单卡包，图鉴指向职业合图；不能据此断言所有卡都这样。查询三条实际映射比一个TEXTURE_NAME字段更可靠。

包中还存在Prefab、Sprite、Texture2D、材质、动画等对象与引用。Sprite可以引用Texture2D图集的一块区域；Prefab引用更多组件和依赖。只复制一张PNG、只改外部文件名或只找到一个Texture2D，均不等于整条资产链完整。

## 4. 找到包以后还要找到包内资产

原版`AssetBundlePathProvider`有三个相关入口：

| 方法 | 作用 |
|---|---|
| `IsAssetBundled` | 判断请求路径是否属于Bundle资源 |
| `AssetPathToBundleName` | 解析请求所在Bundle |
| `AssetPathToUsableAssetName` | 解析供包内加载使用的资产名 |

如果只把新卡请求指向原版Bn，内部仍请求不存在的“新卡别名.prefab/png”，包能打开也可能找不到资产。R9在上述三个入口一致替换路径，再交给原版解析，因此Bundle和内部资产名都来自同一原版条目，依赖仍沿原版清单加载。

原版RVA、方法ABI和对象布局绑定具体二进制。本章记录方法名和关系，不提供可跨版本照抄的地址。

## 5. Manifest版本与每个Bundle版本是两层数字

当时设备的目录为：

```text
files/cache/manifest/manifest_version                 # 内容：11064
files/cache/manifest/UnityABVersion_11064/AssetPathsManifest
files/cache/manifest/UnityABVersion_11064/AssetPathsManifest.bin
```

`11064`标识清单版本，不意味着所有Bundle都以`_11064`结尾。该清单实际读取：

| 逻辑资源族 | 当时磁盘文件 |
|---|---|
| `cards/card_data` | `cards/card_data_1` |
| `loc/cn` | `loc/cn_9` |
| `data_assets` | `data_assets_36` |

APK文件名里的内置资源11056、旧参考11047、旧Mod里的`cn_8/data_assets_29`都不能替代设备当前清单。版本迁移应由逻辑资源族映射到当前目标，不能选磁盘数字最大的文件，也不能只改一个Bundle的文件名就假定内部兼容。

## 6. JSON与bin：哪些已经验证

用户提供的旧笔记把JSON/bin加载优先级及删除bin列为探索建议。R9只采用其中的资源寻址线索，另核对当前清单和原版方法；**未验证bin优先级、JSON回退行为、bin编码或删除bin的后果**。

本轮没有修改这两份清单文件，前后SHA256一致，见[摘要](验收摘要.json)。因此新增GUID复用既有美术的成功，不依赖“删bin后JSON必然生效”的假设。若将来真正新增资源，需要另外验证路径映射、包详情、内部资产、依赖和加载/下载行为；不能把本次复用结果当作新增美术已经完成。
