# 02. 底层 JSON 组件结构

在 PVZH 的数据架构中，每张卡牌的核心战斗逻辑是由挂载在 `entity.components` 数组中的各种 C# 组件（Component）决定的。这种设计模式类似于 ECS（实体组件系统），卡牌是一个实体（Entity），具体的攻防、费用、护甲、死亡判定等行为通过挂载不同的组件来定义。

---

## 一、 组件的基本 JSON 声明规范

在 `components` 数组中，每一个组件对象都由标准的两个字段组成：
- `$type`: 组件的 C# 全限定类名与程序集说明。
- `$data`: 该组件所需的初始化参数和内部数据结构。

```json
{
  "$type": "PvZCards.Engine.Components.AttackComponent, EngineLib, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null",
  "$data": {
    "AttackValue": {
      "BaseValue": 3
    }
  }
}
```

> [!IMPORTANT]
> **程序集说明不可省略**！必须包含 `, EngineLib, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null` 后缀，否则 Unity 引擎的反序列化器无法找到对应的 C# 类，会导致游戏加载或出牌时直接 Crash。

---

## 二、 核心必需组件解析

几乎所有标准随从或卡牌都必须挂载以下基础组件：

### 1. `CardComponent`（卡牌唯一标识）
挂载卡牌的底层 GUID，与外层字典键匹配。
```json
{
  "$type": "PvZCards.Engine.Components.CardComponent, EngineLib, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null",
  "$data": {
    "Guid": 900000001
  }
}
```

### 2. `SunCostComponent`（阳光/脑力费用组件）
定义卡牌在战斗时的实际出牌费用。
```json
{
  "$type": "PvZCards.Engine.Components.SunCostComponent, EngineLib, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null",
  "$data": {
    "SunCostValue": {
      "BaseValue": 2
    }
  }
}
```

### 3. `AttackComponent`（攻击力组件）
定义随从的基础攻击力。非随从卡（如法术卡、环境卡）通常不挂载此组件。
```json
{
  "$type": "PvZCards.Engine.Components.AttackComponent, EngineLib, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null",
  "$data": {
    "AttackValue": {
      "BaseValue": 2
    }
  }
}
```

### 4. `HealthComponent`（生命值组件）
定义随从的基础生命值。
```json
{
  "$type": "PvZCards.Engine.Components.HealthComponent, EngineLib, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null",
  "$data": {
    "HealthValue": {
      "BaseValue": 3
    }
  }
}
```

### 5. `RarityComponent`（底层稀有度组件）
在底层用枚举标识卡牌的稀有度。
```json
{
  "$type": "PvZCards.Engine.Components.RarityComponent, EngineLib, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null",
  "$data": {
    "Value": "R4"
  }
}
```
*常见的 `Value` 值：`R0` (Token/基础), `R1` (Common), `R2` (Uncommon), `R3` (Rare), `R4` (SuperRare/Event), `R5` (Legendary)。*

---

## 三、 独立能力组件 (Standalone Component Abilities)

除了基础属性外，绝大部分常见的常驻关键字能力，都是通过直接挂载专门的能力组件实现的：

| 组件名称 (`$type` 短名) | 对应能力 | `$data` 字段结构与示例 |
| :--- | :--- | :--- |
| **TeamupComponent** | 团队协作 (Team-Up) | `"$data": {}` |
| **ArmorComponent** | 护甲 (Armor) | `"$data": {"ArmorValue": {"BaseValue": 1}}` |
| **SplashDamageComponent** | 溅射伤害 (Splash Damage) | `"$data": {"SplashDamageValue": {"BaseValue": 2}}` |
| **UntrickableComponent** | 无法成为法术目标 (Untrickable) | `"$data": {}` |
| **StrikethroughComponent** | 贯穿 (Strikethrough) | `"$data": {}` |
| **DeadlyComponent** | 致命 (Deadly) | `"$data": {}` |
| **FrenzyComponent** | 狂暴 (Frenzy) | `"$data": {}` |
| **TruestrikeComponent** | 无视盾牌 (Bullseye/Truestrike) | `"$data": {}` |
| **AquaticComponent** | 水生 (Amphibious/Aquatic) | `"$data": {}` |
| **MultishotComponent** | 多重射击 / 两路射击 | `"$data": {}` |
| **AttacksInAllLanesComponent** | 攻击所有路线 | `"$data": {}` |
| **PlaysFaceDownComponent** | 盖牌/墓碑/隐匿登场 | `"$data": {}` |

### 示例：带护甲 1 与贯穿能力的随从组件列表片段
```json
"components": [
  {"$type": "PvZCards.Engine.Components.CardComponent, EngineLib...", "$data": {"Guid": 900000001}},
  {"$type": "PvZCards.Engine.Components.SunCostComponent, EngineLib...", "$data": {"SunCostValue": {"BaseValue": 3}}},
  {"$type": "PvZCards.Engine.Components.AttackComponent, EngineLib...", "$data": {"AttackValue": {"BaseValue": 3}}},
  {"$type": "PvZCards.Engine.Components.HealthComponent, EngineLib...", "$data": {"HealthValue": {"BaseValue": 4}}},
  {"$type": "PvZCards.Engine.Components.RarityComponent, EngineLib...", "$data": {"Value": "R3"}},
  {"$type": "PvZCards.Engine.Components.ArmorComponent, EngineLib...", "$data": {"ArmorValue": {"BaseValue": 1}}},
  {"$type": "PvZCards.Engine.Components.StrikethroughComponent, EngineLib...", "$data": {}}
]
```

## 四、 计数器组件 (Counters)

某些卡牌或特殊效果需要在实体上记录持续状态或计数器（如 Buff 叠加层数、回合数限制等）。在底层中通过 `CountersComponent` 实现：

```json
{
  "$type": "PvZCards.Engine.Components.CountersComponent, EngineLib, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null",
  "$data": {
    "Counters": {
      "IsPersistent": true,
      "Counters": [
        {
          "SourceId": -1,
          "Duration": 0,
          "Value": 1
        }
      ]
    }
  }
}
```

## 五、 修改避坑提示与常见错误

> [!WARNING]
> 1. **内外层数值不同步**：
>    在修改随从面板时，切记**内层组件与外层 display 必须一并更新**。若只改内层不改外层，手牌面板显示原数值但上场变新数值；若只改外层不改内层，手牌显示新数值但上场实际仍为旧数值。
> 2. **语法缺失与类型错拼**：
>    JSON 中的组件类型字符串区分大小写，且程序集后缀中的空格与标点必须与标准模板保持一致。
> 3. **挂载冲突与缺少必要组件**：
>    若将随从卡的 `HealthComponent` 误删，随从在进入战场后会被引擎判定为 0 血并立即销毁。
