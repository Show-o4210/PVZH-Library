# 03. 显隐规则与异常排查

## 一、显隐必须同时考虑四条通道

idle 没有写某节点，并不代表该节点默认可见。正确处理方式是先保留 prefab 默认值，再用动画首帧中明确存在的曲线覆盖：

1. 检查节点及所有父节点的 `GameObject.m_IsActive`；
2. 检查 `SpriteRenderer.m_Enabled`；
3. 动画将 Sprite PPtr 设为 null 时，隐藏该 Renderer；
4. 同时应用 Renderer 颜色和动画 alpha。

遗漏这些规则会把正常、受伤、严重受伤、攻击、死亡、眨眼替换和粒子特效层叠在一起。研究中修复显隐后，成长蘑菇由 11 个错误叠加层降为 5 个正常层，坚果墙由 11 层降为 8 层。

## 二、跨 CAB 引用缺失

典型错误：

```text
File cab-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx not found
```

这表示目标 Bundle 引用了其他包中的公共资源。确认 `cab_index.json` 包含该 CAB 名称，并且映射的实际文件存在于 `--bundles` 指定目录。完整示例会加载目标包的直接依赖；若资源存在更深的间接依赖，仍可能需要扩展为递归加载。

## 三、角色缺头、缺脸或缺阴影

优先检查：

- 是否加载了公共依赖包；
- 缺失 Sprite 的 PPtr 是否能在依赖中解析；
- 该节点在 idle 第一帧是否被故意设为 null 或 inactive；
- 缺少的是否只是跨包通用特效，而非角色主体。

不要因为一项引用缺失就把包内所有 SpriteRenderer 都纳入输出，这会引入无关 prefab。

## 四、图层遮挡错误

完整示例综合 `SortingLayerID`、`SortingOrder` 与 Transform 世界 Z 排序。若个别对象仍有误，应对照游戏实际 Shader、Sorting Group 或自定义渲染逻辑；简单按对象遍历顺序或 Sprite 名称排序并不可靠。

## 五、画布异常巨大

脚本对总像素数设置了上限。类似错误：

```text
ValueError: invalid output dimensions: 385253x102314
```

通常说明选错动画、包含了本应隐藏的远距离辅助节点，或目标本来就是使用非角色尺度的环境对象。不要直接删除上限，应先记录各图层边界、节点路径和动画覆盖值，定位异常层。

## 六、已知特殊项

在 578 条有效研究样本中，以下 6 项没有由通用流程生成：

| 项目 | 原因 |
| :--- | :--- |
| 精准轰击 | 没有 idle 动画。 |
| 山羊 | 没有 idle 动画。 |
| 焕发活力 | UUID 根节点不匹配。 |
| 全蚀 | idle 坐标导致画布异常。 |
| 成对豌豆天堂 | idle 坐标导致画布异常。 |
| 黑洞 | idle 第一帧没有本地可见图层。 |

这些记录是特定资源版本下的实测结果。游戏资源更新后应重新验证，不应永久硬编码为跳过名单。

## 七、维护检查表

1. 更新 `autotagged/` 与 `index_new.json`；
2. 资源集合变化后重建 `cab_index.json`；
3. 用 `--limit` 跑小样本；
4. 抽查跨包角色、成长/受伤分层角色与复杂多部件角色；
5. 全量运行并检查报告中的所有非 `ok` 状态；
6. 单独研究特殊项，不以扩大画布或忽略异常代替修复；
7. 发布脚本时记录 Python 与依赖版本，避免 UnityPy 行为变化造成结果漂移。
