# 01. 从 Unity 部件到完整角色

## 一、为什么导出 Texture2D 还不够

一个 PVZH 角色通常被拆成头、身体、眼睛、手臂、武器等部件。各类对象的职责如下：

| 对象 | 在拼接中的作用 |
| :--- | :--- |
| `Texture2D` | 保存像素数据，可能是一张独立图片，也可能是图集。 |
| `Sprite` | 指定图集裁剪区、packing rotation、pivot 与 Pixels Per Unit。 |
| `SpriteRenderer` | 引用 Sprite，并保存颜色、翻转、启用状态和渲染顺序。 |
| `Transform` | 保存部件相对父节点的位移、旋转、缩放与 Z 坐标。 |
| `GameObject` | 组成 prefab 层级，并通过 `m_IsActive` 控制整条子树的显隐。 |
| `AnimationClip` | 在特定时刻覆盖 Transform、Sprite、active、enabled 或 alpha。 |

因此，直接导出 `Texture2D` 只能得到素材，不能得到完整角色布局。脚本使用 UnityPy 的 `sprite.image`，让图集裁剪、打包旋转和压缩贴图由 UnityPy 统一处理。

## 二、只处理目标 prefab

一个 AssetBundle 可能同时含有角色 prefab、卡牌头像、阴影、特效和音频。完整脚本从 `index_new.json` 读取 `UUID`，查找同名 `GameObject`，再只收集该根节点后代中的 `SpriteRenderer`。

若包中出现重名嵌套节点，优先选择层级最高的匹配对象。这样不会把同包内的其他 prefab 或预览素材混入结果。

## 三、为什么采用 idle 第一帧

prefab 的序列化状态不保证是一张可展示的完整立绘。它可能保留多个状态层，而 Animator 在运行时才会关闭不需要的节点并切换正确 Sprite。

脚本选择动画时遵循以下顺序：

1. 找到角色根节点上的 `Animator`；
2. 优先读取 `AnimatorOverrideController` 中名称含 idle 的 override clip；
3. 其次采用原始 controller 中的 idle；
4. 最后才在已加载环境中按名称回退查找；
5. 普通 `_idle` 优先于 `attack_idle`、`special_idle`、`damage_idle` 等特殊状态。

动画绑定用相对 prefab 根节点的路径 CRC32 标识节点。脚本遍历层级计算 CRC32，再把 `m_MuscleClip.m_ValueArrayDelta[].m_Start` 按 `m_ClipBindingConstant` 的顺序映射到首帧属性。这里不需要对整段动画进行插值。

## 四、坐标变换

局部二维矩阵由缩放、四元数的 Z 轴旋转和位移构成，沿父级链相乘得到世界矩阵：

```text
WorldMatrix = ParentWorldMatrix × LocalMatrix
```

Sprite 像素坐标还要经过 pivot 与 PPU 换算。Unity 的 Y 轴向上，而 PNG、Pillow 和 OpenCV 的 Y 轴向下，因此转换矩阵必须翻转 Y 轴。

所有可见图层变换后的四角共同决定画布边界。渲染时先画远处/低排序图层，再以 RGBA Alpha Composite 叠加靠前图层，最终保留透明背景。

## 五、最小示例的适用边界

[rebuild_sprite.py](examples/rebuild_sprite.py) 展示了单个自包含 Bundle 的基本拼接方式，便于理解矩阵和合成过程，但它有意省略了：

- prefab 根节点筛选；
- idle 动画首帧；
- active、enabled、alpha 和 null Sprite 动画；
- 跨 CAB 依赖；
- 批量异常报告。

它适合学习和验证简单资源，不适合直接替代完整批处理脚本。
