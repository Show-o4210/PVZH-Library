# 10. 全场变形保留当前攻血与原生子效果

本节归档2026-10-24的 **Android启动器 R25 pharaoh RC5**：招笑版“不死法老”将其他场上植物变成豌豆射手、僵尸变成普通僵尸，并保留每个目标变形前的当前攻血。它与[第07节](../07.第四批组合动作与攻击后扩展/README.md)的历史mod2-runtime R25是不同候选，版本号相同不能混用。

先读[原实现记录](R25法老实现记录.md)和[字段筛选验收摘要](法老技能验收摘要.json)；执行者走[Agent21](../../../agents/21-pharaoh-transform-and-child-effects.md)。本节只整理已有材料，没有重新调用设备或API，不包含完整运行时、APK、Bundle、WAV或账户备份。

## 先固定“保留”的语义

不死法老为GUID201，6费4攻6血、装甲1，原英雄最低生命1能力在Mod中移除。自身不变；英雄、手牌、牌库、环境不作为变形目标。植物目标为GUID10，僵尸目标为GUID50。后者不能误写成小鬼28。

“攻防相等”经用户确认表示**每个目标变形前后的当前攻击力与当前生命分别相等**。例如7攻、最大13血、已伤3，变形后为7攻10血、伤害记录0；不是7攻7血，不是保留最大13血，也不是再施加3点旧伤害。阵营、owner、lane沿用原生变形路径；费用、种族、词条、原技能等采用目标定义。双组队、水路、零攻、受伤与墓碑均应单独核对，不能只看GUID变了。

## 1026是有条件的私有运行能力

`pvzh.rule.transform_others_keep_current_stats` version1使用私有规则1026，绑定当前匹配Base、原Grant分派和`r25-capabilities-1`。它受扩展许可、原版模式和模型守卫控制；登记为运行支持、AI自由配方未开放。公开Python v1合同没有因此新增通用1026配方，其他项目也不能直接复制规则号或RVA。

一次真实自身PlayTrigger启动后，先对所有其他有效场上单位做同一批快照，再按目标逐个走原生TransformSystem。这样前面单位移除旧光环，不会改变后面目标应保留的原始攻血。不要把逐目标“读取→变形”当作同一快照。

## 为什么原生子效果会被取消

RC1沿用旧descriptor的EffectEntityId，子效果进入原EffectEntityValidator后会重新验证原PlayTrigger；只设`RequiresTargetValidation=false`仍会被静默取消。队列跑完、接口未报错、音乐启动都不能证明变形执行。

本例自行快照并核对目标，续接绑定真实effect指针、当前model和generation。新子效果使用`EffectEntityId=-1`与`RequiresTargetValidation=false`，SourceId、SpringboardId继续是真实法老。这个窄合同只用于已自行验证的本批子效果，不是关闭整个游戏验证器的通用修复；外层许可、已知规则、实体容器和当前模型归属仍必须检查。

## 指定卡与随机卡池不同

RC3经Subset Finder找普通僵尸50时，被原版强制`NotCheats`筛掉。目标定义中的cheats标签是原数据事实，不能为了这张卡全局删除标签，也不能改其他随机卡池的筛选语义。

RC4改用原EffectRouter所持handler委托定位真实TransformSystem，并核对其Entities属于当前模型，再调用指定GUID的CreateCard路径。它保留原生重置、位置、owner和TransformedCard记录；没有另造System、只写GUID或新增Hook。原版豌豆10和普通僵尸50定义均保持。

## 连续Buff要等实际结算边界

目标变形后，环境和光环会重新施加连续修正。RC4先恢复快照数值，再等原生连续组结算，曾把5/11再次加为10/16。基础场景52项通过不能覆盖这个反例。

RC5复用已有router owner观察真实`ContinuousEffectsCompleteEffect`，核对同一router/model后，按已经生效的修正做**一次**补偿。负生命环境还可能在这个窗口暂时把原本应保留1HP的单位压成0HP，因此在原CheckDeath之前对已绑定的本次正生命快照做窄保护；完成后立即解除观察。负环境实测确有1次保护，后续Buff和真正致命伤仍按原生结算，没有把属性长期钉在快照值，也没有全局取消死亡或递归泵队列。

## 音乐复用与表现边界

音乐独立复用已有1024能力：当前Mod登记`liukun_theme`，namespace=mod2，slot=8952476。用户WAV为48kHz双声道16bit PCM、111.513583秒，原SHA及21,410,756字节保持；本库只存元数据。流程为临时静音原音乐RTPC、播放登记的本地MediaPlayer曲目，继续尊重游戏音乐偏好。音乐生命周期与原版隔离见[第09节](../09.本地背景音乐与共享生命周期/README.md)。

本轮真实后端isPlaying、111514ms时长、进度推进与RTPC0有证据；系统媒体音量前后0，未提高手机音量，**没有人工听验或录音波形验收**。没有降低画质或修改系统音质。原生变形模型、记录与队列通过，也不等于已逐帧看过专属动画。
