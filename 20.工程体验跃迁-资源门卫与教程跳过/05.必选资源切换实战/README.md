# 05. 必选资源切换实战：原版与mod2

第20章前四篇主要讨论全量内置资源与FTUE。本节补充R19的另一个需求：保留这些能力，同时在每次冷启动时明确选择原版或改版，切换对应缓存后才加载Unity。

| 文档 | 内容 |
|---|---|
| [必选资源界面](resource-selector.md) | schema1清单、双模式、三文件白名单、暂存／备份／事务恢复、选择收据、显式测试Intent |
| [界面与交付验收](gate-acceptance.md) | 无跳过选项、Back不入游戏、Unity未加载、原版／mod2真实缓存校验 |
| [候选包构建](packaging.md) | B4差异白名单、唯一revision、完整有效载荷散列、签名与zipalign、构建和设备结果分离 |

三文件为 `cards/card_data_1`、`data_assets_29`、`loc/cn_8`，路径在实际外部缓存根下解析；不要从清单接受任意写入路径。每个rename原子，不等于三个文件整体天然原子；整体一致性靠事务记录、备份、回滚和最后提交收据保证。

`profile_revision=4` 是R19资源内容版本，`schema=1` 是清单结构版本，二者不可混为一谈。运行时读取实际选择收据，original模式必须关闭新增规则；只验证“安装了同一个APK”不足以证明使用了哪份缓存。

活动Unity已经加载卡定义后不能只换磁盘文件继续用旧进程。R19仅支持冷启动选择。测试Intent显式请求原生按钮并走同一校验／事务流程，普通启动仍必须由用户选择；它不是永久跳过开关。

本次只归档文档，没有重装APK、连接设备或重做签名。R19原始8项交付检查的摘要见[第21章证据索引](../../21.语义调试与技能扩展实战/06.R19实现与验收记录/证据索引.json)，完整测试边界与已知建局异常见[第21章](../../21.语义调试与技能扩展实战/README.md)。所有“手机停在界面”的描述都指2026-10-14交付当时，不表示本次归档重新检查了当前设备。
