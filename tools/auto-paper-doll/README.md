# Unity 纸片人资源重构工具

这是从原桌面 `pvzh工具包/auto` 整理进入 Library 的 **v2.6 离线实验工具**。它将既有角色的 Unity AssetBundle 与一张 PNG 配对，注入单图纸片人节点并重定向动画；在输入包含相应手牌贴图时，也会尝试替换手牌贴图。它不是手机工作台的功能，也不负责给新 GUID 卡牌注册独立美术。

> **当前状态：实验原型，未通过完整引用验证。** 历史样本的原工具自检通过，但另一次独立静态检查在输出中发现预加载表 79 处及容器 22 处引用指向已删除对象（总计 101 处），输入样本为 0。该结果不单独证明游戏会崩溃，但也不能把原工具自检视作完整 Bundle 有效性或实机通过。请只在隔离副本上研究，不要直接用于用户 Mod、正式分发或覆盖游戏资源。

## 内容

| 文件或目录 | 作用 |
| --- | --- |
| `auto.py`、`main.py` | 启动入口与重构流程 |
| `pairing.py`、`tasks.py`、`progress.py` | 输入配对、任务状态和运行记录 |
| `scanner.py`、`cleaner.py`、`injector.py`、`sprite_mesh.py` | 解析和调整 Bundle 对象、注入角色节点 |
| `animator.py`、`dump_parser.py` | 读取动画 Dump 并重定向动画 |
| `validator.py` | 原工具的限定范围回读检查；不覆盖上述完整引用缺口 |
| `3_templates/` | 五件套序列化模板：Sprite、Texture2D、GameObject、Transform、SpriteRenderer |
| `4_animations/` | 原项目提供的 7 类对齐动画 Dump |

本目录保留原项目提供的模板结构和动画数据；纹理模板 `1002.dat` 内原有的旧图片已替换为透明占位，运行时由用户输入的 PNG 替换。模板和动画的来源与再分发许可尚无单独说明，游戏资源及第三方素材不因随工具提供而获得授权。原始 Bundle、示例图片、历史输出、任务状态和缓存未收入仓库；用户需要自行提供有权使用的输入。

## 环境与使用

历史只读检查使用 Python 3.14、UnityPy 1.25.0 和 Pillow 12.2.0。`requirements.txt` 固定了当时检查到的依赖版本，不代表所有游戏版本或操作系统已兼容。

2026-11-02 整理时，在临时目录用同一个原版输入样本和程序生成的测试 PNG 分别运行原模板及透明模板，两次生成的 Bundle SHA256 完全一致，原工具限定回读检查均通过。此对照只验证替换模板图片没有改变该样本的处理结果；并未修复或重新判定上面的完整引用问题，也未进行 Android 或游戏验证。

```bash
cd tools/auto-paper-doll
python -m pip install -r requirements.txt
python auto.py
```

运行入口会在工具目录创建缺失的工作目录：

- `1_input_bundles/`：自行提供的原始角色 Bundle。
- `2_new_skins/`：自行提供的 PNG；原项目以 1024×1024 图像和固定模板为主要使用场景。
- `5_output_bundles/`：输出 Bundle 和原工具的检查报告。
- `tasks.json` 和 `progress.md`：程序自动生成或更新的本地任务状态和运行记录。

这些输入、输出和运行状态都由本目录 `.gitignore` 排除。脚本默认对文件名排序后盲配，运行时会直接处理待执行任务；运行前应核对并备份输入，避免一次放入多组难以辨认的文件。修改素材、参数、代码或模板后，旧的 `completed` 状态不会自动基于内容变化失效，不能将跳过视为重新生成或重新验证。`config.py` 和 `tasks.json` 中可配置 PPU、垂直偏移等参数。

## 边界与后续改进

- 默认流程同时处理战场纸片人和可识别的手牌贴图；并非独立的“只换卡图”模式。收藏／牌组编辑器的 atlas 等资源不保证随之更新。
- 固定模板 PathID 1001–1005、动画和文件顺序配对都需要对具体输入校验。后续应增加 PathID 冲突检查、明确的卡牌／资源／图片映射和任务内容指纹。
- 历史单个样本由 278,829 字节增至 4,865,681 字节；这只是该样本的观察，其他输入仍需分别测量。输出资源的完整引用图、加载、画面、动画、手牌及收藏页应分别验证。
- 替换共用的原版资源可能同时影响原卡和使用同一模板的新卡。新卡独立美术还需要单独设计资源身份、路径及注册，不能将本工具的输出直接视为已支持。

项目背景和手工结构见 [纸片人技术指南](../../Library-docs/历史教程/Unity_2D_AssetBundle_Modding_Guide.md)；从骨骼部件生成静态透明 PNG 的不同流程见[贴图资源拼接](../../Library-docs/13.贴图资源拼接/README.md)。
