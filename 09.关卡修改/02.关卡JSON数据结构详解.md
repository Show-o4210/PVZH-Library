# 02. 关卡 JSON 数据结构详解

关卡在底包中以标准的 JSON 文本存在。理解关卡 JSON 的核心字段，是手工修改与使用关卡编辑器的核心。

---

## 一、 基础属性与规则开关

```json
{
  "Id": "plant_hero_solar_flare_01",
  "OpponentElo": 1000,
  "MustPlayAllPlayableCards": false,
  "DisableSurprisePhase": false,
  "EnableReadySetPlant": true,
  "SkipHeroSelect": true
}
```

| 字段名 | 类型 | 含义说明 | 常用场景 |
| :--- | :---: | :--- | :--- |
| **`Id`** | `string` | 关卡唯一标识符 | 必须与 `TextAsset` 的资源节点名完全匹配。 |
| **`OpponentElo`** | `int` | 人机 AI 出牌智商与难度 | 数值越高 AI 决策越聪明。 |
| **`MustPlayAllPlayableCards`** | `bool` | 是否强制出完所有手牌 | 常用于解密挑战（Puzzle Party）。 |
| **`DisableSurprisePhase`** | `bool` | 是否禁用僵尸墓碑奇袭阶段 | 用于教学关或特殊限制模式。 |
| **`SkipHeroSelect`** | `bool` | 是否跳过英雄选择直接开局 | 剧情关卡固定英雄时开启。 |

## 二、 角色配置 (`OpponentConfig` 与 `PlayerConfig`)

人机（`OpponentConfig`）与玩家（`PlayerConfig`）拥有完全对称的属性配置结构：

### 1. `Parameters` 基础角色参数
```json
"Parameters": {
  "Faction": 0,
  "StartingHandCount": 4,
  "MaxHealth": 20,
  "StartingSun": 1,
  "ShuffleDeck": true
}
```
- `Faction`: 归属阵营（`0` 代表植物，`1` 代表僵尸）。
- `MaxHealth`: 英雄初始血量上限（常用于制作残局解密或 BOSS 战高血量模式）。
- `StartingSun`: 第 1 回合初始阳光/脑力费用。

### 2. 护盾概率权重表 (`SuperBlockTable`)

> [!IMPORTANT]
> **护盾概率校验铁律**：
> `SuperBlockTable.TableEntries` 数组中记录了每次触发护盾格数（1格、2格或3格）的随机权重 `RngWeight`。
> **所有 `RngWeight` 的数值之和必须严格等于 100！** 若权重和不等于 100，关卡加载时会触发算术异常导致崩溃。

```json
"SuperBlockTable": {
  "TableEntries": [
    { "RngWeight": 33, "Blocks": 1 },
    { "RngWeight": 33, "Blocks": 2 },
    { "RngWeight": 34, "Blocks": 3 }
  ]
}
```

## 三、 战场与 5 路地形配置 (`BoardConfig`)

定义对局战斗场景、5 条路线的地形类别以及开局预置在场上的单位：

```json
"BoardConfig": {
  "PlantsBoardName": "Board_Suburbs",
  "LaneEntries": [
    { "LaneType": 0, "Cards": [] },
    { "LaneType": 1, "Cards": [900000001] },
    { "LaneType": 1, "Cards": [] },
    { "LaneType": 1, "Cards": [] },
    { "LaneType": 2, "Cards": [] }
  ]
}
```

### 1. 地形分类 (`LaneType`)
- **`0`**：高地 / 屋顶地形 (Highground)
- **`1`**：平地 / 地面地形 (Ground)
- **`2`**：水路地形 (Water)

### 2. 预置场上单位 (`Cards`)
可在对应的 `Cards` 数组中填入卡牌的 GUID。开局时，引擎会自动将对应的植物/僵尸随从或环境放置在该路线的战场上！
