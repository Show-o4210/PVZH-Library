# 03. 剧情与解密发牌事件配置

PVZH 的剧情对话、调牌顶及部分脚本出牌由关卡JSON中的 **`GameEvents`** 驱动；它们与抽牌、AI动作选择及阶段系统配合，不应把列表中的每条事件都理解为立即执行的动作。

本篇详细解析 4 大常用游戏事件节点。

> 2026-10-25更正：旧版的Engine.Config类型串、MessageLocKey／Speaker、Add事件的CardGuid／TargetPlayer、Scripted事件的TurnIndex及顶层CardGuid均不适用于当前核对底稿。以下改用实际原生字段，示例只是结构摘录。程序应克隆当前事件并改目标参数，AI不输出完整关卡或替换整份GameEvents。当前范围、指纹、调用方式和实测状态见[索引](INDEX.md)。

---

## 一、 游戏事件 (`GameEvents`) 结构

在关卡JSON中，`GameEvents`保存有序事件配置。排列顺序会被保留，但实际何时执行还取决于触发器、阶段和初始化流程，不能把拖动后的顺序当成所有机制的时序保证。

```json
"GameEvents": [
  {
    "TriggerConfig": {"Type": 1, "CardId": 280, "TurnNumber": 0, "RecordType": 7},
    "DismissConfig": {"Type": 0, "TimeToWait": 0.0},
    "ViewType": 2,
    "X": 0.0,
    "Y": 1.5,
    "TextKey": "Node_PVE_Soft_Node_Zombie_200:Mod1_Title",
    "Delay": 0.0,
    "MustTapThrough": true,
    "TelemetryEvent": 0,
    "Narrator": 2,
    "$type": "PvZCards.Core.Data.MessageEventConfig"
  }
]
```

## 二、 4 大常用游戏事件节点详解

### 1. 剧情对话事件 (`MessageEventConfig`)

上方为历史僵尸任务200改版的开场对话结构。示例`TextKey`必须与实际CN增量一起构建，不能仅复制一个不存在的键。

- **`TextKey`**：在当前CN的`LocalizedStrings`中唯一解析到中文正文；程序负责生成独立键、增量CSV写入及回读，保留原格式与引用。
- **`Narrator`**：原生枚举为0=None、1=Plants、2=Zombies；常见界面对应无、戴夫、僵王博士，不是任意英雄ID。
- **`TriggerConfig.Type`**：例如1=Turn；`TurnNumber`是该触发器的参数。完整枚举和使用时序需按同版本dump／样本核对。
- Turn触发还精确匹配`RecordType`：7=僵尸主阶段开始、8=植物主阶段开始、9=僵尸锦囊阶段开始、29=TurnStart、1=TurnStartComplete。示例7不是通用回合开始；Engine回合与History回合也不能未经验证直接混用，见[组件语义](06.组件语义与时序边界.md)。
- **`DismissConfig.Type`**：0=点击屏幕、1=下一次出牌、2=等待秒数、3=点击战斗按钮、4=手动结束。不同关闭方式还需与队列／`MustTapThrough`配合验证，不能只改一个字段便承诺不会阻塞。
- 本底稿400个正式任务中的268条对话都使用TurnNumber=0；存在不同ViewType及MustTapThrough配置。回合中对话、自动关闭与连续对话列入本轮专项实验，不能直接借开场样本宣称通过。

---

### 2. 新增到牌顶事件 (`AddCardToTopOfDeckConfig`)

原生配置指定要加入的卡牌列表与阵营，**没有TurnNumber字段**。它在初始化中相对洗牌、起手抽牌的顺序需要核对，不能解释成任意回合直接发到手牌。

```json
{
  "CardIds": [1],
  "PlayerFaction": 0,
  "$type": "PvZCards.Core.Data.AddCardToTopOfDeckConfig"
}
```
- **`CardIds`**：目标卡牌GUID数组；示例数字只是结构展示，必须按目标阵营与当前卡表选定，不能照抄当作推荐牌。
- **`PlayerFaction`**：接收阵营，0=植物、1=僵尸。
- 本次400正式任务没有该事件，其他原版关型存在样本；移植后的执行顺序属于待实测项。

---

### 3. 移动已有卡到牌顶 (`MoveCardToTopOfDeckConfig`)

```json
{
  "TurnNumber": 2,
  "CardGuid": 1,
  "PlayerFaction": 0,
  "$type": "PvZCards.Core.Data.MoveCardToTopOfDeckConfig"
}
```

该配置由系统调整牌库顺序，**不等于直接抽入手牌**。同版原生`OrderedCardPoolSorter.MoveToTop`查找第一份指定GUID，找到后移到索引0；不存在则不改动，不会凭空生成。是否在所写回合随后被正常抽到、回合0与起手的关系、同回合多个调牌事件的顺序，需要实机验证。

“确保获得指定牌”与“只移动已有牌”必须在意图和预览中区分。若牌库可能缺该牌，应明确调整本关牌组或另用已核实的新增机制，不能给Add事件杜撰回合字段，也不能把缺牌无变化写成成功发牌。

---

### 4. 人机脚本出牌事件 (`ScriptedTurnEventConfig`)

配置人机在某回合尝试执行的一组出牌。原生实现经过AI合法动作选择；这不是绕过手牌、资源、落点或目标限制的通用召唤命令。

```json
{
  "TurnNumber": 2,
  "Plays": [{"CardGuid": 1, "LaneIndex": 1}],
  "PlayDuringSurprise": false,
  "ContinuePlaying": true,
  "$type": "PvZCards.Core.Data.ScriptedTurnEventConfig"
}
```
- **`Plays`**：有序出牌列表，每项包含`CardGuid`与可选`LaneIndex`。保留原事件所有项，不能只读写第一项。
- **`LaneIndex`**：0～4表示五条路线。配置构造器未设-1，普通int默认0，初始化原样复制；省略不能被称作已证“任意路”。实际选择会优先匹配指定路，无匹配时可能回退其他有效动作，不能承诺绝对落点。
- **`TurnNumber`**：脚本回合参数。自然语言“第几回合”应由已验证的转换负责，不能让模型猜0／1基数。
- **`PlayDuringSurprise`／`ContinuePlaying`**：分别涉及锦囊阶段和脚本后继续行动；缺牌、费用不足、无落点、多牌部分成功等分支需专项验证。该配置没有任意目标实体字段，不能宣称可精确指定所有锦囊的目标。
- 全底稿有85条该事件，其中10条`Plays`超过一项；400正式任务没有现成样本。因此本轮先手工移植进正式任务验证，再决定工具对AI开放的承诺范围。
- 同回合／同阶段配置会合并Plays，最后一个ContinuePlaying覆盖该组的前值；脚本在查合法动作前即标Executed。完整静态依据及待测分支见[06](06.组件语义与时序边界.md)，不能假定每条数组事件是独立的强制执行块。
