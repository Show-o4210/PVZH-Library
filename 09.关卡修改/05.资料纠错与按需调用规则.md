# 关卡资料纠错与按需调用规则

本页随2026-10-25关卡专项维护新增，先读[统一索引](INDEX.md)。它规定资料如何被使用和维护，不宣称新的AI产品接口已发布。

## 从事实到模型资料

1. 确定当前资源赢家和版本。依据Manifest与选定Mod的实际输入，记录卡表、data_assets、CN的指纹，不能拿同名旧包替代。
2. 定位400任务内的唯一目标：阵营、1～200编号、补零内部ID、TextAsset名称、实际Faction及中文标题互相核对。
3. 先返回短概况：双方英雄／牌组引用、基础参数、地形、场景GUID和事件数量。只有相关内容才展开。
4. 按修改需求读取当前参数、完整相关事件、牌组内容、场景完整实体、目标卡定义和实际CN。规则或牌组是Mod已改版本时，不能把原版参考当当前事实。
5. 需要解释语义时再读精确节点、同版dump、原生调用摘要和范围匹配的实测案例。函数名／GUI标签只用于检索，不单独证明功能。
6. 生成短操作并由程序构建候选，回读比较真实差异，再进行关卡专用审查和用户采纳。模型说明不是候选事实，作者记录不是可信PASS。

## 操作边界

| 操作类别 | AI提交的意图参数 | 程序维护的内容 |
| --- | --- | --- |
| 参数 | 一方、字段、数字／布尔值 | 原字段存在性、类型／值域、未涉及字段 |
| 调牌顶 | 一方、回合、卡牌引用 | 原生事件壳、牌库依赖、缺牌提示、时序映射 |
| 脚本出牌 | 回合／阶段、卡牌列表、可选路线、继续行动选择 | 完整Plays数组、缺省字段、引用和合法性证据 |
| 对话 | 触发逻辑、说话方、内容、关闭方式 | 稳定事件定位、TextKey、CN转义／编码、完整原生字段 |
| 场景能力 | 触发、条件、目标、效果和数值 | 不可收藏场景外壳、GUID、关卡绑定、中文、三资源一致性 |

这些是操作分工，不是可直接提交的JSON schema。当前R30的旧levels[].changes不能因为本表出现而获得GameEvents／场景构建能力。实验或后续实现必须提供真实的参数清单与可定位错误，禁止让AI借“高级JSON”写整份关卡或执行任意代码。

## 当前本机实验调用

当前已存在`campaign_cli.py`实验控制端，位于本机工作区`pvzh-launcher/operations/campaign-lab-20261025/scripts/`，完整启动与参数说明在同实验目录`docs/CLI-USAGE.md`。它优先于直接手写整份case文件；模型未来也应把固定子命令／工具参数当操作界面，不需要看到或重写内部存储JSON。

| 步骤 | 已实现的操作 | 资料与结果 |
| --- | --- | --- |
| 找关卡 | `search --side zombie --mission 200`、`inspect plant 1 --section fields` | 严格限400任务，程序解析补零ID；分页读取fields/events等 |
| 建待审操作 | `--workspace local case create demo --side plant --mission 1` | 在实验cases/cli独立目录保存，不覆盖旧case |
| 设置标量 | `--workspace local set demo OpponentConfig.Parameters.InitialHealth 40` | 只改已有数字／布尔，字符串引用限已观察值；不是完整领域兼容性保证 |
| 事件 | `event add/list/update/remove` | add接收kind与小values；原事件更新／删除需index和SHA，新增事件需added序号和SHA，不能贴完整GameEvents／原生$type对象 |
| 场景 | `rule clone/bind` | 原场景外壳克隆，before守卫的数字／布尔变体和明确阵营；当前不是任意逻辑图构建器 |
| 构建 | `--workspace local build demo --revision first` | 新revision输出ZIP、SHA和真实Bundle差异；不部署，不覆盖旧产物 |

上表为实际子命令参数，运行还需使用本机已确认的Python和脚本绝对路径；公开Library不附本机实验工程。`--values`仅短参数对象，不是任意宿主脚本；接入AI时应提供固定命令对应的结构化工具，而非任意shell执行权。

前次2026-10-25实验来源固定R30原版底稿，不把它当作已适配任意当前Mod。24项真实CLI子进程检查（`cli-host-test-272b1569.json`）、构建器41项及独立35项为host离线通过；该轮未调用AI API、未接R30工作台。输出OFFLINE_PASS／NOT_TESTED不能变成正式任务运行通过。2026-10-26续做的真实API和正式002实机各有新收据，见本页末尾与统一索引，不能混写回旧检查点。

## 纠错依据

- [事实摘要](关卡事实核对-20261025.json)从R30实际11064底稿重新统计，保留SHA、400目标连续性、事件分布、非100权重反例和原版场景外壳标记；不包含完整游戏资源。
- 02篇的字段以当前底稿为准：InitialHealth、InitialSunCount、InitialCardsToDrawFromDeck、ShuffleDeckAtStartOfGame和ChargeAmount。
- 03篇的类型及字段交叉核对同版本`PvZCards.Core.Data`定义。MoveTop、Add、Scripted和Message的职责不同；缺少回合字段不能靠新增未知字段补齐。
- 原生调牌实现只支持“找到已有条目并移动到索引0”；抽牌阶段、起手、换牌和多事件先后仍需单独证据。原生脚本会挑选合法AI动作，不能据配置名保证必打。
- 2026-10-26正式002的Move正例已有独立69项：第二自然轮正常抽到移顶的已有牌，下一轮恢复原牌顶，总40张不变；这不是凭空加牌或直接给手牌。起手／换牌、敌方、缺牌和多事件顺序仍未由此覆盖，完整边界读[06组件语义](06.组件语义与时序边界.md)。
- 脚本缺首项且`ContinuePlaying=false`会走组收尾并结束阶段，不能许诺跳过缺牌继续后牌；true只允许外层自然AI策略。原case缺首牌两轮未出牌的功能预期保留FAIL，观察断言通过不替代原预期通过。初始手牌须实际核对，不把关闭洗牌理解为牌库头部必为起手。
- Message的RecordType／History触发与Engine模型／UI动画队列分别记录。record7消息可见不等于Engine行动前屏障，UI可落后于模型；判断脚本是否执行同时看单位、手牌、资源和阶段，不能只看对话框。自动关闭最终队列为空也不证明指定时间窗口已正确显示。
- 400正式任务没有Add或Scripted样本，268条对话均为Turn0。其他关型中的原生样本只能证明结构来源，不能自动证明移植到正式任务的时序。
- 桌面工具可帮助理解输入控件和序列化，但其固定模板、UI重建和导出限制不能作为新的领域硬规则。

## 如何防止重复犯错

- 索引里给每条已知错误一个明确的替代解释，并指向唯一的事实摘要；不要保留可复制的错误结构再只在页头轻描淡写地警告。
- 实验结果按原生／结构／fixture／正式任务／AI调用分层记录，保留失败及用户跳过。新“进游戏”不能覆盖旧精确结算未测。
- 新资料先补路由与依赖，再补正文；大文件拆成概况、字段、事件、场景和证据等主题，使用稳定ID和命名章节，而非每次机械全量投喂。
- R30现有工具缺关卡主动检索和读取，应在后续能力中补齐，不能让模型反复查卡牌知识来猜关卡ID。
- 回归包含普通表达：“僵尸任务200”“植物37关，对手200血”“第1关给对手加10血”。前两者不能选错阵营／编号，第三者仅在阵营不明时准确澄清。
- 成本统计以相同任务成功率、调用次数、输入／输出token和重复资料读取为准；减少无关全文，不删必要的逻辑或语义审查。
