# 09. 关卡修改

**从[关卡资料索引](INDEX.md)开始。** 2026-10-25起当前范围锁定植物／僵尸任务1～200；索引统一登记资料优先级、已纠错内容、工具限制与正式任务实验状态，避免反复从旧示例猜测。按需调用与维护规则见[05](05.资料纠错与按需调用规则.md)。

在 PVZH 中，单人战役、英雄关卡与解密挑战（Puzzle Party）的所有数据均存放在 `data_assets_*` 资源包内。

本章节详细讲解 PVZH 关卡数据的存储机制、JSON 属性结构、剧情与解密发牌事件配置，以及基于社区工具 [PVZH-Level-Editor](https://github.com/Show-o4210/PVZH-Library/tree/main/tools/level-editor) 的可视化编辑与打包注入流程。

> 2026-10-25纠错：01～04已纠正旧字段、事件类型和“权重必须100／最大编号优先”等误导。代码摘录仍不是完整导入模板。历史僵尸200案例见[Agent关卡指南](../agents/03-levels-and-localization.md)，新专项事实见[筛选摘要](关卡事实核对-20261025.json)，不能把新文档或原包结构核对称作新实机通过。

## 核心工作流概览

```mermaid
graph TD
    A["1. 定位目标关卡 ID<br/>在 cn.csv 中搜索关卡中文名反查 Id"] --> B["2. 读取 data_assets_* 底包<br/>提取关卡 TextAsset JSON 数据"]
    B --> C["3. 可视化编辑 / 手写修改 JSON<br/>规则, 人机/玩家, 5路地形, 剧情解密事件"]
    C --> D["4. 增量构建和真实差异核对<br/>按当前Manifest部署并验证"]
```

1. **结构解耦**：关卡文件本质上是标准的 `TextAsset` JSON 文本，包含英雄卡组、场地属性与游戏事件链。
2. **按用途校验**：原包已有权重合计0／1的配置，不能一律归一化为100。原包存在不是逐例实机已验；结构、编译、启动以及具体事件结算分别留证。
3. **AI操作范围**：修改参数或一条事件由程序保留其他结构，AI不重写完整关卡JSON；新增场景使用独立构建外壳，详见索引。

固定NPC出牌、动态难度及初始／后续给牌策略见[08.固定人机脚本与给牌前提](08.固定人机脚本与给牌前提.md)。
