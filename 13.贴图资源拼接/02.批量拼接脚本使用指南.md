# 02. 批量拼接脚本使用指南

## 一、准备环境

建议使用独立 Python 虚拟环境，并安装脚本依赖：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install UnityPy Pillow numpy opencv-python
```

将 [batch_rebuild_sprites.py](examples/batch_rebuild_sprites.py) 与以下输入放在同一工作目录，或在命令行中传入对应路径：

```text
工作目录/
├── batch_rebuild_sprites.py
├── index_new.json
├── cab_index.json
└── autotagged/
    ├── 资源包文件 1
    ├── 资源包文件 2
    └── ...
```

`index_new.json` 至少需要为每个条目提供 `GUID`、`UUID`、`NAME_CN`、`TEXTURE_NAME`、`FACTION` 与 `TYPE`。`cab_index.json` 的结构为：

```json
{
  "cabs": {
    "cab-内部名称": "autotagged中的实际文件名"
  }
}
```

> [!IMPORTANT]
> `cab_index.json` 必须与当前 `autotagged/` 资源集合对应。游戏更新或替换 Bundle 后，应重新扫描各包的内部 `CAB-*` 名称并更新映射，否则公共头脸、Sprite 或动画控制器可能无法解析。

## 二、先做小批量测试

```powershell
python .\batch_rebuild_sprites.py --limit 20 --workers 4 --output .\拼图测试
```

建议抽查多部件单位、受伤分层单位、成长单位和使用公共僵尸组件的角色。确认构图、显隐和遮挡正确后再运行全量任务：

```powershell
python .\batch_rebuild_sprites.py --workers 8 --output .\拼图输出
```

完整参数：

| 参数 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `--index` | `index_new.json` | 资源索引路径。 |
| `--bundles` | `autotagged` | AssetBundle 目录。 |
| `--cab-index` | `cab_index.json` | CAB 内部名称到实际文件名的映射。 |
| `--output` | `拼图输出` | PNG 和报告输出目录。 |
| `--limit` | `0` | 仅处理前 N 条有效索引；0 表示不限。 |
| `--workers` | 最多 8 | 并发线程数；内存紧张时应降低。 |

## 三、索引筛选与输出

示例脚本跳过中文名包含 `！`/`!` 的条目，以及 `TEXTURE_NAME` 为空或“无”的条目。输出格式为：

```text
拼图输出/
├── 植物/单位/0020_成长蘑菇.png
├── 植物/单位/0077_坚果墙.png
├── 植物/魔法/...
├── 僵尸/单位/...
└── 处理报告.json
```

文件名前的四位 `GUID` 用于稳定排序，并避免中文重名覆盖。

## 四、读懂处理报告

每条成功记录包括输出路径、尺寸、图层数、idle clip、动画覆盖数量和依赖包数量。失败状态如下：

| 状态 | 含义 |
| :--- | :--- |
| `missing_bundle` | 索引指向的资源包不存在。 |
| `missing_root` | 包内找不到与 UUID 对应的 prefab 根节点。 |
| `missing_idle` | 未找到可用 idle 动画。 |
| `no_layers` | idle 首帧没有可读取的本地可见 SpriteRenderer。 |
| `error` | 引用、解码、变换或画布尺寸等其他异常。 |

单项失败不会中止整个批处理。运行结束后应以 `处理报告.json` 为准，不要只统计 PNG 数量；重复输出到旧目录时，还要防止上次残留图片被误认为本轮成功结果。
