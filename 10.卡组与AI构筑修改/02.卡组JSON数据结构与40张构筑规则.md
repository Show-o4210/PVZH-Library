# 02. 卡组 JSON 数据结构与 40 张构筑规则

理解卡组 JSON 的节点属性，是修改 AI 出战卡牌与制作恶搞/关卡专属卡组的基础。

本篇详细解构卡组 JSON 数据格式，并讲解如何通过标志位突破 40 张卡牌限制。

---

## 一、 卡组 JSON 核心结构

```json
{
  "DeckId": "Deck_SolarFlare_Custom",
  "HeroId": 900000001,
  "ignoreDeckLimit": false,
  "Cards": [
    { "CardGuid": 900000101, "Count": 4 },
    { "CardGuid": 900000102, "Count": 4 },
    { "CardGuid": 900000103, "Count": 4 }
  ]
}
```

### 核心属性含义：

| 属性 Key | 数据类型 | 含义说明 |
| :--- | :---: | :--- |
| **`DeckId`** | `string` | 卡组唯一识别名称。 |
| **`HeroId`** | `long` | 绑定出战英雄的 GUID（如耀斑花、超级脑子）。 |
| **`ignoreDeckLimit`** | `bool` | 是否忽略标准卡组构筑上限规则（**Mod 核心标志位**）。 |
| **`Cards`** | `array` | 卡牌构筑列表，包含 `CardGuid` (卡牌GUID) 与 `Count` (数量)。 |

---

## 二、 40 张构筑规则与突破限制

### 1. 官方标准对局规则 (`ignoreDeckLimit: false`)
- **总张数约束**：整套卡组的卡牌总数量（`Count` 之和）必须**恰好等于 40 张**。
- **单卡上限**：除超能技能卡外，普通卡牌同名卡上限为 **4 张**。
- **职业匹配**：卡组内所有卡牌的 `color`/`faction` 必须完全匹配绑定的 `HeroId` 英雄的双职业属性。

---

### 2. Mod 破限模式 (`ignoreDeckLimit: true`)

> [!TIP]
> **Mod 恶搞与挑战关卡黑科技**：
> 当在卡组 JSON 中将 **`ignoreDeckLimit` 设为 `true`** 时：
> 1. **解除单卡 4 张限制**：可以制作包含 40 张相同的“潜水僵尸”或 40 张“闪电草”的趣味卡组。
> 2. **解除 40 张总数限制**：可以制作包含 60 张卡牌的大容量卡组，或仅 10 张卡牌的精简快速对局卡组。
> 3. **跨职业/跨阵营编组**：允许把其他职业的卡牌直接塞入该英雄的卡组中。
