# PVZH 视频挂载：英雄 vs 普通卡牌 — 实战差异总结

> 基于鳄梨鳄（普通随从卡，可工作）与坚果骑士 Wall-Knight（英雄，可工作）对照整理。  
> 适用：Android 真机 / 模拟器，`VideoPlayer` + Material Override + 本地 MP4 URL。

---

## 1. 一句话结论

| 类型 | 玩家看到的立绘主要来自哪里 | 改错包的表现 |
|------|---------------------------|--------------|
| **普通卡牌**（如鳄梨） | **卡牌 AB 自己**里的身体节点（默认 active） | 改对了包就能立刻看到视频 |
| **英雄**（如坚果骑士） | **英雄 AB** 的 `Heroes/*.prefab`，不是卡牌 AB | 只改卡牌包 → **完全没效果** |

普通卡的「示例成功路径」**不能直接抄到英雄上**，差在 **加载哪一个 AB** 和 **节点默认是否激活**。

---

## 2. 资源包职责对比

### 2.1 普通随从卡（以鳄梨 `2ceeb890…` 为例）

一个 autotagged 包通常同时包含：

- 卡牌 Prefab（UUID 名）
- 身体碎骨 `Texture2D` / `Sprite`（**多在本包内**）
- 动画、OverrideController 等

局内上场、手牌检视，用的都是 **这一个包里的 prefab 层级**。  
视频挂在 `Guacodile_body_base` 即可，和示例 `2ceeb890…_1_patched` 一致。

### 2.2 英雄（以坚果骑士为例）

至少拆成两套（还有图集依赖）：

| 文件（hash 示例） | Bundle 名线索 | 职责 |
|-------------------|---------------|------|
| `918c7e11fcad9f64f99c5e61455e7fc0_1` | `…/918c7e11…` | **英雄预制体** `wallknight.prefab`、局内动作、表情/FX 贴图 |
| `902a0d523c685f544a92feca91dd2cf8_1` | `…/902a0d…` | **英雄卡牌** prefab、攻击/手牌动画、SEEDPACKET、部分音效 |
| `02584f5e51a7a4108be733a1762dd293_1` 等 | 图集 / 通用 | 盔甲碎骨等高清部件（**外部 FileID 引用**） |

- **选英雄 / 对局英雄立绘** → 主要吃 **英雄 AB（918c7e…）**  
- **图鉴 / 卡牌 prefab 侧** → 才是 **卡牌 AB（902a0d…）**

只改 `902a0d`、不改 `918c7e`，对局里就像「什么都没改」。

## 3. Prefab 与节点激活（关键坑）

### 3.1 普通卡

- 身体节点（如 `Guacodile_body_base`）默认 **`m_IsActive = true`**
- 根下 `root` / `body_whole` 等显示链是开的
- `VideoPlayer.playOnAwake` 能正常 Awake 并播

### 3.2 英雄卡牌 AB（902a0d）

常见默认状态：

| 节点 | 默认 active | 说明 |
|------|-------------|------|
| 卡牌根 `fcbde864-…` | true | 有 `CardAvatarViewComponent` |
| **`WallKnight_root`** | **false** | 碎骨立绘整棵子树挂在这下面 |
| **`Wal_Knight_SEEDPACKET`** | **false** | 种子包立绘 |
| `WallKnight_body_base_art` | true | 但父级 root 关着时仍不显示 |

后果：

- VideoPlayer 即使注入成功，挂在 **inactive 子树** 上 → 不播 / 看不见  
- 必须在保存前 **强制 `m_IsActive = true`**（注意：部分 UnityPy `save_typetree` 写 bool 不可靠，可用 raw 末字节翻成 `1`）

### 3.3 英雄 AB（918c7e）

- `WallKnight` / `WallKnight_root` / `body_base_art` 默认多为 **active**
- 适合作为 **主挂载路径**（局内可见）

## 4. 贴图内外置与 Full Rect

视频要用 Material Override 画满矩形网格；原厂碎骨多为 **Tight 网格**，会裁切画面。

### 4.1 普通卡

- 身体 `Sprite` 多在 **本包**（`m_FileID = 0`）
- 可直接对 body Sprite 做 **Full Rect** + 调 `m_PixelsToUnits` 放大
- 示例鳄梨：body Sprite 已改 Full Rect，`ptu` 约从 22.9 降到 7.6

### 4.2 英雄

- **身体/盔甲 Sprite 大量 `m_FileID = 1/2` 指向外部图集**  
  → 在卡牌/英雄包内 **无法** 直接改外部 Sprite 网格  
- 正确做法（对齐 callzombie 经验）：

  1. 在本包找一张 **本地 Sprite**（`FileID=0`）  
     - 卡牌包：如 `Wal_Knight_SEEDPACKET`  
     - 英雄包：如 `Wal_SP_FX_shieldwhole` 等本包 FX  
  2. 将该 Sprite **Full Rect** 化（**保留原 `m_Texture` PathID**）  
  3. 把要播视频的 `SpriteRenderer.m_Sprite` **重绑**到这张本地 Sprite  
  4. 禁用其余盔甲/五官 `SpriteRenderer`，避免挡视频

**失败案例**：把鳄梨的 Sprite raw 整段盖到坚果包上 → 名字变成 guacadile、纹理 PathID 指向鳄梨包内不存在资源 → 紫块/崩溃/无画面。

## 5. 组件注入与 PPtr（两者相同的部分）

下面这套对 **英雄 / 普通卡** 通用：

1. **类型**：注册 `VideoPlayer`(328)、可选 `AudioSource`(82) 的 TypeTree（从 Unity 模板 AB 拷贝节点）  
2. **新建对象**：固定 PathID 如 `999999` / `999993`，`add_object` + `save_typetree`，**不要**把 sample 的 `ObjectReader` 硬塞进目标 AF  
3. **绑定**：

   ```
   m_GameObject              → 挂载的身体 GO
   m_TargetMaterialRenderer  → 该 GO 上的 SpriteRenderer
   m_TargetMaterialProperty  → "_MainTex"
   m_RenderMode              → 3 (Material Override)
   m_DataSource              → 1 (URL)
   m_PlayOnAwake / m_Looping → true
   m_Url                     → 真机 file:// …/video/xxx.mp4
   ```

4. **反向挂载**：身体 GO 的 `m_Component` 追加 VideoPlayer（及 AudioSource）  
5. **保存**：`env.file.save(packer="original")`，勿随意改成无压缩导致包暴涨  
6. **音频**：AB 内绑 AudioSource 播 MP4 音轨，真机实测多半无声；音效应走 Wwise 路线  

脚本参考：`fix_video_ab.py`（鳄梨/callzombie）、`patch_wallknight_video_v3.py`（英雄+卡牌）。

## 6. 视频文件格式（Android 硬约束）

| 格式 | 能否在 PVZH 安卓 URL 播放 | 备注 |
|------|---------------------------|------|
| **H.264 + yuv420p 的 `.mp4`** | ✅ 稳定 | 唯一建议格式 |
| WebM VP8/VP9 + alpha | ❌ 常挂不上 | 透明在安卓解码层基本不可用 |
| MOV qtrle / ProRes + alpha | ❌ 常挂不上 | 体积大且解码器不认 |

因此：

- 「智能抠像」可以做（rembg 等）  
- 最终仍应 **铺到不透明底（如黑底）再压 H.264 mp4**  
- **真透明遮挡 UI** 在不改引擎/Shader 的前提下 **做不到**；应用 **下移 / 缩小 / 调 Sorting** 减轻挡 UI  

真机路径示例：

```text
file:///storage/emulated/0/Android/data/com.ea.gp.pvzheroes/files/cache/bundles/files/video/kunkun.mp4
```

## 7. 显示参数（位置 / 大小）

在 body 的 **Transform.m_LocalPosition.y** 上叠加 `display_y_offset`：

- Unity **+Y 向上**，要 **整体下移** → 使用 **负的** `display_y_offset`  
- 放大：降低 Sprite 的 `m_PixelsToUnits`（`orig_ppu / display_scale`）  
- **不要**缩放 `body_whole` 父节点（会连带把子节点位置拽飞）  

| 对象 | 典型调整项 |
|------|------------|
| 英雄 AB body | `display_y_offset`、`display_scale`、本地 Full Rect Sprite |
| 卡牌 AB body / SEEDPACKET | 同上 + **强制 active** |

## 8. 推荐工作流对照

### 8.1 普通卡（最短路径）

```text
1. 确认干净原包（含 body Sprite 在本包）
2. 注入 VideoPlayer → 绑 body GO + body SpriteRenderer
3. body Sprite Full Rect + 调 ptu / body Transform.y
4. 可选：禁用碎骨 SR
5. 部署 autotagged/<hash>_1 + video/*.mp4
6. 杀进程重启游戏验证
```

### 8.2 英雄（完整路径）

```text
1. 用 AssetPathsManifest / 容器路径确认：
   - 英雄 prefab 在哪个 AB（主）
   - 卡牌 prefab 在哪个 AB（副）
2. 【主】改英雄 AB：
   - 本地 Sprite Full Rect + 重绑 body SR
   - 注入 VP，禁用盔甲 SR
   - 调 y / scale
3. 【副】改卡牌 AB（图鉴/卡面需要时）：
   - 强制 WallKnight_root / SEEDPACKET active
   - 同样注入 + Full Rect 本地图
4. 多模拟器缓存路径都覆盖一遍（雷电 / MuMu 共享目录等）
5. 只用 H.264 mp4；重启游戏验证「选英雄 / 对局」而不只看卡包目录
```

## 9. 故障对照表

| 现象 | 优先排查 |
|------|----------|
| 完全没变化 | 是否改错 AB（英雄只改了卡牌包） |
| 有注入但从不播 | GO/父节点是否 `m_IsActive=false` |
| 紫块 / 崩 | Full Rect 是否误用他卡 Sprite/错误 Texture PathID |
| 包体积暴涨数倍 | 是否错误合并 sample 对象 / packer 不对 |
| webm/mov 无画面，mp4 有 | 正常：安卓只认 H.264 mp4 |
| 挡 UI | 下移 y、减小 scale；勿指望透明 mp4 |
| 有画无声 | 预期内；走 Wwise，勿死磕 VideoPlayer 音轨 |
