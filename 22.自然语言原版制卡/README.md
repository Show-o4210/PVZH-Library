# 22. 自然语言原版制卡

目标是让普通用户用中文描述卡牌，由AI API理解需求，程序输出可复查的原版卡表补丁、中文和Bundle。模型需要一份明确的能力合同、当前原包索引和编译器反馈；资料整理、生成、校验与游戏验收应连成一条制作流程。

2026-10-18已完成独立原型：[natural-card-author](../tools/natural-card-author/README.md)。没有使用R19／R25的1001～1023规则，没有修改现有Mod、APK或设备。原版源数据由使用者提供，库内不打包游戏资产。

- [01.知识组织与制作流程](01.知识组织与制作流程.md)：把经验变成可供API消费的原包事实、能力合同和编译规则。
- [02.能力边界与后续接入](02.能力边界与后续接入.md)：现在能做什么，接UI／hook还需要什么。
- [03.API实测与证据](03.API实测与证据.md)：DeepSeek真实调用、误拒绝、程序失败修复、静态复制矩阵和验收范围。
- [04.API卡牌独立真机抽测](04.API卡牌独立真机抽测.md)：后续使用B4及独立单卡profile验证实际结算，与mod2隔离；证据单独归档。
- [机器验收摘要](验收摘要.json)／[Agent13](../agents/13-natural-language-native-cards.md)。

当前标准达到“可调用、可验证的单卡制作后端”：支持属性与词条、已开放的原版能力组合，以及同阵营可用单位的完整原生能力包复制。650个原卡定义与162种序列化类型可索引；415个可用单位能力包的逐一复制／编译比较通过。

初轮最终32个不同中文用例中，23个生成候选、6个返回不支持、3个要求澄清，全部符合各自预先写好的预期；23个候选均对两个Bundle回包并回读。这个结果经过两次能力说明修正，不是32例首轮全对。**初轮没有逐卡战斗实测，也不代表任意原版设计已全部开放。**后续抽样的游戏证据见04，不回写初轮静态报告。

后续独立设备抽测六份未改写的API计划，最终25个检查点通过，涵盖登场伤害、出牌增益、邻线冻结、回合抽牌、伤害后随机回手和原生完整能力复制。保留一次助手断言FAIL、初始化托管异常及恢复证据，见04与[真机机器摘要](真机验收摘要.json)；没有新增动画／AI预测验收。

公开给玩家前仍需累计项目、预览与撤销、版本冲突、原版复杂条件覆盖、实机回归和加载适配。Hook适合承担审核通过的数据加载；AI的输出仍须经过同一个原版编译与验证核心。
