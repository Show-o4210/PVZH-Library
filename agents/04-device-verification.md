# 04 · ADB 部署与验证

## 路径与回退

先执行 `adb devices -l`，多设备时明确 `-s SERIAL`。本次模拟器为 emulator-5554，包名 com.ea.gp.pvzheroes；这些值不是跨环境常量。

设备缓存根目录：

```text
/sdcard/Android/data/com.ea.gp.pvzheroes/files/cache/bundles/files/
```

| 本地文件 | 相对设备路径 |
|---|---|
| card_data_1 | cards/card_data_1 |
| data_assets_29 | data_assets_29 |
| cn_8 | loc/cn_8 |

部署步骤：

1. pull 三个设备文件到独立备份目录；记录 SHA-256，不覆盖既有备份。
2. 对比设备备份与用户输入；若不一致，先确定是否存在应保留的既有 Mod。
3. force-stop 游戏，push 已校验的三个输出包。
4. 设备 `sha256sum` 对比本地输出，确保实际写入完成。
5. 按用户验收范围启动并记录截图：只要求能进游戏时确认正常主界面；要求关卡或技能实测时才进入相应关卡检查。
6. 需要回退时 force-stop 并将三个备份推回同一路径，再校验哈希。

不要清除应用数据、删除缓存目录或修改用户存档来替代调试。不要假定添加一个更高数字后缀文件即可让客户端加载；先核实当前实际缓存和资源清单。此任务只替换设备已使用的同名文件。

## 全单位冬青／设1生命案例的实测矩阵

以下是该案例的技能测试项目，不是用户仅要求启动时的额外必做工作。启动验收应看到当前构建正常主界面，并再次核对设备包哈希。

- 能正常加载菜单和目标关卡。
- 僵王博士头像、入场标题、规则文字正确。
- 植物普通单位打出后为 1 血。
- 僵尸普通单位打出后为 1 血。
- 僵尸打出能冻结相邻路线植物，植物打出能冻结相邻路线僵尸；同路线、己方单位不应因新增技能被冻结。
- 英雄生命、锦囊和环境不受场景设血影响。
- 后续加血能生效，没有持续锁血。
- 非 200 关没有新场景规则（全卡新增冬青技能仍为全局改变）。

墓碑揭示、召唤/变形、进化/融合、原生登场设血、连续光环等交互按实际测试范围单独列出，不用静态验证替代实测。

截图可用 Python `subprocess.run([adb,...,"exec-out","screencap","-p"], capture_output=True).stdout` 保存二进制，避免旧 PowerShell 重定向损坏 PNG。通过 `input tap/swipe` 操作前读取新截图，坐标须来自当前界面。

### 出牌落点与长按截图

不要把可见路线的任意位置当成有效格子。此模拟器 1080×1920 竖屏中，僵尸手牌实际要拖到靠己方英雄的一排格子（此次中路约 x=540、y=1210），落在 y=600~1040 的路线空白处会退回手牌。

定位方法：以 `subprocess.Popen` 启动 `adb shell input swipe x y x y 8000`，在命令仍长按时，另一次 ADB 调用执行 screencap，读取高亮格子后再决定落点。这里只是示例坐标，换分辨率和场景后必须重新观察。此设备的 `input` 不支持 `motionevent`，且错误可能写在 stderr 而退出码为 0，封装工具应展示 stderr，不能只检查返回码。
