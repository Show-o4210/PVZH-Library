# 11 · 语义测试、失败隔离与交付证据

适用：持有匹配的测试工程／APK，并且用户授权设备测试。只有图书馆时仅能查阅方法和已归档摘要，不能假定已经存在端口、Gadget或 `scripts/test.py`。

接口、操作表与完整流程见[第21章01](../21.语义调试与技能扩展实战/01.语义接口与测试流程.md)，资源选择见[第20章05](../20.工程体验跃迁-资源门卫与教程跳过/05.必选资源切换实战/README.md)。

## 1. 会话前核对

- 读取当前设备、实际安装包和资源profile，不写死案例序列号或实体ID。
- 保留用户账户、缓存与已有改动；不要以清数据代替调试。安装、资源写入和对局操作须在用户授权范围内。
- `launch(reset=True,profile=...)`冷选模式；`reset=False`复用进程，不切换其现有profile。核对返回的真实模式。
- 等暖机与就绪只是必要条件。R19的120秒限制、非空binding及新模型初始化都不是旧局已销毁的证明。

## 2. 每个技能用例

1. 明确正例、反例、前置条件、来源／目标／阵营及预期结算时机。
2. 从新fixture的state读取generation和实体身份；不拿上一局相同数字ID当成同一对象。
3. 先用普通、已验证的初始牌组，再give测试卡是R19已完成整局的路径；含601／202的初始牌组冷建局有失败记录，不能宣称同样通过。
4. 使用合法出牌、目标选择和原版阶段推进验证技能；summon或fixture设置仅用于清晰标明的前置条件，不能冒充PlayTrigger／墓碑验证。
5. 每次保存请求／响应、前后状态和模块计数；核对费用、手牌／牌库、来源和所有相关单位，不只看一句“触发成功”。
6. 随机技能按实际原版选择校生命差，记录候选完整集合、单次RNG和实际接收者；固定seed样本不等于证明所有随机种子。
7. 非终局应核模块错误未增加、临时根归零和待处理效果／metadata结束。Destroy先标记后死亡的场景须观察真实离场。

`fixture_effect`有白名单，不提供任意native调用。R19 fixture Grant只允许0–18及1012–1014；不要为让测试跑通临时开放所有保留标签或绕过原版目标验证。

## 3. 原生异常和连续重开

遇到native access violation立即停止该模型上的后续操作。保留异常、请求、代数和已有日志，强停恢复后用新证据名重新测，不把恢复后的PASS写回旧FAIL。

R19记录过无等待温重开失败、两秒等待仍失败，以及一次新卡初始牌组冷建局失败。独立冷进程、每场景五秒等待曾完成静态37项；这只是那轮通过，**不是五秒可以保证任意重开安全**。appReady、旧Context移除、过渡队列和长期GC根回收仍需独立屏障与观测。

不要直接清空held根、强制低层Destroy／OnRemove或递归驱动Unity帧来消除表面异常。[后续调查](../21.语义调试与技能扩展实战/05.实测与建局边界/warm-fixture-followup.md)没有确定具体0x0根因；不得按时间邻近归因到某个技能。

## 4. 分层报告

| 层级 | 能证明的内容 | 不能自动推出 |
|---|---|---|
| 静态及回包 | 类型、差异、序列化对象、包与输入一致 | 技能真正结算 |
| 设备身份／缓存 | 安装载荷、收据、三个实际缓存符合清单 | 新技能及动画全部通过 |
| 模型与合法操作 | 指定场景的费用、伤害、生命、目标、触发及阶段 | AI独立推演／所有组合 |
| 原版History | 本次显式快照可见的真实记录 | 未观察记录从未生成、全日志完整 |
| 真实动画队列 | busy→empty、原版消费者和回合推进 | 逐帧美术与专属动画全部正确 |
| 用户反馈 | 用户实际反馈范围内的运行表现 | 全部卡牌、初始牌组或边界均已验收 |

无画面fixture的动画空标志不能算渲染证据。用户不需要截图时，不为逻辑测试额外要求截图；若要求实际画面，则另行明确可见验收范围。

## 5. 终局、版本与交付

原版LoseEffect是不可解除的终局Blocking。致死伤害后的最后after-marker可能停在它后面；R19整局实测19次开始／18次完成，保留1组标量metadata且没有新增持久GC根。非终局pending=0检查仍保留，终局不能强推书签或清队列以迁就断言。详见[终局记录](../21.语义调试与技能扩展实战/04.History与原版动画/terminal-attack-metadata.md)。

候选采用新revision，不覆盖失败包和证据。卡表、脚本、界面DEX、清单及实际安装包的SHA应一致。不可变构建报告中的 `runtime: NOT TESTED` 和后续真机报告分开，不为更新状态修改旧构建证据。

双模式交付应在同一候选上验证原版规则关闭、必选门卫无跳过／Back不能入Unity、实际收据与三缓存散列一致，最后按用户要求留下界面状态。记录未测项、完整日志位置和修复范围。R19原始结果的归档入口为[验收记录](../21.语义调试与技能扩展实战/06.R19实现与验收记录/README.md)，本次文档归档没有重新运行设备测试。
