# 10 · 缓存契约与运行时技能扩展工作流

适用：用户已经要求实现纯JSON不能准确表达的技能，且授权相应Base／Gadget工作。普通属性、原版技能复用、关卡和CN仍优先按01–09执行，不为简单任务自动引入原生patch。

依据为2026-10-14的R19实践，2026-10-15整理；[第21章](../21.语义调试与技能扩展实战/README.md)保存详细原理与历史。**这里提供决策与检查清单，不提供可直接安装的测试运行时。**

## 1. 先选实现层

1. 核对用户当前要求、原始Bundle和已有修改，保留输入与旧候选。
2. 从当前卡表找实际原版组件、目标查询、触发器和效果描述器。先判断能否完整复用，不按类名猜语义。
3. 若只缺配置关系，继续修JSON。例如97单位筛选须用合适的InSameLaneQuery；547须区分授予两栖、移动及移动后的减属性条件。
4. 若缺真正攻击结束、伤害规范化、快照换血等时机，再在已授权范围设计运行时入口。不要用“造成伤害后”冒充“攻击后”，也不要把设1生命写成交换当前生命。
5. 明确技能效果、界面标识、History、动画、AI预测是否分别实现。不能因为原卡有special就默认所有新结果都能消费。

## 2. 固定版本和配置契约

- 记录APK、`libil2cpp.so`、脚本、资源清单、实际缓存和profile身份；RVA、布局、类型串及ABI都须与目标二进制匹配。
- 保留原版的完整IL2CPP `$type`，不编造不存在的类。字段、枚举、持续时间及查询类型从当前原包确认。
- R19的1001–1014只是该Gadget与卡表之间的私有合同，不是原版枚举，也不是第12章历史19号赋甲补丁的通用升级。
- 持续marker在卡体读取；动作marker须在未知枚举进入原版Grant或图标分派之前截获。移植前核对两种路径，不能只复制JSON数字。
- schema、资源revision、规则编号、技能参数分开；同步中文长短描述，精确保留非目标卡和隐藏定义。
- original／mod2双模式由真实选择收据控制。相同APK下original必须不触发新规则，不能只看APK文件名。

14类规则及17张卡映射见[卡表契约](../21.语义调试与技能扩展实战/02.缓存契约与扩展规则/card-data-and-history.md)。要复用其中任一标签，必须同时具备匹配运行时；普通原版包不能直接导入这些标签。

## 3. 维护原版效果所有权

优先用原版Effect、实例池、响应队列、StateCheck和History完成结果，少直接改最终属性。

- 新Acquire的Effect、原生返回List在尚未交给托管容器时需临时strong GC root；成功入队后释放。不能用JavaScript变量替代托管GC根。
- 禁攻通过取消原列表中的效果，保留原队列所有权；不要提前Clear并自行Return原效果。
- 标量字段可用正确大小的缓冲区；引用字段必须传真实托管对象并走匹配API／写屏障。R19对应二进制使用 `il2cpp_field_set_value_object`，不能把指针缓冲区地址写成String。
- native hook只取已缓存且模型身份匹配的上下文；cache miss不得递归发起Unity Resources全局扫描。显式命令或外层帧负责可控刷新。
- 对响应继承源Effect的实际EffectGroupId。InterruptQueue取得新组时，CurrentGroupId可能仍指向旧Blocking组，不能随意取当前值导致响应晚一阶段。
- 数字来源GroupId、Damage source/player、原始倍率和真正接收者防御都要保留；不能为一次标记乱用已有Tag或EffectData字段。

详见[引用ABI](../21.语义调试与技能扩展实战/03.托管内存与效果所有权/il2cpp-reference-field-abi.md)、[攻击规则](../21.语义调试与技能扩展实战/02.缓存契约与扩展规则/attack-rules.md)。

## 4. 以伞叶为例处理单次重定向

用户确认的规则是每笔正伤害在自身与左右邻线各株植物间选择一次；同线其他植物不参与，选自己正常结算，转给邻株后不再被另一株伞叶转移。

R19使用当前原版RNG，修改同一伤害包的target及context target，在接收者免伤／护甲之前接入。单次标记为JS标量metadata，经原版DeepCopy／redirect context传播，并在返池、队列／模型scope变化时清理；不能把标记带给独立新建的受伤触发伤害。

不要把未知EffectValue写进字典：匹配版本的序列化器仅接受0–11，越界会抛枚举异常。也不能在Armor才换目标，前面的免伤已作用于错误对象。

这些是R19的具体实现，不证明其他二进制相同。实际321笔专项结果、native97复制及未测的目标相关倍率／沉默场景见[伞叶记录](../21.语义调试与技能扩展实战/02.缓存契约与扩展规则/umbrella-rules.md)。

## 5. 处理原版动画

区分AbilityGroupId（原卡动画组）与EffectGroupId（结算组）；不要把规则编号当成动画组。保留合法PlayTrigger原有Start／End与通用结果消费者。

借用旧触发实体追加special书挡可能重写结果上下文并重新验条件，导致技能结果被取消。R19默认关闭这类额外包装。87与106采用有严格source、当前模型和记录结构守卫的窄消费者兼容；不能清空队列或设置“已完成”绕过问题。

History快照始终不完整；无画面状态不能证明动画。下一步按[11语义测试与证据](11-semantic-testing-and-evidence.md)记录每层验收结果。
