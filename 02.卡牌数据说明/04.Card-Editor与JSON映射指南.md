# 04. Card-Editor 与 JSON 映射指南

为了让开发者免于繁琐、易错的十六进制与底层 JSON 手工编辑，社区开发了基于 Python & PySide6 的图形化修改工具 **[PVZH-Card-Editor](https://github.com/Show-o4210/PVZH-Card-Editor) (幻影引擎 / Phantom Engine)**。

本篇文档将深入讲解该工具在代码层面的数据模型定义、.phantom 项目文件格式以及它与 PVZH 游戏原生卡牌 JSON 之间的映射机制。

---

## 一、 工具核心模块架构

PVZH-Card-Editor 的关键源码模块对应关系如下：

```text
PVZH-Card-Editor/
├── card_model.py        # 定义 CardModel 类：卡牌内存模型 ↔ 原生 JSON 字典的双向转换
├── logic_library.py     # 技能节点库定义：包含 Trigger, Filter, Target, Effect 等全量 C# 类型字典
├── constants.py         # 常量定义：程序集后缀、命名空间、独立能力映射表 (COMP_ABILITY_MAP)
├── logic_translator.py  # 自然语言描述引擎：将逻辑节点树翻译为中文/英文技能说明
├── project_manager.py   # .phantom 多卡牌项目文件管理
└── bundle_packer.py     # 基于 UnityPy 的 AssetBundle 卡牌数据注入与导出打包器
```

## 二、 `CardModel` 内存对象与原生 JSON 的映射机制

在 [card_model.py](https://github.com/Show-o4210/PVZH-Card-Editor/blob/main/card_model.py) 中，`CardModel` 类封装了一张卡牌的所有基础属性与能力组件。

### 1. 基础属性映射关系

| `CardModel` 属性字段 | 原生 JSON 对应位置 | 说明 |
| :--- | :--- | :--- |
| `self.guid` | 顶层字典键 & `CardComponent.Guid` | 卡牌 GUID 编号 |
| `self.cost` | `SunCostComponent.SunCostValue.BaseValue` & 外层 `displaySunCost` | 卡牌出牌费用 |
| `self.attack` | `AttackComponent.AttackValue.BaseValue` & 外层 `displayAttack` | 随从攻击力 |
| `self.health` | `HealthComponent.HealthValue.BaseValue` & 外层 `displayHealth` | 随从生命值 |
| `self.rarity_key` | `RarityComponent.Value` & 外层 `rarity` | 稀有度枚举 |
| `self.logic_subtypes` | 外层 `subtypes` 数组 | 逻辑判断族群 |
| `self.display_subtypes` | 外层 `tags` 数组 | UI 显示族群标签 |
| `self.logic_entities` | `EffectEntitiesDescriptor.data.entities` | 技能逻辑树数组 |

### 2. 类型工厂与程序集补充

在 [constants.py](https://github.com/Show-o4210/PVZH-Card-Editor/blob/main/constants.py) 中，定义了全自动化补全 C# 程序集后缀的工具函数：

```python
NAMESPACE_ENGINE = "PvZCards.Engine.Components."
NAMESPACE_QUERY = "PvZCards.Engine.Queries."
ASSEMBLY_SUFFIX = ", EngineLib, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null"

def build_type_str(comp_name: str, is_query: bool = False) -> str:
    """自动将短组件名构建为全限定 C# 类型字符串"""
    prefix = NAMESPACE_QUERY if is_query else NAMESPACE_ENGINE
    return f"{prefix}{comp_name}{ASSEMBLY_SUFFIX}"
```

当导出或生成 JSON 时，编辑器自动调用 `build_type_str("Attack")` 生成：
`PvZCards.Engine.Components.AttackComponent, EngineLib, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null`

## 三、 能力组件的双轨同步与序列化

编辑器支持独立能力组件（如 Armor, Teamup）与双轨/触发类能力（如 DoubleStrike, Overshoot）的自动同步与生成：

### 1. 独立组件映射表 (`COMP_ABILITY_MAP`)

```python
ABILITY_COMP_MAP = {
    "Multishot": "MultishotComponent",
    "AttacksInAllLanes": "AttacksInAllLanesComponent",
    "Aquatic": "AquaticComponent",
    "Truestrike": "TruestrikeComponent",
    "Strikethrough": "StrikethroughComponent",
    "Deadly": "DeadlyComponent",
    "Frenzy": "FrenzyComponent",
    "Armor": "ArmorComponent",
    "Untrickable": "UntrickableComponent",
    "Teamup": "TeamupComponent",
}
```

### 2. 序列化流转流程 (`generate_json_dict`)

当在编辑器中点击保存或导出时：
1. **构造 `components` 数组**：依次压入 `CardComponent`、`SunCostComponent`、`AttackComponent`、`HealthComponent` 和 `RarityComponent`。
2. **附加能力组件**：遍历 `components_abilities`，根据 `ABILITY_COMP_MAP` 自动压入对应的能力 C# 组件。
3. **附加逻辑节点**：若存在 `logic_entities`，构造 `EffectEntitiesDescriptor` 并将完整节点树序列化装入。
4. **生成外层元数据**：自动同步组装外层 `displayAttack`、`displayHealth`、`subtypes`、`tags` 和 `special_abilities` 数组。

## 四、 项目文件 (.phantom) 与打包注入

- **.phantom 文件**：
  PVZH-Card-Editor 自定义的工程存储格式（本质上是序列化后的多卡牌 JSON 字典，便于保留编辑历史、工程名、卡牌关系以及节点连线等辅助元数据）。
- **打包注入 (`bundle_packer.py`)**：
  基于 `UnityPy` 库。导出时：
  1. 读取游戏原版 AssetBundle 数据包（如 `card_data_5`）。
  2. 提取并解包其中的 `TextAsset` / JSON 文本。
  3. 将修改后的卡牌 JSON 对象覆写或追加至原生字典中。
  4. 重新打包二进制 AssetBundle 并输出为可直接替换到设备的 Mod 文件。

---

## 五、 Mod 开发协作最佳实践

1. **可视化搭建逻辑树**：
   对于复杂的卡牌技能，优先使用 `PVZH-Card-Editor` 的图形化 Logic 选项卡进行拖拽拼接，避免手动手写 JSON 出现括号未闭合或节点嵌套层级错误。
2. **导出对比校验**：
   导出的 Mod 数据包，建议先用编辑器反向导入一次，确认攻防数值、界面 Icon 标签 (`special_abilities`) 以及 `subtypes` 无误后再部署到模拟器进行测试。
