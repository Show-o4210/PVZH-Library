# 05. 手动修改最佳实践与新建卡牌指南

本篇文档归纳了在编辑 `card_data` 数据时最关键的手工修改法则、新卡牌创建逻辑以及经验踩坑避坑指南。

---

## 一、 手动修改 JSON 最核心法则：复制原版粘贴修改！

> [!IMPORTANT]
> **黄金法则：手动修改或添加 JSON 逻辑时，最好的方式就是直接“复制原版已有卡牌的代码结构”进行粘贴与微调！**

### 为什么必须优先复制粘贴？
1. **防止 C# 程序集类型错误**：
   底层 C# 组件类型全名极其繁琐（如 `PvZCards.Engine.Components.AttackComponent, EngineLib, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null`）。凭空手写极易出现大小写错拼、标点或程序集后缀遗漏，从而导致游戏加载直接闪退。
2. **保证嵌套结构完整**：
   许多属性组件带有深层嵌套（如 `{"AttackValue": {"BaseValue": 3}}`）。直接复制原版随从的组件块，再修改 `BaseValue` 数字，能确保 100% 不破坏数据语法。
3. **避免语法符号缺失**：
   JSON 对逗号 `,`、花括号 `{}`、中括号 `[]` 的闭合要求极严。通过复制已有完整节点，可以最大程度减少语法报错。

---

## 二、 创建全新的独立卡牌 (新建卡牌指南)

如果你想在 PVZH 中新增一张全新的卡牌（而不是修改原有卡牌），其实非常简单：**直接在 `card_data` JSON 文件的最底部，照着原版框架续写一个新的卡牌对象即可！**

### 1. GUID 唯一性要求
- **核心原则**：新增卡牌的 **GUID（顶层字典键名及内层 `CardComponent.Guid`）必须是全网唯一的**，绝不能与已有卡牌重复。
- 建议自定义 GUID 使用较大数值区间（如 `900000001`、`900000002` 等）。

### 2. `prefabName` 的复用与索引规则
- **能否复用原版 `prefabName`？**
  **完全可以！** `prefabName` 重合没有任何问题。
- **复用效果**：
  在底层引擎眼里，只要 GUID 不重合，这就是一张**全新的独立卡牌**。
  如果复用了某张原版植物/僵尸的 `prefabName`，新卡牌只是会共享使用该原版卡牌的 2D 贴图素材、预制体动画以及默认的 UI 展示索引。
- **自定义文本与视觉**：
  如果希望新卡牌拥有独立的中文名称与技能说明，只需在本地化文件 [cn.csv](../资源/cn.csv) 中添加新 GUID 对应的 `_name` 与 `_shortDesc` 选项即可。

## 三、 新建卡牌完整模板与步骤示例

以新增一张 GUID 为 `900000001` 的自定义随从卡为例：

```json
{
  "900000001": {
    "entity": {
      "components": [
        {
          "$type": "PvZCards.Engine.Components.CardComponent, EngineLib, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null",
          "$data": {
            "Guid": 900000001
          }
        },
        {
          "$type": "PvZCards.Engine.Components.SunCostComponent, EngineLib, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null",
          "$data": {
            "SunCostValue": {
              "BaseValue": 3
            }
          }
        },
        {
          "$type": "PvZCards.Engine.Components.AttackComponent, EngineLib, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null",
          "$data": {
            "AttackValue": {
              "BaseValue": 4
            }
          }
        },
        {
          "$type": "PvZCards.Engine.Components.HealthComponent, EngineLib, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null",
          "$data": {
            "HealthValue": {
              "BaseValue": 4
            }
          }
        },
        {
          "$type": "PvZCards.Engine.Components.RarityComponent, EngineLib, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null",
          "$data": {
            "Value": "R3"
          }
        }
      ]
    },
    "prefabName": "002f2d4b-7b58-4c32-86f1-0bd414848d4b", 
    "baseId": "BasePlantFighter",
    "color": "0",
    "set": "Gold",
    "rarity": 3,
    "setAndRarityKey": "Rare",
    "displayHealth": 4,
    "displayAttack": 4,
    "displaySunCost": 3,
    "faction": "Plants",
    "ignoreDeckLimit": false,
    "isPower": false,
    "isPrimaryPower": false,
    "isFighter": true,
    "isEnv": false,
    "isAquatic": false,
    "isTeamup": false,
    "subtypes": ["Pea"],
    "tags": ["Pea"],
    "subtype_affinities": [],
    "subtype_affinity_weights": [],
    "tag_affinities": [],
    "tag_affinity_weights": [],
    "card_affinities": [],
    "card_affinity_weights": [],
    "usable": true,
    "special_abilities": []
  }
}
```

> [!TIP]
> 上述代码中的 `prefabName` 直接复用了原版卡牌 `002f2d4b...`，但因 GUID 为全新的 `900000001`，引擎会成功将其识别为一张独立的费用为 3、攻防 4/4 的新随从！
