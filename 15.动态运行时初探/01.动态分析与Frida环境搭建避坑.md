# 01. 动态分析与 Frida 环境搭建避坑

在 Mod 开发中，静态分析（通过反编译看代码）和动态插桩（在运行期看内存）就像一位医生的“X光片”与“内窥镜”。静态反编译能够帮我们理清函数的调用结构，但诸如“某个对象在内存中究竟长什么样”、“某个变量在对局中的瞬时数值是多少”，必须依赖动态调试来解答。

本篇讲解如何在真实测试设备上搭建稳定可靠的 **Frida** 动态调试环境，并记录实战中高频出现的各种环境避坑要点。

---

## 一、 为什么选择动态插桩（Frida）？

在研究复杂游戏逻辑（例如卡组如何初始化、对战胜负判定如何触发）时，静态修改面临如下困境：

```text
静态 Patch 修改代码 ──► 重新编译 SO ──► 重新签名打包 APK ──► 安装到手机 ──► 启动游戏测试
      ▲                                                                         │
      └────────────────────────── 耗时 3~5 分钟 / 单次循环 ──────────────────────┘
```

而引入 Frida 动态插桩后：

```text
编写/修改 JS 脚本 ──► 保存文件 (Hot-reload) ──► 进程内存实时拦截 ──► 终端立即看到输出日志
      ▲                                                                  │
      └────────────────────────── 耗时 1~2 秒 / 单次循环 ─────────────────┘
```

**核心优势**：
1. **零重装、热重载**：修改 JavaScript 脚本后无需重启游戏进程，Frida 自动重新加载；
2. **非侵入式探测**：不改动手机上的 APK 文件本体，随时关闭随时恢复原版；
3. **跨语言双轨支撑**：一套框架同时支持挂钩 Android Java 层（UI 与生命周期）与 C/C++ Native 层（IL2CPP 游戏引擎）。

## 二、 基础环境准备与真机要求

为了获得最佳的符号暴露效果，推荐准备一台用于测试的 ARM64 物理真机（已获取 Root 权限）：

### 1. 检查物理设备架构
通过 ADB 确认测试手机的 CPU 指令集架构：

```bash
# 查看设备 ABI
adb shell getprop ro.product.cpu.abi
# 预期输出: arm64-v8a

# 查看设备 Android 系统版本
adb shell getprop ro.build.version.release
# 输出例如: 14 或 16
```

> [!IMPORTANT]
> ⚠️ **强烈推荐 ARM64 物理真机**：
> 如第 11 章所述，PC 安卓模拟器大部分采用 x86_64 指令集配合转译层运行 ARM64 游戏，这会导致 Frida 难以枚举到真正的游戏 SO 库。在物理真机上运行可以彻底规避转译层干扰。

## 三、 PC 端与手机端安装配置

Frida 采用“客户端（PC 命令行 / Python）+ 服务端（手机守护进程）”的架构模式。**双端版本必须保持一致**。

### 1. PC 端安装 Frida 命令行工具
推荐使用 Python 3.10+ 环境安装 Frida 客户端套件：

```bash
pip install frida frida-tools

# 验证 PC 端安装与版本
frida --version
# 输出例如: 17.15.3 (请记住当前的主次版本号)
```

### 2. 手机端部署对应版本的 frida-server
前往 Frida 官方 GitHub Releases 页面，下载与 PC 端**版本完全一致**的 Android ARM64 二进制文件：
- 文件名形如：`frida-server-<版本号>-android-arm64.xz`
- 解压后得到 `frida-server` 可执行文件。

通过 ADB 推送至手机并赋予执行权限：

```bash
# 1. 推送到安卓受保护的临时可执行目录
adb push frida-server /data/local/tmp/

# 2. 进入手机 Root shell 赋予权限
adb shell
su
chmod 755 /data/local/tmp/frida-server

# 3. 后台启动服务
/data/local/tmp/frida-server &
```

## 四、 连通性测试与进程枚举

启动手机上的 PVZH 游戏，在 PC 终端验证 Frida 是否能正确穿透至游戏进程：

```bash
# 列出当前连接 USB 设备上正在运行的所有应用进程
frida-ps -Uai
```

控制台若输出如下内容，说明环境部署成功：

```text
  PID  Name                      Identifier
-----  ------------------------  --------------------------
24314  PvZ Heroes                com.ea.gp.pvzheroes
```

同时可以通过一行极简的命令行快速附加，测试目标进程是否响应：

```bash
# 通过进程名附加并执行简单的模块枚举
frida -U -n com.ea.gp.pvzheroes -E "Process.enumerateModules()[0]"
```

若能正确返回 `[Module: "..."]` 结构，说明动态插桩链路已完全打通！

## 五、 实战常见报错与避坑指南

### 1. 报错：`Failed to enumerate applications: unable to connect to remote frida-server`
- **排查步骤**：
  1. 手机端执行 `adb shell su -c "pidof frida-server"`，检查服务是否在后台意外退出；
  2. 检查是否有安全软件或 Magisk 模块拦截了 `27042` 端口；
  3. 执行 `adb forward tcp:27042 tcp:27042` 进行端口手动映射。

### 2. 报错：`Permission denied`（启动 frida-server 失败）
- **根本原因**：SELinux 处于严格模式（Enforcing）。
- **解决办法**：在测试设备上临时将 SELinux 调为宽容模式：
  ```bash
  adb shell su -c "setenforce 0"
  ```

### 3. 游戏启动即闪退或卡死（Watchdog 崩溃）
- **根本原因**：在游戏冷启动的第一帧就挂载大量 Hook 钩子，可能阻塞 Unity 主渲染线程初始化。
- **最佳实践**：采用“延迟挂钩（Delayed Attachment）”策略，等待游戏完全进入主界面，或使用 Frida 脚本的 `setTimeout(..., 2000)` 预留两秒初始化窗口。
