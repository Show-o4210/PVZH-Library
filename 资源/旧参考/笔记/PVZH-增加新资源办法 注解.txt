# 🧩 Unity Modding 实战教程：看懂 Dump，手把手添加新部件

> 本文基于《植物大战僵尸：英雄》的真实资源片段，用**自然语言**解释每一个关键字段。  
> 适用场景：你想往游戏里 **凭空增加一个全新的可动部件**（例如给向日葵加个皇冠），并且这个部件能被动画独立控制。  
> 前置工具：UABEA（能打开 `.assets` / `.bundle` 文件，支持导出/导入 Dump 文本）。

---

## 一、先记住三个“铁三角”组件

任何能在游戏里看见、会动的东西，都由下面三个数据块组成。你需要在 Dump 文本里手动创建它们。

| 组件 | 它负责什么 | 关键字段 |
|------|------------|------------|
| **GameObject** | 起名字，挂载组件列表 | `m_Name`，`m_Component[]` |
| **Transform** | 位置、旋转、父子关系 | `m_LocalPosition`，`m_Father`，`m_Children[]` |
| **SpriteRenderer** | 显示哪张图片 | `m_Sprite`，`m_GameObject` |

**一句话理解**：  
- `GameObject` 是身份证（名字 + 我身上挂了哪些组件）。  
- `Transform` 是户口本（我爹是谁、我儿子有哪些、我在家里的坐标）。  
- `SpriteRenderer` 是工作证（我属于哪个 GameObject，我负责画哪张图）。

### 📌 案例 1：一个“父节点”的 Transform（来自 `fa.txt`）

这个文件里描述了一个 **Transform 组件**。它本身属于某个 GameObject（那个 GameObject 的 ID 是一长串数字）。  
它有一大堆 **孩子**：在它的 `m_Children` 列表里，列出了 15 个子 Transform 的 ID。  
它自己也有一个 **父亲**：`m_Father` 指向另一个 Transform 的 ID，说明它不是根节点。

**👉 你要学会看：**  
- 如果想把自己的新部件挂在它下面，你需要：  
  1. 把你的新 Transform 的 `m_Father` 填成这个父节点 Transform 的 ID。  
  2. 在这个父节点的 `m_Children` 列表里，把 `size` 加 1，并在末尾加上你新 Transform 的 ID。  
  （⚠️ 改 `size` 和加元素必须用“导出 Dump → 改文本 → 导入 Dump”流程，不能直接在界面改。）

### 📌 案例 2：一个“花瓣”的 Transform（来自 `2.txt`）

这个文件描述了一个 **没有孩子** 的 Transform（`m_Children` 列表为空）。  
它自己挂在一个父亲下（`m_Father` 指向某个 Transform ID）。  
它的本地方位是 `x=0.84, y=1.79`，意味着相对于父亲的位置偏移。

**👉 你创建新部件时，需要类似的一个 Transform 副本**，把 `m_GameObject` 改成你的新 GameObject ID，把 `m_Father` 改成你选定的父节点 ID，位置自己调。

### 📌 案例 3：一个 GameObject 的“空壳”（来自 `father.txt`）

这个文件描述了一个 GameObject，名字叫 `"Sunflower_petals_rotate"`。  
它的 `m_Component` 数组里只有一个组件（可能只是 Transform，没有 SpriteRenderer）—— 这类物体通常用作动画辅助节点或逻辑分组。

**👉 你创建你自己的 GameObject 时**，`m_Component` 数组必须至少有 2 项：一个指向 Transform，一个指向 SpriteRenderer（因为你要显示图片）。  
数组里每一项是一个 `PPtr<Component>`，格式为 `{fileID, pathID}`。通常 `fileID=0`（同一包内），`pathID` 填你新建的 Transform 和 SpriteRenderer 的 ID。

### 📌 案例 4：一个 SpriteRenderer（来自 `14_unhappy.txt`）

这个文件里是一个 SpriteRenderer，它已经修改过，指向了一张外部图片：  
- `m_GameObject` 字段指向它属于哪个 GameObject（一个数字 ID）。  
- `m_Sprite` 字段是一个指针：`{ m_FileID = 1, m_PathID = 1028 }`。  
  这意味着它引用的 Sprite（图片资源）不在本文件里，而是在 **另一个依赖包** 中，`PathID` 是 1028。

**👉 你创建新 SpriteRenderer 时**：  
- 把 `m_GameObject` 改成你的新 GameObject 的 ID。  
- 把 `m_Sprite.m_PathID` 改成你在 A 包里添加的 Sprite 的 ID。  
- 关于 `m_FileID` 具体填几，看下一节。

### 📌 案例 5：一个 Sprite（图片资源）

在你添加图片的 A 包里，UABEA 会自动生成一个 Sprite 对象。  
你不用关心它里面那些复杂的顶点数据，你只需要知道：  
- 这个 Sprite 有自己的 **PathID**（比如 `1028`），显示在 UABEA 左侧列表里。  
- 你在 SpriteRenderer 里就填这个 PathID。

> ⚠️ 注意：你**不需要**手动编辑 Sprite 内部的索引缓冲或顶点数据，那些是 Unity 自动生成的。你唯一要记的就是它的 PathID。

## 三、最重要的数字：`m_FileID` 到底填几？

在 Unity 的资源里，引用另一个资源时用一对数字：  
`{ m_FileID, m_PathID }`。

- **`m_FileID = 0`** ：目标资源在 **当前正在编辑的这个文件（包）** 里。  
- **`m_FileID = 1, 2, 3…`** ：目标资源在 **另一个文件（依赖包）** 里。数字代表该依赖包在当前包的依赖列表中的**索引**（从 1 开始数）。

### 如何知道该填 1 还是 2？

1. 在 UABEA 中打开你的 **B 包**（骨架包）。  
2. 找到一个类型为 `AssetBundle` 的资源（通常在列表里叫 `autotagged/一堆字母数字`）。  
3. 查看它的 `m_Dependencies` 数组 —— 这是一个字符串列表，每一项是一个依赖包的文件名（也是哈希形式）。  
4. 你的 A 包（贴图包）的名字出现在这个列表的第几位？例如：

```
m_Dependencies:
  size: 9
  [0] "autotagged/03ce9ed..."   ← 这是第一个依赖包，索引 = 1
  [1] "autotagged/3ac590ae..."   ← 第二个依赖包，索引 = 2
  [2] "autotagged/41c99bcd..."   ← 第三个依赖包，索引 = 3
  ...
```

如果你的图片放在 `"autotagged/03ce9ed..."` 这个包里，那么 `m_FileID` 就填 **1**。  
如果放在第二个包里，填 **2**，依此类推。

> ✅ 在大多数 mod 场景中，你新增的图片会放入专门的贴图包，而你的 B 包通常已经依赖了那个贴图包。如果不确定，就按上面的方法查一下。

## 四、实战：完整创建一个新部件（手把手自然语言版）

假设你想给向日葵的头部加一个“小皇冠”，动画里能控制它旋转。  
你需要做下面 6 件事。

### 第 1 步：在贴图包（A 包）里准备图片
- 用 UABEA 打开 A 包。  
- 导入你的皇冠图片（`.png`）。  
- 右键点击刚导入的 Texture2D → `Create Sprite`。  
- 记下 **这个新 Sprite 的 PathID**，比如 `8888`。  

### 第 2 步：在骨架包（B 包）里复制一份“铁三角”
- 找一个健康的原版部件（比如某片花瓣），分别选中它的 GameObject、Transform、SpriteRenderer。  
- 对每个组件，点击 `Export Dump`，保存为三个不同的 `.txt` 文件。  
- 给这三个组件**分配全新的 PathID**（随便选三个未使用的数字，比如 `90001`, `90002`, `90003`）。  
  （改法：打开每个 `.txt`，文件头附近有一行如 `PathID: 123456`，改成你自己的数字。）

### 第 3 步：改名字，对齐动画暗号
- 打开 GameObject 的 Dump（`90001`），找到 `m_Name:` 字段。  
- 改成动画系统需要的节点名 —— 例如 `"crown"`（具体名字必须和动画文件里预设的一致，可参考原版同类部件命名）。  
- 这个名称决定了动画能不能驱动它，非常重要。

### 第 4 步：内部绑定（让三个组件互相认识）

**修改 GameObject (90001) 的 `m_Component` 数组**：  
把它改成 size = 2，第一个子项指向 Transform (90002)，第二个指向 SpriteRenderer (90003)。  
写法（在 Dump 文本里是类似 yaml 格式）：
```
m_Component:
  size: 2
  data:
  - {fileID: 0, pathID: 90002}
  - {fileID: 0, pathID: 90003}
```

**修改 Transform (90002) 的 `m_GameObject`**：改成 `{fileID: 0, pathID: 90001}`。  
**修改 SpriteRenderer (90003) 的 `m_GameObject`**：同样改成 `{fileID: 0, pathID: 90001}`。

### 第 5 步：让 SpriteRenderer 去拿你的新图片
- 打开 SpriteRenderer (90003) 的 Dump，找到 `m_Sprite` 字段。  
- 假设你的 A 包是 B 包的第一个依赖包，则写：
  ```
  m_Sprite: {fileID: 1, pathID: 8888}
  ```
- 如果你把图片和 SpriteRenderer 放在同一个包里（不推荐），则写 `fileID: 0`。

### 第 6 步：挂到父节点（双向奔赴）

**儿子认爹**：打开 Transform (90002) 的 Dump，找到 `m_Father`，填入目标父节点 Transform 的 PathID。  
例如，你想把皇冠挂在头部的 Transform 下，就去找到那个头部 Transform 的 PathID（比如从 UABEA 左侧列表里看到是 `12345678`），然后写：
```
m_Father: {fileID: 0, pathID: 12345678}
```

**爹认儿子**：找到父节点 Transform 的 Dump 文件（你需要先把它也导出成 txt）。  
- 找到它的 `m_Children` 数组。  
- 把 `size` 增加 1（比如从 15 改成 16）。  
- 在数组末尾添加新的一项：`{fileID: 0, pathID: 90002}`（你的新 Transform 的 ID）。  
- **保存这个父节点的 Dump**。

### 最后：导入并测试
- 在 UABEA 中，分别对修改过的四个对象（GameObject、Transform、SpriteRenderer、父节点 Transform）执行 `Import Dump`。  
- 保存 B 包，替换原文件。  
- 进入游戏，你的皇冠应该出现在正确位置，并且能被动画驱动（如果动画里有定义）。

## 五、常见问题速查

| 现象 | 根本原因 | 解决方法 |
|------|----------|----------|
| 游戏闪退 | 父节点的 `m_Children` 数组只改了 size，没有加新元素，或者直接界面改 size 导致文件损坏 | 必须用导出/导入 Dump 的方式改数组，且 size 和新增元素同时改 |
| 新部件看不见 | SpriteRenderer 的 `m_GameObject` 没指向正确的 GameObject ID | 检查三个组件的互指是否正确 |
| 新部件不会动（动画失效） | GameObject 的 `m_Name` 与动画路径要求的名字不一致 | 去查原版动画文件或同类型部件的命名，严格一致 |
| 图片显示位置错乱 | Transform 的 `m_LocalPosition` 没调好，或者 Sprite 的 Pivot 不合适 | 在 Dump 里修改位置数值，或调整 Sprite 的锚点 |
| SpriteRenderer 里的图片不显示 | `m_FileID` 填错了（指向了错误的依赖包） | 按第三节的方法检查 B 包的依赖列表，确认 A 包是第几个 |

## 六、你只需要记住的三句话

1. **GameObject 管名字和挂件，Transform 管爹和儿，SpriteRenderer 管画图。**  
2. **父子关系是双向的：儿子记 `m_Father`，父亲记 `m_Children`。**  
3. **永远用 `导出 Dump → 改文本 → 导入 Dump` 来扩容数组，绝对不要直接在界面改 size。**
