# 03. 富文本与图标标记语法

在 PVZH 的本地化文本（如 [cn.csv](../资源/cn.csv)）中，很多卡牌技能描述包含 `[+1a]`、`[frenzy]`、字面反斜杠换行等结构。它们可能展开为图标、共享文字、链接或格式，不能都当作普通待译词。本页标记形式按 2026-10-16 B4 输入核对，指纹见[案例证据摘要](文言中文包证据摘要.json)。

## 标记定义与共享文字

同版 APK 的 `assets/AssetBundles/fonts/inline_text_tag` 中，MonoBehaviour **`HeroesInlineTextTagMapping`** 的 `Mappings` 保存 `Tag → Text`。本批有 208 条记录、205 个唯一标签。例如 `frenzy` 的映射为：

```text
<sprite=26><style=ability><link="frenzy">|ability_frenzy|</link></style>
```

可据此整理静态依赖：说明中的 `[frenzy]` → 映射 → 图标／链接与 `|ability_frenzy|` → cn 中该键的中文值。翻译共享中文值，正文保留标记。说明键 `ability_desc_plants_*`、`ability_desc_zombies_*` 还可能嵌套标记；按命名推断的关联应与真实映射引用区分记录，遍历时用已访问集合防止循环。

**只新增 `temp,某文字`，不能据此认定 `[temp]` 已注册。** 本次证据中的标记定义在 cn 之外；只改 cn 时处理既有共享值。新增标记需另查定义及解析器，不能把未验证语法当原版功能。

## 一、 属性与增益数值图标标记

在技能描述中，任何有关攻防增减的文字均使用专用中括号标记：

| 标记语法 | 渲染效果说明 | CSV 真实文本示例 |
| :--- | :--- | :--- |
| **`[+Xa]`** | 渲染为 **+X 攻击力**（带有攻击图标） | `一株植物获得[+1a]/[+1h]。` |
| **`[+Xh]`** | 渲染为 **+X 生命值**（带有生命图标） | `使一个僵尸获得[+2h]。` |
| **`[-Xa]`** | 渲染为 **-X 攻击力**（带负向攻击图标） | `使一株植物获得[-2a]。` |
| **`[-Xh]`** | 渲染为 **-X 生命值**（带负向生命图标） | `使一个随从获得[-3h]。` |

## 二、 关键字图标标记 (Keyword Icons)

使用原表中已存在的标签形式，不能仅按英文技能名猜标签；方括号也不一定产生图标：

| 图标标记 | 对应关键字 | 渲染效果 | 示例／处理说明 |
| :--- | :--- | :--- | :--- |
| **`[frenzy]`** | 狂热 (Frenzy) | 图标及共享中文名 | `[frenzy]\n在消灭植物时获得[+2a]/[+2h]。` |
| **`[armored=1]`** | 装甲 (Armored) | 基础映射 `armored` 含 `{0}` 参数及图标 | 保留完整参数形式，不改成 `[armor1]` |
| **`[strikethrough]`** | 贯穿 (Strikethrough) | 贯穿图标 | `[strikethrough]\n登场：抽一张牌。` |
| **`[untrickable]`** | 无法成为法术目标 | 免疫法术图标 | `[untrickable]` |
| **`[truestrike]`** | 必中 | 图标及共享中文名 | 当前输入使用此标签，不擅换成 `[bullseye]` |
| **`[aquatic]`** | 两栖 | 当前映射为文字链接，无 sprite | 不擅换成 `[amphibious]` |
| **`[teamup]`** | 协作 (Team-Up) | 当前映射为文字链接，无 sprite | `[teamup]` |
| **`[overshoot=2]`** | Overshoot 2 | 基础映射 `overshoot` 含 `{0}` 参数及图标 | 保留完整参数形式 |
| **`[bounce]`** | 弹射 (Bounce) | 当前映射为文字链接，无 sprite | 翻译 `ability_bounce`，正文保留标记 |
| **`[linkgoat]`** | 山羊卡名链接 | 引用 `ability_linkgoat` | 与单卡名称及来源提示同步 |

表中的中文是原词／解释，不要求风格化改版一律采用这些译名。映射及标记形式以用户当前版本为准；序列化内容不直接证明解析器的执行顺序、大小写敏感性或重复项优先级。

## 三、 换行符与格式化语法

1. **区分两种换行**：
   CSV 中被双引号正确包裹的多行字段有效，一条逻辑记录可以跨多条物理行。字段内还可能存在字面反斜杠与字母 `n`，部分位置含多个反斜杠；应分别保留实际字符及数量，不能统一转换。
   - 使用 CSV 解析器与记录的原始物理行区间，不以逐行 `split(',')` 代替。
2. **Unity 富文本颜色 (Rich Text)**：
   原文可含颜色、样式、链接、缩进等富文本标签，例如：
   - `<color=#FF0000>高亮红字</color>`
   - `<b>加粗文本</b>`
3. **动态变量插值 (`{0}`, `{1}`)**：
   在系统提示或部分动态关卡文本中，`{0}`、`{1}` 可在运行时替换为实际数值或卡牌名称；具体来源与替换时机需另行核对。
   其他命名占位（如 `{cardSetCollectedCounter:Silver}`）、带格式参数、`%s`／`%d` 若存在，也应保护，不能只检查数字占位。

## 四、 修改与撰写建议

> [!TIP]
> 1. 在为新卡牌撰写中文技能描述时，**务必优先使用 `[+1a]`、`[+1h]` 代替纯文字的“+1攻击”**，这样渲染出来的卡牌面板在视觉上才符合 PVZH 官方的原汁原味规范。
> 2. 值包含逗号、物理换行或英文双引号时，使用 CSV 写入器处理引用与双引号转义。富文本标签另查开闭顺序，不手拼 CSV。

## 五、原包异常与保护范围

本批原包中，`linkgoat`、`linkzombats` 各重复且内容相同，`untrickable` 的两条定义是否带 sprite 不同。索引可去重展示，原序列化记录保留；不能在翻译时顺手改变覆盖顺序。

另有一处 `[Gravestone]` 大小写差异、两处 `[roundtext]` 不在所提取映射中及普通括号注释候选。记录为原有异常并保留，未知标记不删除、不补猜测定义。`[roundtext]` 的实际运行时注入来源尚未定位。

校验需覆盖完整标记、键引用、参数、富文本、数值、正负号、百分号、各类换行和方括号等分隔符数量。仅数字相同不能发现 `[+1a]` 被改为 `[-1a]`；集合相同也不保证标记顺序与语义正确。完整流程见[04. 复用引用与批量翻译工作流](04.复用引用与批量翻译工作流.md)。
