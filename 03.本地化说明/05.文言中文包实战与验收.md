# 05. 文言中文包实战与验收

2026-10-16 案例。目标是只改简体中文值，将 PVZH 的说明、故事和界面改为可读的浅近文言，随后补译卡名与英雄名。本页保存通用经验与筛选后的证据；不随库收录原 APK、完整 Bundle、全量语言表、翻译工程或图标文件。

## 输入与版本边界

来源为 PVZH 1.67.8、B4、构建标识 11056、ARM64 的底座 APK。读取同版 cn、`inline_text_tag`、`card_data`、`data_assets` 作为证据，仅写 cn 的 `LocalizedStrings`。

| 项目 | 本例值 |
|---|---|
| APK 内中文资源 | `assets/AssetBundles/loc/cn` |
| 本地输入文件名 | `cn_8`，只是工程命名 |
| TextAsset 名称 | `LocalizedStrings` |
| TextAsset path_id | `-2978648870419362077`，只适用于本批输入 |
| 原始 cn SHA-256 | `d40408353ec001f84fc56b56dff6417e883048090d78a3cee712c11cefdd9aab` |
| 原始 CSV SHA-256 | `383e168d7033b61024e66b59b70384273d208536c6485a0c1ccd8311abfeb92a` |
| 已用环境 | Python 3.14.6、UnityPy 1.25.0；不是其他版本任务的强制升级要求 |

完整输入和输出指纹、原报告指纹见[文言中文包证据摘要.json](文言中文包证据摘要.json)。换输入应重提取，不套用本页的 path_id、数量或映射覆盖判断。

这些是记录、键、单元或引用出现次数，不能互相当成卡牌数量。`_name` 初始角色索引含英雄、排位和系列名，后续卡名分区经过重分类；615 个卡名单元也含令牌、旧别名与测试占位，不等于 615 张可收集卡。

原始 CSV 的特殊结构均保留：首键有 BOM 与反引号加空格前缀，`BONUS_TEXT` 含第三个空字段，同时存在字面反斜杠换行和引号内物理换行。旧工程的同名 cn 还多两个测试键并有一条账号说明差异；库内历史语言表与 B4 也有换行等差异，因此没有用历史表覆盖新底座。

标记映射中的全部 `|key|` 在本批 cn 可找到。配置的 179 次 LocKey 未解析到当前 cn、标记大小写及重复定义等另列为原有异常；它们不是本轮新增缺失，也未被补造内容掩盖。

## 从试译到全量，再补名称

先提交 71 条审核后的试译，用户认可“既有古风又看得懂”的方向，再全面推进。工作按内容分给三个子 agent，交叉审阅后由主审裁决；每版保留稿件和修改依据。

| 阶段 | 结果 | 验收范围 |
|---|---|---|
| 全量首版 full-v1 | 覆盖 7,369 单元，实际改写 6,333 键；主审 40 处单元修订 | 离线覆盖、标记和回包校验通过；随后用户实机试用反馈整体不错，并指出卡名、英雄名及 UI 仍有保留 |
| 名称／UI 第二版 full-v2 | 相较首版新增改变 4,326 键，记录 3,683 条引用同步 | 离线校验通过，用户认可翻译效果；没有第二版逐界面字体／排版验收清单，不写成全量实机通过 |

第二版处理 615 卡名单元（591 改名）、22 位英雄（21 改名）和 1,125 个 UI 单元（808 改写）。剩余项有保留理由，例如测试标识、简明古词和精确术语。第二版新增改动与首版改动有重叠，不能将两版键数相加当累计唯一键数。

## 代表性修订与教训

| 场景 | 决定与依据 |
|---|---|
| 首页仍像原版 | 补译“植物任务→草木征途”“僵尸任务→群尸征途”“草坪战争→庭园争锋”“收藏→藏册”“组合包→牌囊”“好友→知交” |
| 名称应可辨 | 豌豆射手→豌豆射士、向日葵→向阳葵、绿影侠→青影游侠；坚果骑士等已有古意者保留 |
| 古意不能毁语义 | 将“降B调→B调下行”纠正为“降B之调”；降号不等于旋律下行。角龙不拆成“角之龙”，小鬼不加儿童年龄含义 |
| 角色误分 | 将混入卡名组的排位段名、系列名交还 UI，保留英文前缀和令牌卡名 |
| 普通词与人名 | 玫瑰英雄引用按键白名单，野玫瑰长名先匹配，普通花刺谚语不套改；测试关卡里的种类简称另查实际英雄 |
| 牌阵选择页与提示句不一致 | 主审检查并同步 169 处带引号的牌阵标题引用，另处理确切旧别译 |
| 旧别称遗漏 | 交审补出“巨人学家／巨尸学家”“火鸡骑士／火鸡骑手”等 24 键确切引用，按键短语修订，不全局猜同义名 |
| 操作按钮不清楚 | 接受 UI 交审修订，保留确认、免费、回收；退出帐号不含删除帐号之义 |

主审还对规则歧义回查同版配置：

- 原“自己和相邻线上的植物”对应同线所有植物与邻线植物的组合筛选，译“本线及邻线植物”，不能缩成只有自身。
- `Hot Date_shortDesc` 的原文缺“对”字，容易误读伤害方向；长文和 `DamageEffectDescriptor(3)` 的僵尸目标筛选支持“伤本线一只僵尸3点”。只澄清文字，没有改技能。
- 交审曾建议将 Madcap 职业“疯狂”改成 Frenzy“狂热”，主审依据卡牌职业与能力配置否决。

这些是静态配置消歧，不代表本轮执行了对应战斗用例。

## 已通过与仍待核实

两版均检查覆盖、源文匹配、标记／参数／数值／百分号／换行、原键和额外列、非目标记录原始片段。第二版还分别相对首版及原始 CSV 校验。新 Bundle 读回的 `LocalizedStrings` 与目标文字一致；比较全部序列化对象的原始字节，只该 TextAsset 改变。

首版引入 166 个新增汉字，第二版相较首版再引入 64 个；这是字符差异统计，不能当作字体已覆盖的证明。用户实机正面反馈也不替代所有长名称、共享提示和界面的字形／排版检查。

截图中的 `RANK: NA`、`Round 4` 不在 cn 的字面值中；cn 已有对应名次中文值，倒计时含 `[roundtext]`。本次保留标记，未定位两处英文的最终来源。没有为此修改游戏逻辑或伪造映射。

本轮仅把文档和证据摘要收入 Library。原翻译工程保持独立，历史首版、第二版与其通过／未测项不互相覆盖。后续复用可按[工作流](04.复用引用与批量翻译工作流.md)重新提取、翻译与校验，不需要依赖本机工程路径。
