# 02. 键名规范与后缀索引

在本地化文件 [cn.csv](../cn.csv) 中，所有条目均采用 `Key,Value` 的键值对模式存在。理解并掌握卡牌及系统 Key 的命名规范，是进行卡牌汉化、文本修改及添加新卡牌的基础。

---

## 一、 卡牌本地化 Key 的四大后缀规范

在 PVZH 中，每张卡牌通过其唯一的字符串或 GUID 关联 4 条核心文本条目：

| Key 后缀格式 | 示例条目 (提取自 [cn.csv](../cn.csv)) | 作用与显示位置 |
| :--- | :--- | :--- |
| **`[GUID]_name`** | `002f2d4b..._name,植物养料` | **卡牌名称**。显示在手牌标题栏、卡库收藏及出牌提示中。 |
| **`[GUID]_shortDesc`** | `002f2d4b..._shortDesc,一株植物获得[+1a]/[+1h]，然后额外攻击一次。` | **简短技能描述**。显示在战斗对局手牌界面的卡牌下方面板。 |
| **`[GUID]_longDesc`** | `002f2d4b..._longDesc,一株植物获得[+1a]/[+1h]，然后额外攻击一次。` | **详细技能描述**。显示在收藏卡册查看卡牌详情时的完整文字框中。 |
| **`[GUID]_flavorText`** | `002f2d4b..._flavorText,每天最重要的营养美餐。` | **背景故事/风味描述**。显示在收藏卡册详情面板底部的趣闻风味文字。 |

---

## 二、 典型文本示例解构 (以吸血僵尸为例)

提取自 [cn.csv](../cn.csv) 的真实数据如下：

```csv
00848e55-e990-459f-8927-beefa06f815e_flavorText,他要来吸干你的叶绿素啦！
00848e55-e990-459f-8927-beefa06f815e_longDesc,[frenzy]\n在消灭植物时获得[+2a]/[+2h]。
00848e55-e990-459f-8927-beefa06f815e_name,吸血僵尸
00848e55-e990-459f-8927-beefa06f815e_shortDesc,[frenzy]。在消灭植物时获得[+2a]/[+2h]。
```

- **卡牌 GUID**：`00848e55-e990-459f-8927-beefa06f815e`（对应卡牌数据中的 `prefabName` 或关联 GUID）。
- **`shortDesc` 与 `longDesc` 的差异**：有些卡牌的 `shortDesc` 会为了战场手牌简洁度使用更简短的关键字提示，而 `longDesc` 会给出更详尽的机制解释。

## 三、 游戏系统与 UI 通用 Key

除了卡牌专属的 GUID 文本外，`cn.csv` 还包含了游戏所有的系统 UI 与文字提示：

| Key 前缀/样式 | 说明 | 示例 |
| :--- | :--- | :--- |
| **`Subtype_...`** | 族群分类显示名称 | `Subtype_Pea,豌豆`、`Subtype_Nut,坚果` |
| **`Ability_...`** | 技能关键字浮窗提示标题 | `Ability_Frenzy,狂暴`、`Ability_Armor,护甲` |
| **`UI_...`** | 界面按钮与菜单提示文本 | `UI_DeckBuilder_Title,卡组构筑` |
| **`Hero_...`** | 英雄名称与介绍文本 | 英雄个人档案与经典台词 |

---

## 四、 自定义卡牌时的补全规则

> [!IMPORTANT]
> 当你在 Mod 中创建了一张全新的卡牌（分配了全新的 GUID 或 `prefabName`）时，**必须在 `cn.csv` 中补全对应的 4 个 Key**。
>
> 如果缺失对应的 Key，游戏界面将不会报错闪退，但卡牌名称和描述位置将直接显示原始 Key 字符串（如显示为 `900000001_name`）或显示为空白。
