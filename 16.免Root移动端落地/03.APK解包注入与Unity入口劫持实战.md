# 03. APK 解包注入与 Unity 入口劫持实战

有了上一篇准备好的“Gadget 三件套”后，现在我们需要将它们物理并入原版 APK，并在游戏的 Java 启动入口处插上一根“引线”——通过一行简单的 Java/Smali 指令，通知 Android 虚拟机在游戏开屏的第一毫秒加载我们的动态库。

本篇讲解如何使用 **`apktool`** 进行免资源崩坏解包、如何准确定位主 Activity，以及如何在 Smali 汇编代码中插入 `System.loadLibrary`。

---

## 一、 `apktool` 避坑参数：`-r`（不解包资源）的致命重要性

在处理 Unity 商业大型游戏时，初学者最常犯的错误是直接运行 `apktool d base.apk`。

这会导致 `apktool` 尝试将成千上万个 Unity 自定义资源和加密 XML 逆向还原。在重新打包（`apktool b`）时，**99% 的概率会因为 AAPT2 资源 ID 冲突、9-patch 格式错误而全盘报错崩溃**！

### 正确的解包命令：

```bash
# 必须带上 -r (--no-res) 参数！
apktool d -r -f PVZH_base.apk -o apk_workspace
```

- **`-r`（--no-res）**：告诉 apktool **原样保留 `resources.arsc`、`res/` 以及二进制 XML 资源**，只解包 `classes.dex` 为 Smali 代码！
- 我们的目的仅仅是修改 Java 代码和添加 SO 库，完全不需要碰原版的美术和 UI 资源。这能确保重新打包时的**百分之百成功率与秒级速度**。

---

## 二、 放置 Gadget 三件套到 Native 库目录

解包完成后，进入 `apk_workspace/lib/arm64-v8a/` 目录。

将我们在上一篇构建好的三个文件完整复制进去：

```text
apk_workspace/lib/arm64-v8a/
├── libil2cpp.so
├── libmain.so
├── libunity.so
├── libpvzhgadget.so            <--- [新增 1: Frida Gadget 二进制]
├── libpvzhgadget.config.json   <--- [新增 2: 配置文件]
└── libpvzhgadget.script.so     <--- [新增 3: 业务脚本伪装体]
```

> [!TIP]
> 如果官方 APK 是多 ABI 架构（同时包含 `armeabi-v7a`、`x86` 等），为了防止系统按旧架构加载，建议直接删掉其他目录，**仅保留 `arm64-v8a`**，强制系统以 64 位原生模式运行。

## 三、 寻找主启动入口与 Smali 劫持实操

### 1. 查找主 Activity 入口
打开 `apk_workspace/AndroidManifest.xml`，搜索带有 `android.intent.action.MAIN` 的 Activity：

```xml
<activity android:name="com.ea.gp.pvzheroes.UnityPlayerActivity" ...>
    <intent-filter>
        <action android:name="android.intent.action.MAIN" />
        <category android:name="android.intent.category.LAUNCHER" />
    </intent-filter>
</activity>
```

我们确认了入口类名为：`com.ea.gp.pvzheroes.UnityPlayerActivity`。

### 2. 定位并编辑 Smali 源码
在 `apk_workspace/smali/` 或 `smali_classes*/` 目录下，找到对应的文件路径：
`smali/com/ea/gp/pvzheroes/UnityPlayerActivity.smali`。

用文本编辑器打开该文件。注入代码有两种经典位置：

#### 方案 A：注入到静态代码块 `<clinit>()V`（推荐：最早时机）
在类刚被加载进内存时就立即加载 Gadget，早于所有界面初始化。

搜索 `.method static constructor <clinit>()V`。如果存在，在第一行插入；如果不存在，可以在类末尾新写一个：

```smali
# 静态初始化代码块
.method static constructor <clinit>()V
    .registers 1

    # 加载 libpvzhgadget.so (不需要写开头的 lib 和结尾的 .so)
    const-string v0, "pvzhgadget"
    invoke-static {v0}, Ljava/lang/System;->loadLibrary(Ljava/lang/String;)V

    return-void
.end method
```

#### 方案 B：注入到 `onCreate(Landroid/os/Bundle;)V` 方法
如果担心静态代码块过早，也可以注入到 `onCreate` 的最开头：

```smali
.method protected onCreate(Landroid/os/Bundle;)V
    .registers 3
    .param p1, "savedInstanceState"    # Landroid/os/Bundle;

    # === [Mod 注入代码开始] ===
    const-string v0, "pvzhgadget"
    invoke-static {v0}, Ljava/lang/System;->loadLibrary(Ljava/lang/String;)V
    # === [Mod 注入代码结束] ===

    invoke-super {p0, p1}, Landroid/app/Activity;->onCreate(Landroid/os/Bundle;)V
    ...
```

## 四、 重新打包为未签名 APK

完成 Smali 修改和 SO 放置后，执行打包命令：

```bash
apktool b apk_workspace -o PVZH_Mod_unsigned.apk
```

因为我们在第一步使用了 `-r` 参数，打包过程将极其迅速，几秒钟内便会输出全新的 `PVZH_Mod_unsigned.apk`。

---

> [!WARNING]
> ⚠️ **此时切勿直接安装！**
> 新生成的 `PVZH_Mod_unsigned.apk` 是完全没有数字签名的，且压缩包内的资源尚未经过 4 字节边界内存对齐。直接安装会导致 Android 系统报 `INSTALL_PARSE_FAILED_NO_CERTIFICATES` 错误。
