# 02. Gadget 与自研脚本编译构建流

在编写初期的轻量脚本时，所有逻辑写在一个 `.js` 文件里尚能维护；但随着 Mod 功能的丰富（例如引入了卡组分享协议解析器、原生悬浮窗 UI、IL2CPP 方法映射表、版本兼容层），代码必然会拆分为多个模块：

```text
src/
├── main.js                 # Mod 入口装配
├── native_provider.js      # IL2CPP 原生函数 Hook
├── ui_controller.js        # Android 浮窗组件
├── share_codec.js          # 卡组 Base64URL 编解码
└── version_catalog.js      # 各版本 RVA 偏移表
```

本篇讲解如何使用 **`frida-compile`** 工具链将多模块工程编译为单体分发载荷，并揭秘一个在 Android 10+ 高版本系统上保证脚本百分之百被释放执行的**“伪装 SO”独门避坑绝技**。

---

## 一、 使用 `frida-compile` 打包单体脚本

Node.js 生态中的 `frida-compile` 是官方专为 Frida 打造的代码打包器（类似 Webpack / Rollup），它能将 `import / export` 模块化代码及其 npm 依赖整体压缩打包为一个纯粹的独立 JavaScript 文件。

### 1. 初始化独立的构建目录
在工程根目录下准备 `package.json`：

```bash
# 初始化环境
npm init -y

# 安装开发期编译依赖 (固定版本防兼容性抖动)
npm install --save-dev frida-compile
```

### 2. 执行编译与代码混淆/压缩
在 `package.json` 中配置编译命令：

```json
{
  "scripts": {
    "build": "frida-compile src/main.js -o dist/bundle.js -c"
  }
}
```

- `-o dist/bundle.js`：指定打包输出单体文件；
- `-c`：启用压缩优化，剔除调试注释，减小载荷体积。

执行 `npm run build` 后，所有的模块与依赖都将被无缝缝合进 `dist/bundle.js`。

## 二、 核心避坑：Android 10+ 的原生库释放限制（W^X 机制）

这是 90% 的初学者在制作免 Root APK 时都会踩中的致命陷阱：

> ❌ **典型错误做法**：
> 将配置文件写为 `"path": "bundle.js"`，并把 `bundle.js` 塞进 APK 的 `assets/` 或根目录。结果在 Android 10+（API 29+）设备上测试时，游戏直接闪退或报错 `Script file not found`！

### 根本原因：
Android 系统从 Android 10 开始全面收紧了应用私有目录的执行与解压策略：
1. **`extractNativeLibs` 机制**：如果 APK 没有在 `lib/arm64-v8a/` 目录下放置符合规范命名的文件，系统在安装时**根本不会把普通文件解压到 App 私有的物理执行路径下**；
2. **只读保护与 W^X**：应用无权在没有释放权限的目录中执行动态代码。

### 🌟 业界金牌解决方案：“伪装 SO”命名法
Android 系统的包管理器在安装应用时，遵循一条铁律：
> **只要存放在 `lib/<abi>/` 目录下，且文件名以 `lib` 开头、以 `.so` 结尾的文件，系统在安装时必然会将其原样释放到 App 专属的原生库目录中！**

因此，我们**不要使用 `.js` 后缀**，而是将编译出来的脚本直接命名为形如 **`libpvzhgadget.script.so`** 的纯文本文件！

```text
APK 压缩包内的布局:
lib/arm64-v8a/
├── libil2cpp.so                     (原版游戏库)
├── libunity.so                      (原版引擎库)
├── libpvzhgadget.so                 (Frida Gadget 原生二进制)
├── libpvzhgadget.config.json        (Gadget 配置文件)
└── libpvzhgadget.script.so          (我们编译好的 JS 脚本伪装体!)
```

系统会误以为它是一个原生动态库而安全解压，而 Frida Gadget 在运行时能直接以本地文件绝对路径无阻碍读取它！

## 三、 编写严密的 Gadget 配置文件

在与 `libpvzhgadget.so` 相同的输出目录下，创建完全同名的 JSON 配置文件：**`libpvzhgadget.config.json`**：

```json
{
  "interaction": {
    "type": "script",
    "path": "libpvzhgadget.script.so",
    "on_change": "respecialize"
  }
}
```

### 关键配置项解读：
- **`"type": "script"`**：声明为脱机独立运行模式，不开启任何本地网络端口；
- **`"path": "libpvzhgadget.script.so"`**：指向刚才生成的伪装脚本；由于处于同级目录，可以直接写相对文件名；
- **`"on_change": "respecialize"`**：当脚本更新时（例如开发期热更新），自动重新特化环境，防止老旧状态污染。

## 四、 自动化构建流水线脚本（Node.js / PowerShell）

为了避免每次修改都需要手动复制重命名，推荐编写一个一键自动化脚本：

```javascript
// scripts/bundle_gadget.js
const fs = require('fs');
const path = require('path');
const { execSync } = require('child_process');

const OUT_DIR = path.resolve(__dirname, '../build_gadget');
if (!fs.existsSync(OUT_DIR)) fs.mkdirSync(OUT_DIR, { recursive: true });

console.log("[1/3] 编译 JS 业务代码...");
execSync("npx frida-compile src/main.js -o " + path.join(OUT_DIR, "libpvzhgadget.script.so") + " -c", { stdio: 'inherit' });

console.log("[2/3] 生成同名配置文件...");
const configContent = {
    interaction: {
        type: "script",
        path: "libpvzhgadget.script.so",
        on_change: "respecialize"
    }
};
fs.writeFileSync(path.join(OUT_DIR, "libpvzhgadget.config.json"), JSON.stringify(configContent, null, 2));

console.log("[3/3] 拷贝 Frida Gadget 官方二进制...");
const OFFICIAL_GADGET_PATH = path.resolve(__dirname, '../tools/frida-gadget-17.15.3-android-arm64.so');
fs.copyFileSync(OFFICIAL_GADGET_PATH, path.join(OUT_DIR, "libpvzhgadget.so"));

console.log("✅ Gadget 三件套已在 build_gadget/ 就绪，随时可并入 APK！");
```

运行后，`build_gadget/` 目录下将生成完美的“**Gadget 三件套**”：
1. `libpvzhgadget.so`
2. `libpvzhgadget.config.json`
3. `libpvzhgadget.script.so`

准备好三件套后，下一篇我们将使用 `apktool` 打开原版 APK，并为游戏主 Activity 植入启动代码，实现无感自启动！
